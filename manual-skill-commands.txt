Codex 수동 스킬 명령어
=======================

사용법
------
Codex 입력창에서 "$스킬명"을 입력한다.
예: $grill-with-docs


1. 반드시 수동으로 호출해야 하는 스킬
-------------------------------------

$setup-matt-pocock-skills
  프로젝트마다 최초 1회 실행한다.
  이슈 관리 방식, CONTEXT.md, ADR 저장 위치를 설정한다.

$grill-me
  계획이나 아이디어를 질문 하나씩 검증한다.
  문서 기록이 필요 없는 가벼운 논의에 사용한다.

$grill-with-docs
  재작성 요구사항을 질문 하나씩 검증하면서
  CONTEXT.md 용어집과 중요한 ADR을 함께 관리한다.
  이 프로젝트에서는 일반 grill-me보다 우선 추천한다.

$wayfinder
  한 세션에 담기 어려운 대규모 작업을 결정 지도로 만든다.
  전체 재작성, 데이터 모델, 파일 저장 정책처럼
  여러 선행 결정이 얽힌 작업에 사용한다.


2. 자동 호출되지만 필요할 때 직접 지정하면 좋은 스킬
------------------------------------------------------

$ponytail lite
  요청은 그대로 구현하되 더 단순한 대안을 알려준다.

$ponytail full
  기본 권장 모드. 최소 구현과 기존 기능 재사용을 강제한다.

$ponytail ultra
  극단적인 YAGNI 모드. 이 대형 프로젝트에서는 신중하게 사용한다.

$ponytail-review
  현재 변경 사항에서 과도한 추상화와 삭제 가능한 코드를 찾는다.

$prototype
  UI 또는 상태 모델의 폐기용 프로토타입을 만든다.

$web-design-guidelines
  UI 접근성, UX, 인터페이스 규칙을 검토한다.

$security-best-practices
  TypeScript 코드에 대해 명시적인 보안 검토를 요청한다.
  Rust는 이 스킬의 공식 지원 언어가 아니다.

$requesting-code-review
  큰 기능을 완료했거나 병합하기 전에 코드 검토를 요청한다.

$systematic-debugging
  재현하기 어려운 버그나 성능 문제를 체계적으로 진단한다.

$verification-before-completion
  완료 선언 전에 테스트와 검증 결과를 다시 확인한다.


3. 보통 직접 호출할 필요가 없는 스킬
------------------------------------

다음 스킬은 작업 내용에 맞으면 자동으로 선택된다.

- using-superpowers
- brainstorming
- writing-plans
- executing-plans
- test-driven-development
- domain-modeling
- codebase-design
- shadcn
- playwright-interactive
- receiving-code-review
- finishing-a-development-branch


프로젝트 시작 권장 순서
----------------------

1. $setup-matt-pocock-skills
2. $grill-with-docs
3. $wayfinder
4. 기능 단위로 Superpowers 계획 및 구현
5. $ponytail-review
6. $web-design-guidelines
7. $requesting-code-review
