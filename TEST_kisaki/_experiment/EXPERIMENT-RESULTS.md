# 캐릭터 자동 분류 실험 — 성과와 한계

기록일: 2026-09-07

## 현재 판단

소수의 참조 이미지로 목표 캐릭터의 후보를 찾고, 사용자가 검토하며 참조·반례를 보완하는 흐름은 소규모 실험에서 유용성을 보였다. 사용자는 추가 분석 연결 수정 후 직접 확인한 성과를 “꽤 좋다”고 평가했다. 현재 단계의 성과는 **사용자 검토를 전제로 한 분류 보조**이며, 무검토 자동 확정이나 전체 라이브러리에 대한 정확도가 입증된 상태는 아니다.

흑백·선화와 목표 캐릭터가 포함된 다인 이미지에서 탐지 한계가 관찰됐다. 특히 다인 이미지의 목표 캐릭터 누락은 미탐으로 기록해야 한다. 다인 이미지를 의도적으로 제외하는 기능을 구현한 것은 아니다.

## 범위와 방식

- Lakomics는 동결 상태로 유지하고, `C:\chatgpt\TEST_kisaki\_experiment`에서 독립적으로 실험했다. 최초 대화의 `TEST\_kisaki` 표기와 달리 실제 실험 경로는 `TEST_kisaki`다.
- 사용자 제공 정답은 입력 폴더의 `man`(목표 캐릭터)과 최상위 이미지(비교 자료) 구분이다. 비교 자료에는 실사, 만화, 글, 다인 이미지가 섞일 수 있다.
- CCIP `ccip-caformer_b36-24`의 공식 feature/metric ONNX와 이미지 전체의 특징 거리를 사용한다. 추론은 로컬 CPU에서 수행하며 파일명·폴더명은 추론에 사용하지 않는다.
- 폴더 정답은 참조 선택과 평가에 사용한다. 거리는 정답 확률이 아니다.
- 검토 수정은 신경망 재학습이 아니라 명시적 참조·반례와 비교하는 규칙의 갱신이다.
- 분류 폴더는 실험 안의 가상 상태다. 원본 이동 및 Lakomics 코드·DB·클라우드 변경은 하지 않았다.

## 단계별 정량 결과

각 초기 실험은 참조 후보 5장을 항상 제외한 고정 평가 범위에서 비교했다. 서로 다른 데이터셋의 숫자를 합쳐 하나의 정확도로 계산하지 않는다.

| 실험 | 평가 대상: 목표 / 비교 | 참조 | 발견 | 오탐 | 미탐 |
|---|---:|---:|---:|---:|---:|
| 마커스 초기 | 13 / 65 | 1 | 8/13 | 0 | 5 |
| 마커스 초기 | 13 / 65 | 3 | 10/13 | 1 | 3 |
| 마커스 초기 | 13 / 65 | 5 | 11/13 | 4 | 2 |
| 에이메스 첫 자료 | 14 / 53 | 1 | 13/14 | 6 | 1 |
| 에이메스 첫 자료 | 14 / 53 | 3 | 14/14 | 6 | 0 |
| 에이메스 첫 자료 | 14 / 53 | 5 | 14/14 | 6 | 0 |
| 에이메스 새 자료 | 12 / 127 | 1 | 11/12 | 0 | 1 |
| 에이메스 새 자료 | 12 / 127 | 3 | 11/12 | 0 | 1 |
| 에이메스 새 자료 | 12 / 127 | 5 | 12/12 | 0 | 0 |

마커스 입력은 목표 18장 + 비교 65장, 에이메스 첫 자료는 19장 + 53장, 새 자료는 17장 + 127장이었다. 에이메스 첫 자료에는 사용자가 머리색이 비슷한 다른 캐릭터를 일부 넣었다. 그 집단의 별도 정답 라벨이 없어 해당 집단만의 오탐률은 계산하지 않았다.

마커스 실험에서는 참조를 늘리며 발견 수와 오탐이 함께 늘었다. 현재의 여러 참조 중 최소 거리 방식에서는 참조 추가가 반드시 정밀도 향상을 의미하지 않는다. 에이메스 새 자료의 결과가 더 좋은 것도 데이터 구성과 참조가 달라졌으므로 알고리즘 개선의 단독 효과로 해석할 수 없다.

에이메스 새 자료에는 이전 자료와 내용 해시가 같은 파일 1개가 있었다. 이 실험은 새 자료에서 참조 5장을 다시 골라 시작했으며, 이전 반례를 이어 적용한 독립 일반화 검증이 아니다.

## 검토 피드백의 효과

검토 UI에 임시 분류, 확정, 검토함, 보류, 정답 캐릭터로 수정, 명시적 참조 등록, 반례 기록, 되돌리기를 구현했다. 다른 캐릭터로 수정하면 이전 후보 캐릭터의 반례가 되고, 수정한 목적지에서 확정된다. 확정만으로 자동 참조 등록되지는 않는다.

반례 적용 시 참조보다 반례에 더 가까운 미확인 후보는 검토함으로 돌아간다. 이미 확정하거나 보류한 항목은 보호한다.

| 확인 경로 | 비교 조건 | 목표 발견 | 오탐 | 미탐 |
|---|---|---:|---:|---:|
| 분리된 검증 세션 | 반례 1장, 같은 남은 66장 | 14 → 14 | 5 → 2 | 0 → 0 |
| 사용자 제공 화면 | 반례 4장, 같은 남은 57장 | 8 → 8 | 2 → 0 | 0 → 0 |

직접 검토한 이미지와 참조·반례의 감지된 유사 원본을 제외하고, 동일한 남은 이미지에 반례를 적용하기 전후를 비교했다. 직접 고친 이미지를 정답으로 바꾼 것 자체를 개선 성과로 세지 않는다.

사용자 화면의 수치는 대화에 첨부된 스크린샷을 근거로 기록했다. 이후 새 데이터셋을 시작할 때 접근한 브라우저에서는 해당 반례 4장 상태를 확인하지 못했으므로, 이 기록이 현재 상태에 복원·연결됐다고 주장하지 않는다. 위 결과는 작은 표본에서의 탐색 결과다.

근거: [검토 방식과 검증](REVIEW-README.md), 대화의 사용자 첨부 화면.

## 새 이미지 추가 연결

이전에는 데이터셋 교체 시 새 검토 상태로 시작했다. 현재는 **추가 이미지 분석**으로 기존 참조·반례·확정·보류·캐릭터 폴더·기준선·되돌리기 기록을 유지하면서 새 이미지를 연결할 수 있다.

- 내용 SHA256으로 기존 이미지와 새 이미지를 구분한다. 동일 내용의 이름 변경·복사는 중복 추가하지 않는다.
- 새 이미지에만 특징 추론 및 초기 분류를 수행한다. 기존 특징을 재사용하고 전체 거리 행렬은 다시 계산한다.
- 새 `man` 이미지는 자동으로 참조가 되지 않는다.
- 최근 추가분과 도착 당시 검토 전 평가를 별도로 표시한다. 이후 검토로 도착 시점 평가가 바뀌지 않는다.
- 브라우저 저장과 추가 시작·종료 시 파일 체크포인트로 기록을 연결한다. 원본 삭제를 실험 기록 삭제로 동기화하지 않는다.

확인된 기능 검증:

- 검토·연결 테스트 13개 통과 기록.
- 분리된 복사본에서 실제 모델로 새 이미지 1장 추론·추가 성공, 동일 내용 재추가 0장, 기존 원본이 없어도 참조 특징 유지 확인.
- 분리 브라우저에서 새 비교 이미지 추가 → 최근 추가분 표시 → 새로고침 후 기록 복원 확인.
- 연결 구현 당시 실제 화면은 새 파일 0장으로 기존 144장과 참조 5장 등의 상태 유지 확인.
- 연결 이후 사용자가 성과가 꽤 좋다고 보고했다. 해당 추가분의 장수와 정량 성능은 이번 문서 작성 시 별도로 측정하지 않았다.

근거: [추가 분석 사용법과 검증](APPEND-README.md), [실제 모델 연결 검증 결과](incremental-verification.json). 위 테스트는 기존 실행 기록이며 문서 작성만을 위해 재실행하지 않았다.

## 관찰된 한계

| 항목 | 확인된 내용 | 아직 확인하지 않은 내용 |
|---|---|---|
| 흑백·선화 | 사용자가 오탐 및 탐지 어려움을 보고 | 해당 유형별 정밀도·재현율과 원인 |
| 비슷한 머리색 | 유사 머리색 비교 자료를 넣은 에이메스 실험에서 오탐 발생 | 머리색이 오탐의 직접 원인인지 여부 |
| 다인 이미지 | 사용자가 목표 캐릭터 포함 이미지의 탐지 실패를 보고 | 다인 이미지 전체의 미탐률, 캐릭터 크기·가림 영향 |
| 데이터 일반화 | 두 캐릭터와 여러 소규모 자료에서 검색·검토 가능성 확인 | 여러 시리즈·캐릭터 및 대규모 라이브러리 성능 |
| 피드백 누적 | 참조·반례 유지 및 추가 연결 기능 검증 | 누적 피드백이 독립된 새 자료에서 얼마나 개선하는지 |

현재는 캐릭터별 영역 검출 없이 이미지 전체를 비교한다. 다인 이미지에서 다른 인물의 특징과 구도가 섞여 목표와의 거리가 멀어질 가능성은 있으나, 실제 실패 이미지의 점수·영역별 비교로 원인을 검증한 것은 아니다. 또한 다인 이미지를 실제로 포함하는 정답과 폴더 라벨이 일치하는지 점검해야 포함 여부 평가가 정확해진다.

## 후속 실험 후보 — 미구현

1. 단독 컬러 / 흑백·선화 / 목표 포함 다인 이미지를 구분해 성능을 따로 기록한다.
2. 기존 참조·반례를 고정한 채 새 자료의 도착 시점 평가로 피드백의 일반화 효과를 확인한다.
3. 캐릭터별 영역을 검출해 각각 비교하고, 어느 영역에서든 일치하면 이미지 후보로 올리는 방식을 별도 실험한다. 여러 캐릭터가 맞는 이미지의 복수 분류 정책도 함께 정해야 한다.

위 항목은 검토할 방향을 기록한 것이며 구현·모델 추가·Lakomics 통합을 수행하거나 결정한 것은 아니다.
