# 기존 검토 기록을 유지하는 추가 분석

## 사용

1. 기존 파일을 그대로 두고, 에이메스 이미지는 `C:\chatgpt\TEST_kisaki\man`에, 다른 이미지는 `C:\chatgpt\TEST_kisaki` 최상위에 추가합니다.
2. http://127.0.0.1:1439/review.html 에서 **추가 이미지 분석**을 누릅니다.
3. **최근 추가분**에서 새 이미지의 임시 분류를 검토합니다. 위쪽의 **검토 전 고정 결과**는 추가 직전 참조·반례를 적용한 결과이며 이후 수정해도 바뀌지 않습니다.

기존 확정, 보류, 참조, 반례, 시리즈/캐릭터 폴더와 거리 기준선을 유지합니다. 새 이미지에만 초기 후보를 부여하며, 새 `man` 이미지가 자동으로 참조로 등록되지는 않습니다. 참조 등록은 이전과 같이 확정 화면에서 별도로 수행합니다.

새 파일이 없으면 재추론과 초기화를 하지 않습니다. 이름이 달라졌거나 다른 이름으로 복사한 동일 내용 파일도 새 데이터로 중복 등록하지 않습니다. 내용을 바꾼 파일은 별도의 새 이미지로 취급하며 기존 기록은 남깁니다. 이미 폴더에서 삭제된 기존 이미지도 분석 캐시와 썸네일을 유지하므로 참조를 잃지 않습니다. 이는 삭제 동기화 기능이 아닙니다.

## 저장 / 복구

- 브라우저 localStorage: 기존 데이터셋별 기록과 별도로 마지막 검토 기록 및 파일 해시 연결 정보를 저장합니다.
- 분석 시작 전: `review-checkpoint.json`과 `checkpoints/`에 현재 브라우저가 보내는 검토 기록을 저장합니다.
- 분석 종료 후: 새 파일 해시에 연결한 기록을 브라우저 및 파일 체크포인트에 저장합니다.
- 창을 닫거나 새로고침해도 진행 중 작업은 서버가 계속 처리하며, 다시 열면 체크포인트에서 연결합니다. 서버까지 종료된 경우 완료된 자료와 마지막 체크포인트로 복구합니다.
- 분석 중에는 해당 화면의 편집을 잠급니다. 서로 다른 브라우저의 모든 편집을 실시간으로 동기화하는 기능은 아닙니다. 다른 창에서 자료가 갱신되면 오래된 요청은 거부합니다.
- 모델/전처리가 달라지거나 기존 해시를 찾을 수 없는 잘못된 교체 결과는 조용히 초기화하지 않고 연결 오류를 표시합니다.

데이터 연결은 파일 내용 SHA256을 기준으로 하며 숫자 ID와 이름은 식별 근거로 사용하지 않습니다. 기존 되돌리기 기록도 새 자료에 연결해, 되돌리기로 새 이미지가 사라지지 않게 합니다. 오래된 직접 수정은 최신 순서로 되돌려야 합니다.

기존의 `run.ps1 -Reanalyze`도 이제 전체 초기화 대신 추가 분석을 수행합니다. 보통은 화면 버튼을 사용하면 됩니다. `analyze.py`는 최초 자료 생성용이며 추가 작업에 직접 실행하지 마세요.

## 평가 / 한계

새 이미지의 도착 시점 평가에서는 기존 참조·반례의 감지된 유사 원본을 제외합니다. 새 자료를 보고 참조/반례를 수정한 결과와 구분하기 위해 도착 시점 결과를 고정 보관합니다. 현재 남은 미검토 전체에 대한 반례 전후 평가는 기존 영역에서 별도로 갱신됩니다.

추론은 새로운 내용의 파일에만 수행하고, 기존 특징은 캐시에서 읽습니다. 비교 행렬 계산은 전체 특징을 사용합니다. 누적 자료가 매우 커졌을 때의 성능 최적화는 아직 하지 않았습니다. 다인 이미지 판별이나 새로운 태거는 추가하지 않았습니다.

원본은 읽기 전용이고 라쿠믹스 코드/DB/클라우드는 변경하지 않습니다. 추가 결과는 임시 파일에 쓴 후 교체하며 실패 시 기존 데이터 파일은 유지합니다. 동시 추가 분석은 잠금으로 막습니다. 서버가 강제 종료되어 `.append.lock`이 남으면 실행 여부 확인 후 복구가 필요하며, 임의로 다른 실행 중 작업을 해제하지 않습니다.

## 검증 (2026-09-07)

- `node --test review-engine.test.mjs review-migrate.test.mjs`: 13개 통과. 수정·반례·참조·보류 유지, 파일명/순서 변경, 새 이미지 자동 참조 방지, 추가 후 되돌리기, 모델 변경/누락 시 실패, 도착 시점 평가 고정.
- `check_incremental.py`: 분리된 폴더에서 실제 CCIP로 새 이미지 한 장 추론 성공. 기존 원본이 없어도 참조 특징 유지. 동일 내용/다른 파일명 재추가 0장. 외부 Origin 거부, 오래된 데이터 체크포인트 거부, 시작 전 체크포인트 저장 확인. exit 0. 결과는 `incremental-verification.json`.
- 브라우저 분리 실험: 새 비교 이미지 1장 추가 → 최근 추가분 1장 / 도착 시점 평가 표시 → 새로고침 후 기록 복원 확인.
- 실제 사용 화면: 추가 파일 없음(0장) 확인, 기존 144장 / 참조 5장 / 확정 5장 / 검토 대기 12장 유지, 파일 체크포인트 저장 확인.

검증용 원본 복사본과 모델 링크는 `checks/`에 있으며 실제 데이터셋에 섞지 않았습니다. 검토 서버는 루프백에서만 실행되고 추가 분석/체크포인트 API는 동일 Origin 및 현재 데이터에 맞는 요청만 받습니다.
