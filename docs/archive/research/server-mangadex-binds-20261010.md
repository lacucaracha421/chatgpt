The [Kakao design](server-kakao-binds-20261009.md), especially §§3–5 and decisions/implementation notes in §§8–10, supplies the execution contract. Current source takes precedence over its earlier proposals.

## 1. Current PC behavior

### Fetch and normalization

- `apply_mangadex` delegates to `apply_mangadex_checked`: check write availability, fetch detail plus **all** cover pages, download the representative original image, then apply the prepared result. Network work precedes the write transaction. Sources: `_tools/app/src-tauri/src/library/mangadex_flow.rs:51`, `:61`, `:84`.
- Detail is `/manga/{id}` with `includes[]=cover_art/author/artist`; covers are `/cover?manga[]={id}&limit=100&order[volume]=asc`, with offsets. Preserve returned order, not a new local sort. At most 50 pages and a 60-second cover-crawl guard; reject oversized pages, empty pages before advertised total, incomplete pagination and aggregate cover JSON over 4 MiB. Each PC request has a 30-second timeout; these guards do not constitute one strict end-to-end deadline. Sources: `_tools/app/src-tauri/src/library/mangadex.rs:16`, `:276`, `:296`, `:360`, `:371`.
- Parse `result=ok`, matching detail ID and cover-to-manga relationships; unrelated covers are omitted, malformed matching cover IDs/file names fail. File names allow ASCII letters/digits/`_.-`, length ≤160, no `..`, extension `jpg/jpeg/png/webp`. Sources: `_tools/app/src-tauri/src/library/mangadex.rs:120`, `:179`; identity equality: `mangadex_flow.rs:91`.
- Titles use locale priority `ko/en/ja-ro/ja`, main title before alternates; Japanese original title uses `ja`, then `ja-ro`. People are unique author/artist names in relationship order joined by ` · `. Tags join with `, `; overview/tag localization uses the same priority then the first nonblank key in sorted map order. The stored snapshot is `{detail,covers}`; proposed title, alternate titles and status remain provider data rather than overwriting the user's work name. Sources: `_tools/app/src-tauri/src/library/mangadex.rs:279`, `:472`, `:499`, `:512`, `:537`, `:551`, `:559`.
- Representative = **first** `locale=ja` cover with volume string exactly `"1"`, otherwise first Japanese cover. `"1.0"` is not that first preference. No Japanese cover means no image; no Korean/primary-cover fallback. Download original `https://uploads.mangadex.org/covers/{mangaId}/{fileName}`, not `.256.jpg`. PC download cap is 32 MiB, but authority artwork enqueue caps at 16 MiB. Sources: `_tools/app/src-tauri/src/library/mangadex_flow.rs:312`; `mangadex.rs:151`, `:356`; `collection_authority.rs:980`.

Name, memo/description, personal score, Showcase/order, ownership/range/subscription, Asset cover, unrelated providers and unrelated fields are not replaced by this apply. Blank text is refillable; an intentional blank is not a durable manual override under today's MangaDex merge. Without a usable old snapshot, nonblank existing values remain manual (`mangadex_flow.rs:345`, `:356`).

**Cover discrepancy:** existing per-volume covers and `cover_asset_id` survive, but the representative WorkArtwork selection does not: the PC explicitly selects the new Japanese cover (`work_artwork.rs:319`, `:384`, `:395`). Thus “preserve manual selections exactly as PC does” cannot literally hold for the work selection. Proposed server default follows the user's preservation requirement: retain every existing work selection and Asset cover; select the downloaded cover only into an empty work slot when no Asset cover exists. Still attach/store the provider candidate, even when it is not selected. No provenance heuristic or new override column is needed. This is a deliberate narrow divergence, not an observed existing guarantee.

**Baseline discrepancy:** reuse Kakao's accepted quiet-bind decision: initial bind/rebind emits no release events, even for a repeat bind to the same UUID. This differs from the same-identity PC reconciliation above; it does not change later refresh event policy.

### Failure and the tablet fence

- Fetch/status/timeout/429, invalid identity/envelope, cover download/decode/size/storage failure, missing/non-manga work, duplicate provider identity (or duplicate name for new work), write-state/commit precondition and DB errors abort apply. A representative exists but missing bytes is an identity error; only absence of a representative permits metadata-only apply. Prepared local artwork is committed after DB commit; rollback removes the prepared file. Sources: `mangadex_flow.rs:91`, `:113`, `:121`, `:145`, `:245`, `:587`; `mangadex.rs:463`.
- Tablet request consumer calls the Collections fence before the provider applier. An authority-adopted PC classifies it as permanent failure; MangaDex currently shares this path. Source: `_tools/app/src-tauri/src/library/collection_binding_sync.rs:284`, `:695`, `:730`; activation record: `docs/adr/README.md:55`. Installed state and a live failure were not inspected.
- Direct PC authority apply means queued commands plus local projection, not confirmed server acceptance. `refresh_mangadex` is separate: fetch metadata/covers and reconcile, but download/select no representative (`mangadex_flow.rs:254`, `:263`). This proposal covers selected existing-work bind/rebind, not that refresh or new-work creation.

## 2. Server execution contract

Uncited requirements below are proposed. Existing search normalization and transport are reusable foundations, not a complete detail/cover applier: `server/lakomics-api/collection_bindings.py:387`, `:428`, `:1192`.

### Reuse ownership and lifecycle

- Keep version-1 `POST /v1/collections/bindings/requests`, `choice.mangaId`, existing status/search/list/log/result routes and states `pending/applied/failed/superseded`. Client title/thumbnail hints never authorize a fetch URL or supply metadata. No new Android route is needed.
- Reuse Kakao's execution columns (`executor`, library/epoch, full binding observation including tombstone revision/config/digest/cursor, retry count/time), enqueue transaction, payload digest, replay-before-readiness and per-request executor pinning. Newly accepted MangaDex requests are server-owned only while its switch is ON. Never seize old PC rows or revive failed rows automatically. Sources: `kakao_bind_worker.py:28`, `:67`, `:75`; `collection_bindings.py:1108`.
- Generalize the small shared bind-intent primitives for these two providers: schema, enqueue/capture, lifecycle/serial dispatch, preflight, result/retry storage, publisher fence and receipt IDs. Keep provider parsing/planning separate. One serial bind lane can dispatch both providers with provider-specific readiness; neither switch may start/stop the other's work. No second queue/database, lease service or workflow framework.
- Capture current bound-state/revision/UUID/config/digest at enqueue; honor explicit `expected.externalId`, including null. Omitted expectation means the captured binding, not permission to overwrite a later choice. Strictly refuse changed binding observations (including snapshot-only races and same-ID unbind/rebind ABA); MangaDex needs no Kakao review-only exception.
- Reuse publisher fence already based on executor: scan original positions, omit all server rows, advance cursor even through empty pages, compute PC-only pending heads, reject every publisher result for a pinned server row. Retain this fence with flags OFF. Sources: `kakao_bind_worker.py:40`; `collection_bindings.py:1354`, `:1369`.

### Fetch, spacing and hard bounds

- Preflight pending/server ownership, latest work/provider intent, active library/epoch and live manga, then release DB transaction/connection before all MangaDex, image and blob I/O. Fetch detail and full covers using the PC URLs, order, matching relationships and normalization in §1. Extend `mangadex_item` for detail fields; do not feed detail through `parse_mangadex`, which is a search list capped at 20.
- Use the existing `gate.provider_locks['mangadex']` and call `gate.mangadex_spacing()` before **each** detail/page/image request. Release/reacquire admission per request so a 50-page work cannot monopolize search; serialize spacing calls with the provider lock (the spacing helper alone is not a reservation). Existing interval = 0.25 seconds. Reuse the shared pacing gate for future MangaDex callers, not a private limiter (`collection_bindings.py:200`, `:892`, `:953`). The source comment cites 5 requests/s/IP; no current provider limit was verified. Honor observed 429/Retry-After regardless of that comment.
- Proposed attempt budgets: one monotonic 90-second end-to-end deadline including admission, reads, image verification and storage; JSON request ≤20 seconds/remaining budget; cover phase ≤60 seconds, ≤50 pages ×100 records, ≤4 MiB per reply and aggregate cover envelope. Full `{detail,covers}` must also fit authority `MAX_SNAPSHOT_BYTES` = 2 MiB (`collection_authority.py:221`); fail rather than truncate or bypass it. These are guards, not promised latency.
- Original cover: ≤16 MiB (authority manifest limit), ≤16 Mi pixels, MIME and decoder verification, 30-second phase within remaining attempt budget; thumbnail fitted inside 360×360 WebP using existing helper. Use bounded sockets/short non-retrying storage client already used by automatic artwork and check stop/deadline between stages. No optional-TMDB-artwork failure swallowing: when a representative exists, its original receipt is required for applied. Thumbnail generation failure may use the existing original fallback. Sources: `mobile_collections.py:69`; `work_providers.py:45`, `:98`, `:894`, `:914`, `:968`.
- Only server-confirmed canonical manga UUID and validated filename construct HTTPS API/uploads URLs. Reject redirects, traversal and non-image bodies; no tablet thumbnail download. The current bindings transport contacts API/Kakao hosts only, and `ArtworkRequest`/`image_url` accept TMDB/IGDB only: add the exact MangaDex construction in the owning transport/pipeline, not arbitrary URL support (`collection_bindings.py:219`; `work_providers.py:80`, `:387`, `:661`). No credential is required for MangaDex.

### WorkArtwork and one authority commit

- Reuse `store_artwork`'s verified-byte/thumbnail/content-addressed receipt path: `_stored_blob` hashes bytes, derives `artwork_key`, checks/puts/checks storage, then registers original/thumbnail manifests in `mobile_collection_artwork`. Factor its storage stage if needed so a trusted MangaDex fetch feeds the same code. These staging writes are outside the authority transaction; no network/storage callback runs under its lock (`work_providers.py:943`, `:968`, `:999`).
- Blob staging is not authority completion. Under `BEGIN IMMEDIATE`, recheck ownership/state/latest intent/epoch/live target/full binding precondition and OFF/stop; reload current fields, selection, artwork and slots. Plan only from commit-time user state. Submit one deterministic `apply_command_batch`: conditional `bindProvider`, `applyProviderSnapshot`, required `addArtwork`, conditional `selectArtwork`, changed `upsertVolume` commands. All projections/feed/receipts and request `applied` commit together. Duplicate identity, missing blob receipt, failed command or CAS conflict rolls back **all** authority changes. Reuse existing MangaDex three-way merge; do not emit `updateWork` to force provider values. Sources: `collection_authority.py:552`, `:2091`, `:2177`, `:2196`, `:2227`; batch precedent: `work_providers.py:816`.
- WorkArtwork: `provider=mangadex`, `kind=cover`, `language=ja`, provider image ID = cover UUID, immutable original/thumbnail manifests. Reuse an existing same-work/provider/cover-ID record, as authority PC enqueue does, without overwriting its bytes. For an absent identity derive a stable artwork ID from work + provider + cover ID; do not apply TMDB's path/kind/hash identity convention to MangaDex. Source: `_tools/app/src-tauri/src/library/collection_authority.rs:953`, `:998`. A downloaded replacement at an already-known cover UUID does not mutate the old immutable record; retain it, matching the authority PC path.
- Preserve existing work selection, Asset cover and every non-null volume cover. Select new artwork only for an empty work selection/no Asset cover, using commit-time `expectedArtworkId=null`. If the user selected/cleared artwork during fetch, use authority change history to recognize that intent and skip auto-selection; fail conservatively if needed history is unavailable. An explicit clear must not be mistaken for an untouched empty slot.
- Port the §1 slot planner: Japanese only, first cover per parsed slot, source-null/MangaDex eligibility, preserve manual presentation/IDs/other-provider slots and omitted slots. Fill only the representative slot's null artwork. Authority stores `sourceCoverId`, **not** `sourceFileName`; the complete snapshot preserves filename resolution, and PC volume listing rematerializes filenames from that snapshot (`collection_authority.py:953`, `:2377`; `_tools/app/src-tauri/src/library/collection_volume.rs:166`). Respect authority's volume-number maximum 1,000,000 and 5,000 live-slot limit; reject an unrepresentable plan without partial writes (`collection_authority.py:228`, `:2945`). Do not invent MangaDex commercial `upsertVolumeSource` rows or infer release date/ownership from covers.
- Honor tombstone revisions and avoid deterministic IDs overwriting a moved slot. Reuse Kakao's unique-tombstone revival policy preserving ID/cover/manual fields; ambiguous tombstones fail. This is explicit recovery policy, not a claim that the old local SQL handled tombstones.
- Record a quiet baseline using the full binding snapshot and existing monotonic MangaDex release-schedule slots, with no `recordReleaseEvent` in bind. Existing server schedule derives MangaDex slots from authority volumes (`collection_authority.py:2550`). Include PC catch-up/repeated refresh fixtures proving the first post-handover read does not manufacture initial notifications. No new daily MangaDex worker is included.
- Successful `unbindProvider(mangadex)`, including already-unbound no-op, atomically supersedes its pending server intents as Kakao does; retain slots/artwork. Trash/epoch changes are also checked at commit. No new unbind UI (`collection_authority.py:2152`).

- Preserve `operationConflict` and its existing fixed message. Distinguish missing manga from missing required cover: cover 404 fails the cover stage, never silently succeeds metadata-only. No Japanese cover in a valid complete list is success with no artwork commands and all existing covers retained.
- Transport/timeout/429/5xx, temporary storage and SQLite contention keep pending, using Kakao's durable capped backoff and Retry-After policy. Authentication/access errors use the existing longer delay, not a fabricated MangaDex-key requirement. Cap each attempt/backoff, not an invented finite retry count: Kakao currently retains transient pending indefinitely with bounded waits (`kakao_bind_worker.py:316`; `collection_release_checks.py:415`). Do not reuse daily-check eligibility to delay explicit binds. Map permanent decode/size/identity/authority failures to safe reasons above.
- Request payload hash/operation ID replay precedes readiness/provider traffic. Derive batch ID from library/epoch/request operation ID in a MangaDex namespace, child IDs from command/entity keys. Batch payload contains stable intent identity/digest, not mutable fetch output. Check completed request/receipt before any I/O; changed payload under same ID remains conflict. Crash before commit retries; crash after commit replays without additional fetch, deltas or events. Content-addressed uploads may survive a losing/aborted attempt; they are not an applied binding, and this task adds no blob deletion/GC. Respect existing receipt/request retention limits.
- `LAKOMICS_MANGADEX_BINDS` defaults OFF. OFF starts no MangaDex execution, does no MangaDex worker I/O, creates no execution metadata on a fresh schema when both bind features are OFF, and advertises nothing for MangaDex. Existing Kakao behavior is unchanged. After ON→OFF, keep pinned MangaDex rows pending with owner/retry metadata, stop before commit and resume on ON; no PC reassignment. Completed replay remains readable while OFF. In-flight HTTP may finish bounded reads, but cannot proceed to a new stage/authority commit after stop. Use existing stop/lane synchronization to define the commit boundary, not a lone unsynchronized flag check.
- Recommend **`serverMangaDexBinds`**, with optional bindings status **`mangadexApply:true`**, independently from `serverKakaoBinds` and search/release capabilities. Advertise only with active authority, live ready executor and configured artwork storage/decoder. Independent flags express different cover/storage failure and rollback scopes; extending `serverKakaoBinds` would mislead existing clients. ON but unready refuses new requests with controlled 503, never silently pins PC. Reuse Kakao feature machinery (`kakao_bind_worker.py:45`, `:108`; `collection_bindings.py:270`).

## 5. Risks, defaults and minimal open questions

1. **Selection policy mismatch:** adopt the preservation default in §1: download/store the representative but retain all existing selections, auto-select only untouched empty/no-Asset cover. This meets the user's preservation decision; it intentionally differs from today's work-selection overwrite. No additional UX control is proposed.
2. **Hard limits versus legacy success:** retain authority's 16 MiB image and 2 MiB snapshot limits and fail safely; do not downsample originals, truncate covers or enlarge shared limits in this work. Current PC network caps are larger, so some fetches already cannot complete authority apply. Decoder pixel/time guard may also refuse an unusually large legitimate image. Whether those shared limits should later be raised is the only remaining product question; default is no.

Operational risks: provider quota/latency/actual image sizes and queue state were not measured; shared gate may contend with search, and staged orphan blobs remain governed by existing retention/GC. The PC's old direct/new-work/refresh paths can still race while clients are outdated; authority CAS and upgrade/outbox drain are required, not a second authority or clock rule. Baseline-to-PC catch-up deserves a real fixture because the old PC has local seen tables, while server schedule state is shared. No claims of live provider, native, device or production success are made.

Audit verification: inline source review only; no code/runtime tests run for this documentation task. Initial `git status` showed no changed files but reported inaccessible pre-existing `server/lakomics-api/tmp*` directories; those directories were not accessed or modified. The final document is checked for LF and write scope. No implementation, deployment, activation, backfill, cleanup or backlog change is authorized by this proposal.

The user chose server-side cover download (representative Japanese cover through the WorkArtwork pipeline). The controller accepts this document's defaults: keep every existing work selection, Asset cover and volume cover, and auto-select the new cover only for an untouched empty slot (§5.1); keep the shared 16 MiB image and 2 MiB snapshot limits and fail safely (§5.2); quiet baseline on every bind; separate `LAKOMICS_MANGADEX_BINDS` switch and `serverMangaDexBinds` / `mangadexApply` advertisement. ## 7. Slice 1 implementation notes (2026-10-10)

Server slice is dormant: `LAKOMICS_MANGADEX_BINDS` defaults OFF. Evidence so far is plain-Python only; the FastAPI/route suites have not been run.

- **Shared lane:** `kakao_bind_worker.py` now carries both providers (one serial lane, provider-specific readiness, per-request executor pinning, publisher fence unchanged). `startup_db` adds the execution columns when either switch is ON; with both OFF nothing is migrated, no thread starts and no worker I/O happens. `mangadex_bind.py` holds only MangaDex fetch, normalization and planning; importing it is stdlib-only.
- **Fetch:** detail plus every cover page (offset order preserved, at most 50 pages x 100, 4 MiB per reply and envelope, 2 MiB snapshot, one 90-second attempt deadline, 60-second cover phase), each request behind `provider_locks['mangadex']` and `gate.mangadex_spacing()`. Detail fields reuse `mangadex_item(..., detail=True)`. An oversized reply is marked on the `Upstream("invalid")` error (`too_large` attribute) so Kakao and search keep classifying it as invalid.
- **Cover:** representative = first `ja` cover with volume exactly `"1"`, else first `ja`; fetched from `https://uploads.mangadex.org/covers/{mangaId}/{fileName}` through `work_providers.mangadex_image` (no redirects, 16 MiB, 16 Mi pixels) and staged by the new shared `store_artwork_bytes` (the former body of `store_artwork`, now with a stop hook and an opt-in strict deadline). All staging happens before the commit transaction.
- **Commit:** one `apply_command_batch` under `BEGIN IMMEDIATE`, after the commit lock/stop/OFF recheck: conditional `bindProvider`, `applyProviderSnapshot`, `addArtwork` (reusing an existing same-cover record), `selectArtwork` only when the work slot and Asset cover are empty and the authority change history (plus the last `selectArtwork` receipt, so unchanged explicit clears count) shows no selection activity since enqueue, and changed `upsertVolume` rows (first cover per slot, provider null/MangaDex only, covers never replaced). Any changed binding observation is refused as `bindingChanged`. No `recordReleaseEvent` is issued, so the baseline is quiet.
- **Advertisement:** `serverMangaDexBinds` and bindings status `mangadexApply:true` only with the switch ON, active authority, live executor, R2 settings present and the image decoder (JPEG/WebP/zlib) available. ON but unready gives a controlled 503 `mangadexApplyUnavailable`.
- **Tests:** `tests/test_mangadex_bind_core.py` (plain Python, offline fixtures including the real staging body) and `tests/test_mangadex_bind_routes.py` (HTTP/projection; needs the server-stage dependencies and is unrun).

## 8. Slice 2 implementation notes (2026-10-10)

PC and tablet clients are implemented against the §3 contract; the direct PC path is unchanged without advertisement and without an unresolved server intent. Evidence is injected-transport Rust tests and jsdom tests only; no native, device, live-provider or server-integration run was made.

- **Shared adapter:** `server_bind_intents.rs` holds the persisted-intent/post/replay/validate/pull logic extracted from `server_kakao_binds.rs`. Keys are `serverKakaoIntent:`/`serverMangaDexIntent:` plus endpoint plus work, so the existing Kakao keys survive upgrades. Provider code supplies only the choice and a same-choice predicate (Kakao: unchanged full equality; MangaDex: UUID only). Keys are resolved before taking the single library connection.
- **MangaDex routing:** `server_mangadex_binds.rs` routes search and apply for existing manga targets to the server when `serverMangaDexBinds` is cached or an unresolved MangaDex intent exists. A fresh choice also needs bindings status `mangadexApply:true`; an unresolved same-UUID body replays straight to POST (replay before readiness, also after withdrawal). A coded refusal clears the intent; unknown outcomes keep it and never trigger a local apply; `applied` is returned only after the authority pull, with the pulled collection. New-work import and MangaDex refresh remain on the old paths.
- **Command contract:** `apply_mangadex` returns either a `CollectionSummary` (local path) or `{outcome, message, collection?}`; `search_mangadex` takes an optional `collectionId`. `kakao_intent_post` and `pull_kakao_authority` were renamed to `collection_intent_post` and `pull_bind_authority`.
- **PC dialog:** `MangaDexImportDialog` shows `연결 대기 · 서버에서 처리 중` for pending without closing or calling `onApplied`; failed/superseded show the server message inline; applied calls `onApplied` only with a confirmed collection; busy state blocks re-selection and closing.
- **Tablet:** `BindStatus.mangadexApply?` and one `providerCanApply(status, provider)` helper replace the Kakao-only branches. Copy: `고르면 서버에서 작품 정보와 일본판 표지를 연결해요.` / `내가 고친 값과 고른 표지는 그대로예요.`; mixed-provider notes name only the PC-dependent provider (`MangaDex 연결은 PC 앱을 업데이트해야 적용돼요.`). The search sheet opens only after the first capability read (no PC-copy flash); a failed first read shows a retry alert. Request `executor` still governs wording after withdrawal.
- **Tests:** Rust `server_mangadex_binds` (replay after restart and withdrawal, correlated reply validation, pull failure keeps ID, refusal cleanup, UUID same-choice, key isolation, new-work/unadvertised stays local) plus the existing Kakao tests; PC dialog pending/applied/failed/superseded; tablet capability matrix, withdrawal wording, first-read wait and retry.
- **Not covered:** native Tauri, Android device, a live server with `LAKOMICS_MANGADEX_BINDS` ON, and tablet-originated requests against an active-authority PC (still fenced).
- **Slice 2 fixes:** PC selections now thread the display title through `MangaDexApplyRequest` into `choice.title` (trimmed, at most 500 characters, falling back to the current work name and refusing an empty hint); same-UUID retries still replay the stored body regardless of title changes. Rust coverage asserts the complete server request shape and title limits. Tablet panel, search and confirmation copy now states that providers without server capability cannot yet be handled by the server, including mixed and no-capability cases, while preserving notes for old servers without bind requests; capability-matrix tests cover the corrected wording.

## 9. Volume cover fill (2026-10-10)

The existing serial bind worker now fills up to eight missing MangaDex volume covers per wake, after processing a bind or while idle. It also discovers active authority manga works without a server bind request; newer binding timestamps (then applied request sequence) take priority. Eligibility follows the PC rules: live MangaDex-sourced slots within the work's volume range, NULL artwork, and a known cover ID. File names come exclusively from matching Japanese records in the stored binding snapshot.

The representative and volume covers share one fetch/staging helper: provider lock and MangaDex spacing per request, 30-second image deadline within a 90-second attempt, 16 MiB/16 Mi pixel guards, and the existing decoder/blob storage. Existing same-work provider image IDs are reused without download. Each cover commits through one authority batch under BEGIN IMMEDIATE, rechecking active library/epoch, binding revision/snapshot, work and slot eligibility. User covers, work selection, labels/order and other volume state are preserved; no release events are generated.

A small `mangadex_volume_cover_attempts` table is created only with `LAKOMICS_MANGADEX_BINDS` ON. It persists per-slot/cover permanent skips (404, invalid/oversized image or unusable snapshot) and transient retry deadlines, using the existing backoff/Retry-After policy. Identity changes can receive fresh attempts; successful retries remove their attempt state. Remaining covers continue on later wakes. OFF performs no fill I/O or migration, including when Kakao alone is ON.

Offline core tests cover bounded continuation, authority-only works, concurrent user selection, artwork reuse, permanent skips, 429 restart/resume, OFF, binding races, rollback and quiet behavior. The FastAPI route test checks authority projection of covers for volumes 2 onward over multiple wakes; it still requires the server-stage run. No network, production or device acceptance was performed.
