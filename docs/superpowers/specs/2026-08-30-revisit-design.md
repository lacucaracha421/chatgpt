# 2026-08-30 · 다시보기 설계

## 목적

기존 `작가`와 `달력`을 별도의 빠른 보기로 유지하지 않고, 사용자가 많은 자산을
다시 발견하고 추천받는 단일 목적지 `다시보기`로 통합한다. 다시보기는 자산을
정리하거나 관리하는 화면이 아니라, 이미 저장한 자산을 작은 맥락 묶음으로 다시
보는 경험에 집중한다.

## 정보 구조

사이드바에는 `다시보기` 하나만 둔다. 화면 내부의 최상위 탭은 다음 두 개다.

- `오늘`: 하루 동안 고정되는 추천 자산 묶음
- `둘러보기`: 사용자가 날짜 또는 작가를 기준으로 직접 탐색

`둘러보기` 안에는 `날짜 / 작가` 로컬 탭만 둔다. 별도 `보관함`과 `연결` 탭은
초기 범위에서 제외한다. 기존 작가 카드 크기 조절 기능은 작가 화면에서 유지한다.

## 오늘

### 구성

- 하루에 6~10개의 작은 자산 묶음을 만든다.
- 각 묶음은 6~20개의 자산을 포함한다.
- 화면은 하나의 큰 주인공 묶음과 여러 작은 묶음으로 구성하는 편집형 레이아웃을
  사용한다.
- 주인공 묶음의 유형은 매일 순환한다. 후보 유형은 재발견, 작가, 날짜/시간,
  뜻밖의 연결이며, 선택된 유형 안에서 가장 적합한 후보를 고른다.
- 각 묶음에는 `8개월 동안 열지 않은 즐겨찾기`처럼 추천 이유를 짧게 표시한다.

### 추천 후보 생성

초기 버전은 이미지 임베딩 없이 기존 메타데이터와 로컬 사용 기록만 사용한다.

- 오래 보지 않은 즐겨찾기
- 아직 열지 않은 오래된 자산
- 작가 집중 보기
- 과거의 오늘 또는 특정 시기 묶음
- 최근 열어본 자산의 작가·분류 이어보기
- 사용자가 거의 탐색하지 않은 영역
- 자산이 1~2개뿐인 작가를 다시 보여주는 `한 번만 만난 작가`

추천 구성은 익숙한 재발견과 새로운 발견을 비슷한 비중으로 섞고, 일부는 의외성을
위해 남긴다. 정확한 가중치는 구현 중 조절 가능한 정책으로 두고 UI에 노출하지
않는다.

### 고정과 섞기

당일 추천 결과는 저장하여 앱을 다시 열어도 동일하게 유지한다. 사용자는 개별
묶음이나 오늘 전체를 다시 섞을 수 있다. 다시 섞기는 취향 신호로 해석하지 않는다.

### 피드백

- 즐겨찾기: 강한 긍정
- 같은 묶음에서 여러 자산 열기: 중간 긍정
- 자산 한 번 열기: 약한 신호
- 다시 섞기: 중립
- `관심 없음`: 명시적 부정

`관심 없음`은 작은 팝오버로 `이 묶음만 숨기기`, `이 작가 덜 보기`, `이 추천
유형 덜 보기`를 선택하게 한다.

## 둘러보기 · 날짜

### 기본 상태

날짜 탭에 들어오면 월간 달력을 먼저 펼쳐서 보여준다. 월 헤더에는 해당 월의 전체
자산 수와 저장 활동이 있었던 날짜 수를 표시한다. 날짜 셀에는 실제 저장 개수를
표시하고, 개수 차이는 로그 스케일의 accent 농도로 보조한다.

### 날짜 선택

날짜를 누르면 달력을 축약 헤더로 접고, 선택한 로컬 날짜에 저장된 자산만 아래에
보여준다. 축약 헤더의 이전/다음 버튼은 빈 날짜를 건너뛰고 이전/다음 활동일로
이동한다. `달력 펼치기`로 월간 달력 상태로 돌아간다.

### 날짜 의미

`collected_at` 원본은 UTC 시각으로 계속 저장한다. 달력 집계와 날짜 필터는 사용자의
로컬 날짜를 기준으로 한다. 선택한 로컬 날짜의 시작과 끝을 UTC 범위로 변환하여
조회하며, UTC 문자열의 날짜 부분을 자르는 방식은 사용하지 않는다.

기존 `around_date`는 특정 시점 주변으로 갤러리를 이동하는 기능이므로 다시보기의
정확한 일자 필터와 분리한다. 기존 데이터 마이그레이션은 필요하지 않다.

## 둘러보기 · 작가

작가 화면은 호버에 의존하지 않는 상시 콜라주 카드 그리드를 사용한다. 카드에는
대표 이미지 한 장과 보조 이미지 최대 세 장을 배치하며, 보유 자산이 적으면 이미지
수를 자연스럽게 줄인다. 카드를 선택하면 해당 작가의 전체 자산 갤러리로 들어간다.

- 기본 정렬: 추천순
- 추가 정렬: 자산 수, 최근 수집, 오래 보지 않음, 이름
- 검색: 자산 수와 관계없이 모든 작가 검색
- 기본 그리드: 자산 3개 이상인 작가
- `소규모 작가 포함`: 자산 1~2개인 작가까지 그리드에 추가

1500명 이상의 작가에서도 전체 DOM을 만들지 않도록 기존 행 가상화를 유지한다.

## 상태와 모듈 경계

추천 로직은 Library 백엔드가 담당하고 UI에는 완성된 묶음을 전달한다. 이 경계는
추천 후보 생성, 당일 결과 고정, 다시 섞기, 피드백 반영을 한곳에 모은다. UI는
레이아웃과 사용자 입력만 담당한다.

자산별 사용 기록은 전체 이벤트 로그 대신 다음 집계값만 로컬 DB에 저장한다.

- 마지막으로 연 시각과 누적 열람 횟수
- 마지막 추천 노출 시각과 누적 노출 횟수

별도로 날짜별 추천 결과와 사용자가 선택한 부정 피드백을 저장한다. 이 데이터는
활성 라이브러리에 쓰는 자산 메타데이터가 아니라 애플리케이션 내부 상태로 관리한다.

## 오류와 빈 상태

- 추천 후보가 부족하면 묶음 수 또는 묶음 안의 자산 수를 줄이고 중복으로 채우지
  않는다.
- 선택한 날짜의 자산이 사라졌다면 빈 상태와 `달력 펼치기` 동작을 제공한다.
- 커버 파일을 읽지 못한 자산은 기존 대체 표면을 사용하며 묶음 전체를 실패시키지
  않는다.
- 추천 상태 저장에 실패하더라도 이번 세션의 결과는 표시하되 다음 실행에서 새로
  생성할 수 있다.

## 검증 기준

- KST 자정부터 오전 8시 59분 사이에 저장된 자산도 화면 표시와 같은 로컬 날짜에
  집계된다.
- 날짜 선택 결과에는 해당 로컬 날짜의 자산만 포함된다.
- 앱 재실행 후에도 같은 날의 추천 결과가 유지된다.
- 개별 묶음 섞기와 전체 섞기가 다른 범위에만 영향을 준다.
- 기본 작가 목록은 3개 이상 작가만 표시하고, 검색과 토글은 소규모 작가까지 찾는다.
- 1500명 이상의 작가 목록에서 스크롤과 검색이 기존 수준의 반응성을 유지한다.

## 초기 범위에서 제외

- 이미지 임베딩 또는 의미 기반 유사도 모델
- 전체 원시 행동 이벤트 로그
- 별도 보관함 및 연결 탐색 탭
- 클라우드 동기화와 여러 기기 사이 추천 상태 공유
