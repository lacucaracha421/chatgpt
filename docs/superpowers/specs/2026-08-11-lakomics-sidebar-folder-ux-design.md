# Lakomics 사이드바 폴더 UX 설계

## 목표

Lakomics의 기존 계층형 분류를 사용자가 이해하기 쉬운 폴더 트리로 표현한다. Eagle처럼 사이드바에서 폴더와 하위 폴더를 빠르게 만들고, 이름을 바꾸고, 이동하고, 안전하게 삭제할 수 있어야 한다. 확장 프로그램은 분류를 읽기만 하며 분류 편집은 Lakomics가 소유한다.

같은 변경에서 X 이미지 드래그 도넛이 열린 뒤 브라우저의 후속 클릭이 발생해 이미지 뷰어가 열리는 버그도 차단한다.

## 용어와 데이터 모델

사용자 UI에서는 계층형 분류 항목을 모두 **분류 폴더**라고 부른다. 분류 폴더는 실제 파일 저장 위치가 아니며 하나의 자산은 여러 분류 폴더에 동시에 연결될 수 있다. 내부 데이터베이스와 API의 `root`, `work`, `tag` 종류는 호환성을 위해 유지한다.

- 최상위 새 폴더는 내부적으로 `root`로 생성한다.
- 기존 폴더 아래 새 폴더는 내부적으로 `tag`로 생성한다.
- 기존 `work` 항목도 폴더로 표시하되 작품 아이콘으로 구분한다.
- 자산과 폴더의 연결, 상위 항목 포함 조회, 이름 중복과 이동 제약은 기존 라이브러리 규칙을 그대로 사용한다.

DB 마이그레이션이나 별도 폴더 테이블은 만들지 않는다.

## 사이드바 상호작용

사이드바의 분류 트리는 폴더 아이콘과 이름으로 표시한다.

빈 트리 영역의 우클릭 메뉴:

- 새 폴더

폴더의 우클릭 메뉴:

- 하위 폴더 만들기
- 이름 변경
- 폴더 이동
- 삭제

단축키:

- `Ctrl+Shift+N`: 최상위 새 폴더
- `Alt+N`: 현재 선택 폴더 아래 새 폴더
- `F2`: 현재 선택 폴더 이름 변경
- `Delete`: 현재 선택 폴더 삭제 확인

우클릭 메뉴와 단축키는 같은 명령 함수를 사용한다. 생성과 이름 변경은 모달이 아니라 트리 내부 입력창에서 수행한다. `Enter`는 저장하고 `Escape`는 취소한다. 이름이 비었거나 같은 부모 아래에서 중복되면 입력창을 유지하면서 오류를 바로 표시한다.

기존 포인터 드래그 이동은 폴더 안쪽 드롭만 허용하는 방식으로 단순화한다. 위·아래 삽입선을 없애고 트리는 이름순으로 정렬한다. 자기 자신, 자신의 자손, 같은 이름의 형제가 생기는 위치는 이동 대상으로 허용하지 않는다.

최상위 `root` 폴더는 다른 폴더 아래로 이동할 수 없다. `work` 작품 폴더는 `root` 아래로만 이동할 수 있으며 가능한 대상만 표시한다. 하위 폴더가 있는 폴더를 이동하면 전체 가지가 함께 이동한다. 이동 성공 후 이동한 폴더의 선택과 펼침 상태를 유지하고 새 상위 폴더를 펼친다.

자산을 분류 폴더로 드래그하면 기존 분류 연결을 제거하지 않고 대상 분류를 추가한다. 드래그 피드백에는 `폴더에 추가`라고 표시한다.

## 삭제와 오류

하위 폴더가 있는 폴더는 삭제할 수 없다. 하위 폴더가 없는 일반 폴더를 삭제하면 그 폴더에 직접 연결된 모든 상태의 자산을 상위 폴더에 직접 연결한 뒤 기존 연결과 폴더를 삭제한다. 자산의 다른 분류 연결은 그대로 유지한다. `work` 작품 폴더에도 같은 규칙을 적용한다.

하위 폴더가 없는 최상위 폴더를 삭제하면 해당 폴더의 자산 연결만 제거하고 자산 자체는 보존한다. 자산 연결 변경과 폴더 삭제는 하나의 서버 트랜잭션에서 수행하며, 중간 단계가 실패하면 아무것도 변경하지 않는다.

하위 폴더가 있으면 메뉴에 비활성화된 `삭제 — 하위 폴더 있음`을 표시하고 `Delete` 단축키도 같은 이유를 알림으로 보여준다. 일반 폴더의 삭제 확인창은 정확한 자산 수를 미리 조회하지 않고 자산이 상위 폴더로 이동한다는 결과를 설명한다. 최상위 폴더에는 자산은 보존되고 해당 폴더 연결만 제거된다고 안내한다. 현재 선택한 일반 폴더를 삭제한 뒤에는 상위 폴더를 선택하고, 최상위 폴더를 삭제한 뒤에는 전체 자산 보기를 선택한다.

생성, 이름 변경, 이동, 삭제가 성공하면 분류 목록을 다시 불러온다. 실패하면 현재 편집·선택 상태를 가능한 한 유지한다.

## X 도넛 후속 클릭 차단

이미지 포인터가 12px 이상 이동해 도넛이 열린 경우에만, 같은 제스처 뒤 발생하는 첫 `click` 이벤트를 캡처 단계에서 `preventDefault`와 `stopImmediatePropagation`으로 소비한다. 이를 통해 X의 이미지 뷰어가 열리지 않게 한다.

12px 미만에서 끝나는 일반 클릭은 소비하지 않으며 X의 원래 동작을 유지한다. 취소, Escape, 포인터 취소와 창 포커스 상실도 도넛이 실제로 열렸다면 같은 후속 클릭 방지 규칙을 적용한다.

## 범위 밖

- 확장 프로그램에서 폴더 생성·이름 변경·이동·삭제
- Eagle의 바로 가기, 링크 복사, 자동 태깅, 비밀번호, 정렬 기준, 복제, 내보내기
- 폴더 검색과 수동 정렬
- 별도 다운로드 폴더 또는 브라우저 다운로드 연동
- 분류 데이터 모델 교체나 DB 마이그레이션

## 테스트

자동 테스트는 다음을 검증한다.

- 빈 영역 메뉴에서 최상위 폴더 생성
- 폴더 메뉴와 `Alt+N`으로 하위 폴더 생성
- 인라인 이름 변경의 저장과 취소
- 빈 이름과 중복 이름 실패 시 편집 상태 유지
- 안쪽 드래그 이동, 전체 가지 유지, 최상위·작품·자손·중복 이름 대상 거부
- 자산 드래그가 기존 분류를 유지하면서 대상 분류를 추가
- 하위 폴더가 있는 폴더의 삭제 거부
- 일반 폴더 삭제 시 모든 상태의 직접 연결 자산을 상위 폴더로 이전
- 자산이 연결된 최상위 폴더 삭제 시 자산 보존과 해당 연결 제거
- 삭제 트랜잭션 실패 시 폴더와 자산 연결 유지
- 삭제 후 상위 폴더 선택과 삭제 불가 이유 표시
- 우클릭 메뉴와 단축키가 같은 명령 경로를 사용
- 도넛이 열린 제스처의 첫 후속 클릭 차단
- 12px 미만 일반 클릭 유지
