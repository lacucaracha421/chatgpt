# Lakomics Eagle Compact UI 재설계

날짜: 2026-08-09
상태: 사용자 승인

## 목적

현재 Lakomics의 기능과 3단 작업 구조는 유지하면서, 간격과 표면 표현을 Eagle에 가까운 밀도 높은 Windows 데스크톱 UI로 정돈한다. 이미지가 화면의 주인공이어야 하며, 둥근 카드와 과도한 패딩 때문에 일반적인 웹 대시보드처럼 보이지 않아야 한다.

이번 설계는 기존 `2026-08-08-lakomics-daily-use-ui-design.md`의 기능 요구사항을 변경하지 않는다. 다만 그 문서의 “shadcn을 추가하지 않는다”는 결정은 이번 승인으로 대체한다. shadcn은 전체 레이아웃이 아니라 공통 상호작용 부품에만 제한적으로 사용한다.

## 범위

### 포함

- 기존 왼쪽 분류, 가운데 갤러리, 오른쪽 정보 패널 구조의 시각적 정돈
- 상단 도구 모음과 선택 작업 모음의 밀도 개선
- 공통 색상, 간격, 크기, 모서리 토큰 재정의
- 사이드바와 갤러리의 여백 및 선택 상태 개선
- 정보 패널의 자동 열기와 직접 닫기
- 외부 파일 드래그 진입, 처리 중, 성공, 중복, 실패 상태의 일관된 표시
- shadcn 계열 공통 메뉴, 툴팁, 대화상자, 토스트, 입력 부품의 선택적 도입
- 일반 창과 좁은 창의 실제 화면 검증

### 제외

- 컬렉션
- 검색 기능
- 태그 또는 자산 데이터 모델 변경
- 영상 재생과 만화 읽기
- 새로운 유사 이미지 판별 알고리즘
- 전체 앱을 Tailwind 또는 shadcn 기본 프리셋으로 재작성하는 작업

## 선택한 방향

`A. Eagle Compact` 방향을 사용한다.

- 기존 배치와 도메인별 Module은 유지한다.
- 구역은 카드가 아니라 얇은 경계선으로 나눈다.
- 갤러리와 전체화면 뷰어는 Lakomics 전용 구현을 유지한다.
- 공통 상호작용 부품만 shadcn 구현 방식을 참고하거나 가져와 `shared/ui`에 둔다.
- shadcn의 기본 외형을 그대로 사용하지 않고 Lakomics 토큰으로 표현한다.
- 기존 공통 UI를 한 번에 폐기하지 않고, 이번 화면에서 실제로 사용하는 부품부터 교체한다.

## 화면 구조

### 기본 배치

화면은 다음 순서를 유지한다.

1. 왼쪽 분류 사이드바
2. 가운데 갤러리 또는 자산 감상 화면
3. 선택한 자산의 오른쪽 정보 패널

상단에는 현재 위치와 자산 작업을 표시하는 도구 모음을 둔다. 하단 상태 표시줄은 작업 중이 아닐 때 시선을 끌지 않도록 낮은 대비로 유지한다.

### 기준 치수

치수는 화면별 숫자로 복사하지 않고 전역 디자인 토큰에서 관리한다.

- 상단 도구 모음: 40px
- 하단 상태 표시줄: 24px
- 사이드바 기본 너비: 208px
- 사이드바 조절 범위: 176~320px
- 정보 패널 너비: 272px
- 갤러리 바깥 여백: 6px
- 이미지 사이 간격: 4~6px
- 일반 행 높이: 28px
- 일반 컨트롤 높이: 28px
- 강조 컨트롤 높이: 30px

창 너비가 1100px보다 작으면 정보 패널은 갤러리 열을 줄이지 않고 오른쪽에 겹쳐서 나타난다. 사이드바는 현재의 너비 조절 기능을 유지하되 최소 너비 아래로 줄어들지 않는다.

### 정보 패널

정보 패널은 자산을 선택하지 않은 상태에서는 닫혀 있다. 자산을 클릭하거나 선택해도 정보 패널은 자동으로 열리지 않으며, 상단 도구 모음의 정보 토글을 눌러서만 연다. 여러 자산을 선택했을 때는 공통 태그와 일괄 작업에 필요한 요약만 보여준다.

선택을 모두 해제하면 정보 패널의 내용은 비워지며 패널도 닫힌다. 좁은 창에서 패널을 연 상태로 갤러리를 조작하면 패널 밖을 클릭해 닫을 수 있다. Escape는 전체화면 뷰어가 열려 있으면 뷰어를 먼저 닫고, 그렇지 않으면 겹쳐진 정보 패널을 닫는다.

## 시각 체계

### 색상

푸른 기가 강한 기존 표면을 중성 짙은 회색으로 조정한다. 아래 값은 중앙 토큰의 기준값이며 화면 컴포넌트에서 직접 반복하지 않는다.

- 앱 배경: `#111316`
- 사이드바: `#181b1f`
- 도구 모음: `#1b1e22`
- 일반 표면: `#202328`
- 호버 표면: `#282c31`
- 경계선: `#2b2f35`
- 기본 글자: `#e7e9ec`
- 보조 글자: `#8e959f`
- 선택 및 포커스: `#4e8df7`
- 오류: `#e26767`

강조색은 선택, 키보드 포커스, 유효한 드롭 위치, 주요 실행 버튼에만 사용한다. 표면마다 파란색을 섞지 않는다.

### 간격과 형태

- 간격 토큰은 4, 6, 8, 12, 16px을 기본으로 사용한다.
- 이미지 타일은 기본적으로 2px 이하의 모서리를 사용한다.
- 버튼과 행은 3~4px의 모서리를 사용한다.
- 메뉴와 정보 패널은 최대 6px, 대화상자는 최대 8px을 사용한다.
- 그림자는 팝업, 대화상자, 드래그 미리보기처럼 실제로 떠 있는 요소에만 사용한다.
- 사이드바, 도구 모음, 갤러리, 정보 패널을 각각 둥근 카드로 감싸지 않는다.

글꼴은 Windows에서 안정적인 `Segoe UI`를 유지한다. 본문은 12~13px, 보조 정보는 11px, 화면 제목은 14~16px 범위에서 토큰화한다. 제목이라는 이유만으로 과도하게 굵거나 크게 만들지 않는다.

## 상단 도구 모음

### 일반 상태

일반 상태에서는 다음 항목만 바로 노출한다.

- 현재 위치 이름
- 정렬 방식: 최신순, 오래된순, 좋아요순, 랜덤
- 썸네일 목표 크기
- 메타데이터 표시 토글
- 파일 가져오기

특정 분류를 보고 있을 때만 “이 분류만” 범위 토글을 노출한다. 랜덤 정렬일 때만 다시 섞기 버튼을 노출한다. 자주 쓰지 않는 작업은 `⋯` 메뉴에 넣는다. 아이콘만 표시하는 버튼은 접근 가능한 이름과 툴팁을 가져야 한다.

### 선택 상태

하나 이상의 자산을 선택하면 일반 정렬 도구 대신 다음 선택 작업을 표시한다.

- 선택 개수
- 태그 추가 및 제거
- 좋아요 켜기 및 끄기
- 휴지통 이동
- 선택 해제

선택 작업은 한 줄에 들어가야 한다. 공간이 부족하면 태그 작업과 덜 자주 쓰는 작업을 `⋯` 메뉴로 옮기며 가로 스크롤을 만들지 않는다.

## 갤러리

기존 justified-row 배치와 가상화를 유지한다. 이미지 비율은 보존하고 현재 보이는 행만 렌더링한다. 시각 재설계 때문에 전체 목록을 다시 렌더링하거나 별도의 카드 자료 구조를 만들지 않는다.

- 이미지 사이 간격은 목표 썸네일 크기와 무관하게 4~6px을 유지한다.
- 타일 자체 배경과 모서리 표현은 최소화한다.
- 선택한 자산에는 안쪽 2px 파란 테두리를 표시해 레이아웃 크기를 바꾸지 않는다.
- 좋아요 표시는 이미지 위 작은 아이콘으로만 표시한다.
- 메타데이터 토글이 꺼져 있으면 파일명과 부가 정보 층을 렌더링하지 않는다.
- 빈 공간 클릭은 선택을 해제한다.

## shadcn 적용 방식

shadcn은 설치형 UI 프레임워크가 아니라 프로젝트에 소스가 들어오는 공통 부품 모음으로 취급한다. 필요한 부품의 접근성 및 키보드 동작은 Radix 기반 구현을 사용하고, 외형은 기존 CSS 토큰 구조에 맞춘다. 이번 단계에서 전체 Tailwind 전환이나 shadcn 프리셋 적용은 하지 않는다.

우선 적용 대상은 다음과 같다.

- 메뉴와 우클릭 메뉴
- 툴팁
- 확인 및 중복 비교 대화상자
- 토스트 알림
- 선택 입력, 슬라이더, 토글, 텍스트 입력

공통 부품은 `app/src/shared/ui`에 두고, 업무 화면은 해당 Interface만 사용한다. 같은 목적의 메뉴나 대화상자를 화면별로 새로 만들지 않는다. 디자인 토큰은 `app/src/styles`가 소유하며, 공통 부품 내부에 색상과 간격을 직접 반복하지 않는다.

다음 요소는 업무 특화 구현으로 유지한다.

- `layout`: 전체 화면 배치와 좁은 창 전환
- `classification`: 분류 트리와 내부 드래그 대상
- `assets`: 가상화 갤러리, 선택, 정보 패널, 감상 화면
- `ingestion`: 외부 파일 드롭 상태와 작업 진행 표시
- `drag-out`: Windows 탐색기로 복사하는 네이티브 드래그

## 외부 파일 드래그 앤 드롭

일반 자산 보기를 열고 있으면 앱 창의 어느 위치에 놓아도 파일을 가져올 수 있다. 휴지통, 설정, 안전 확인처럼 드롭을 받지 않는 화면에서는 오버레이를 표시하지 않는다.

### 진입 상태

- 전체 화면을 불투명하게 덮지 않는다.
- 작업 영역 가장자리에 2px 파란 테두리를 표시한다.
- 중앙에 “여기에 놓아 추가”와 지원 형식만 짧게 표시한다.
- 아직 파일 경로를 받지 못한 `over` 상태에서는 지원 여부를 단정하지 않는다.
- 내부 자산 또는 분류 드래그는 외부 파일 드롭 오버레이를 열지 않는다.

### 처리 상태

파일을 놓으면 FIFO 수집을 시작하고 하단 작업 영역에 전체 개수, 완료 개수, 실패 개수를 표시한다. 갤러리 탐색과 스크롤은 계속 가능해야 한다. 성공한 자산은 현재 정렬 규칙에 맞는 위치에 나타나며, 완료 토스트는 짧게 표시한다.

완전히 같은 파일은 새 자산을 만들지 않고 “이미 존재하는 파일입니다”라는 결과를 표시한다. 수집 Module이 유사 후보를 반환하는 경우에만 공통 비교 대화상자를 열고 원본, 새 파일, 둘 다 유지 중 하나를 고르게 한다. 유사도 계산 자체는 이번 UI 재설계 범위에 포함하지 않는다.

실패한 파일은 작업 영역에 파일명과 사용자에게 이해되는 짧은 이유를 표시한다. 재시도 가능한 실패만 재시도 동작을 제공하며, 성공한 파일을 다시 처리하지 않는다.

## 오류와 동시 작업

- 목록 조회가 실패하면 기존 자산을 성공한 것처럼 비우지 않고 재시도 상태를 표시한다.
- 일괄 작업 중에는 같은 작업을 다시 실행할 수 없다.
- 오래된 비동기 응답은 현재 보기, 선택, 정보 패널 상태를 덮어쓰지 않는다.
- 토스트와 작업 상태는 `aria-live`로 전달하되 현재 포커스를 빼앗지 않는다.
- 대화상자는 포커스를 내부에 가두고 닫을 때 실행한 컨트롤로 포커스를 되돌린다.
- 좁은 창의 겹침 정보 패널은 갤러리의 키보드 포커스를 가리지 않는다.

- 정보 패널 토글 열기, 직접 닫기, 선택 해제 시 닫기

- 완전 중복 차단, 실패 표시, 재시도
- 내부 드래그와 외부 파일 드롭 상태의 분리

## 완료 조건

- 기존 자산 조회, 정렬, 선택, 분류, 좋아요, 휴지통, 감상, 드래그 복사 기능이 유지된다.
- 첫인상이 일반 웹 대시보드가 아니라 밀도 높은 미디어 관리 데스크톱 앱에 가깝다.
- 일반 상태의 상단 도구 모음에는 승인된 핵심 항목만 보인다.
- 자산을 선택해도 정보 패널은 자동으로 열리지 않으며 상단 도구 모음의 정보 토글로만 연다.
- 좁은 창에서도 사이드바, 갤러리, 정보 패널이 겹치거나 가로로 넘치지 않는다.
