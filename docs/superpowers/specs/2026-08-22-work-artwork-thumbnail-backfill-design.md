# WorkArtwork Thumbnail Backfill Design

**Date:** 2026-08-22

## Goal

기존 컬렉션 표지를 처음 표시할 때 원본 이미지 여러 장을 동시에 디코딩하며 생기는 렉을 제거한다. 이미 저장된 WorkArtwork 중 썸네일 파일이 없는 항목만 라이브러리 시작 후 백그라운드에서 한 번 생성한다.

## Existing behavior

- 새 WorkArtwork는 저장 시 360px 이내 WebP 썸네일을 원본과 함께 생성한다.
- 그리드는 원본 대신 `work-artwork-thumbnail` URL을 사용한다.
- 과거 데이터에 썸네일 파일이 없으면 해당 URL 요청을 처리하는 동안 원본을 읽고 썸네일을 즉석 생성한다.
- 기존 표지가 많은 컬렉션을 열면 여러 요청의 이미지 디코딩과 WebP 인코딩이 한꺼번에 발생한다.

## Design

라이브러리를 새로 연 직후 별도 백그라운드 스레드에서 누락 썸네일을 순차적으로 보완한다.

1. 데이터베이스에서 모든 WorkArtwork의 ID, 컬렉션 ID, 원본 상대 경로를 읽고 데이터베이스 잠금을 해제한다.
2. 각 항목의 예상 썸네일 파일이 이미 있으면 건너뛴다.
3. 없는 항목만 기존 썸네일 생성 규칙과 동일한 크기·WebP 형식으로 생성한다.
4. 임시 파일에 쓴 뒤 이름을 바꿔 불완전한 썸네일이 노출되지 않게 한다.
5. 한 항목이 손상됐거나 파일 쓰기에 실패해도 다음 항목을 계속 처리한다.
6. 생성 결과는 로컬 캐시 파일뿐이며 데이터베이스 스키마나 사용자 메타데이터는 변경하지 않는다.

파일 존재 여부가 완료 기록이다. 별도 마이그레이션 플래그, 설정 버튼, 진행 표시, 작업 큐는 추가하지 않는다. 앱을 다시 열 때 목록 확인은 반복되지만 이미 생성된 파일은 디코딩하지 않는다.

신규 WorkArtwork의 저장 시 썸네일 생성 동작은 그대로 유지한다.

## Concurrency and lifecycle

- 라이브러리 열기 응답은 백필 완료를 기다리지 않는다.
- 한 번의 백필은 단일 작업으로 순차 처리해 CPU·디스크 사용이 몰리지 않게 한다.
- 사용자가 다른 라이브러리로 전환해도 작업은 해당 `Library` 인스턴스와 루트만 사용한다.
- 화면 요청과 백필이 같은 썸네일을 동시에 만들더라도 기존 임시 파일·원자적 이름 변경 규칙으로 최종 파일 하나만 남긴다.

## Errors

백필은 캐시 최적화이므로 개별 실패를 사용자 작업 실패로 승격하지 않는다. 실패한 항목은 다음 앱 실행 또는 기존 요청 시 백필 경로에서 다시 시도할 수 있다. 비밀정보나 원본 바이트를 로그에 남기지 않는다.

## Verification

- 썸네일이 없는 기존 WorkArtwork만 생성되고 이미 있는 파일은 유지되는 집중 Rust 테스트를 추가한다.
- 손상된 원본 다음의 정상 항목도 생성되는지 확인한다.
- 라이브러리 열기 함수가 백필 완료를 기다리지 않는 구조인지 코드 경계로 확인한다.
- 변경 범위가 Rust 백엔드에 한정되면 프런트엔드 테스트와 프로덕션 빌드는 실행하지 않는다.
