# Lakomics 온라인 만화 카탈로그 설계

## 목표

VCK의 사용자 경험을 참고해 Lakomics 망가 탭에 다음 기능을 독립 구현한다.

- 사용자가 소유한 VCK 설치에서 `kdata.db`와 검색 보조 데이터를 한 번 가져온다.
- 가져온 카탈로그를 VCK와 독립적으로 증분 갱신한다.
- 로컬 만화와 분리된 온라인 카탈로그를 검색하고 최신순·조회수순·기간별 인기순으로 정렬한다.
- 작품을 내려받지 않고 기존 Lakomics 뷰어에서 바로 본다.
- 원격 썸네일을 캐시하고 작품별 마지막 열람 페이지를 복원한다.
- 수동 갱신과 기본 활성화된 1시간 자동 갱신을 제공한다.

VCK 또는 violet-web의 구현을 복사하거나 실행 시 의존하지 않는다. 배포본의 동작과 사용자가 제공한 데이터 형식만 참고해 Rust/Tauri와 기존 React 구조에 맞게 독립 구현한다.

## 범위

### 포함

- VCK 루트 폴더 가져오기
- 독립 카탈로그 저장소와 증분 갱신
- 한국어 태그 번역 및 자동완성
- 온라인 검색, 최신순, 조회수순, 일간·주간·월간 인기순
- Hitomi 우선, K-Hentai 대체 경로를 사용하는 바로 보기
- 원격 썸네일과 페이지 캐시
- 최근 열람과 마지막 페이지 저장
- 갱신 상태, 추가 작품 수, 마지막 성공 시각과 오류 표시

### 제외

- VCK 북마크·검색 기록·다운로드 기록 이전
- 전체 카탈로그를 ID 1부터 다시 만드는 백필 수집기
- violet-web 또는 별도 로컬 웹 서버 포함
- 대사 검색용 대용량 색인
- 날짜 분포 그래프와 고급 검색 문법 전체
- 이번 단계의 영구 다운로드 큐

영구 다운로드, 진행률, 실패 재시도와 중복 방지는 후속 Hitomi 다운로드 단계에서 이 설계의 작품 식별자와 페이지 해석 모듈을 재사용해 추가한다.

## 저장 구조

현재 라이브러리 폴더 안에 다음 경로를 둔다.

```text
<library>/
├─ library.sqlite
├─ catalogs/
│  ├─ kdata.db
│  ├─ tag-ko.json
│  └─ suggestions.json
└─ cache/
   └─ remote-manga/
      ├─ thumbnails/
      └─ pages/
```

`kdata.db`는 `library.sqlite`에 병합하지 않는다. 대규모 검색 색인의 읽기와 갱신을 본체 메타데이터 트랜잭션 및 잠금과 분리하기 위해 별도 SQLite 파일로 유지한다.

`library.sqlite`에는 카탈로그 자체가 아닌 다음 Lakomics 소유 상태만 저장한다.

- 카탈로그 설치 여부
- 자동 갱신 활성 여부와 간격
- 마지막 시도·성공 시각, 마지막 추가 건수와 오류
- 원격 작품별 최근 열람 시각과 마지막 페이지

새 마이그레이션은 `online_catalog_settings` 싱글톤 테이블과 `remote_reading_progress` 테이블을 추가한다. 설정을 기존 `library_settings`에 계속 열로 붙이는 대신 온라인 카탈로그 수명주기를 한곳에 모은다.

## 모듈과 인터페이스

### 아키텍처 결정: Chromium 전송 seam 선행

증분 갱신과 K-Hentai 바로 보기는 모두 일반 HTTP가 아닌 같은 출처의 Chromium 요청이 필요하다. 두 기능이 각각 WebView 수명주기, 타임아웃과 오류 변환을 구현하지 않도록 `catalog_transport`를 먼저 만든다. 이 모듈을 삭제하면 복잡성이 갱신과 갤러리 양쪽으로 되돌아가므로 독립 모듈로 둘 가치가 있다.

검토한 대안은 다음과 같다.

- 뷰어 전용 WebView를 먼저 만들면 화면은 빨리 나오지만 갱신 전송과 중복된다.
- 현재 웹사이트 창만 유지하면 구현은 작지만 자체 뷰어, 캐시와 열람 진행도를 제공할 수 없다.
- 공용 전송 seam을 먼저 만들면 초기 단계가 하나 늘지만 갱신과 내부 뷰어가 같은 검증된 요청 경로를 사용한다.

따라서 공용 전송 seam을 선택한다. 현재 `open_online_catalog_work`가 여는 웹사이트 창은 내부 뷰어가 완성될 때까지의 작동 가능한 임시 경로이며, 내부 뷰어 전환 후 제거한다.

### `online_catalog` Rust 모듈

카탈로그 저장과 검색을 숨기는 깊은 모듈이다. 호출자는 VCK 스키마나 SQL을 알지 않는다.

인터페이스:

- `import_vck_catalog(vck_root) -> CatalogStatus`
- `catalog_status() -> CatalogStatus`
- `search_online_catalog(query) -> CatalogSearchPage`
- `update_online_catalog() -> CatalogUpdateResult`

`CatalogSearchQuery`는 검색어, 페이지, 페이지 크기와 `latest | views | hot_day | hot_week | hot_month` 정렬만 받는다. 내부 구현은 VCK의 `Works`, `Tags`, `CrawlState` 스키마와 색인을 사용한다.

### `catalog_transport` Rust/Tauri 모듈

K-Hentai가 일반 HTTP 요청을 거부할 때도 갱신과 열람이 가능하도록 Chromium 문맥, 숨은 WebView 수명주기, 같은 출처 제한, 콜백 역직렬화와 타임아웃을 감추는 깊은 모듈이다.

인터페이스:

- `fetch_text(path) -> String`

경로는 모듈 내부에서 K-Hentai 원점의 절대 경로로 검증하며 외부 URL이나 임의 스크립트는 받지 않는다. 구현은 보이지 않는 Tauri WebView 하나를 재사용한다. 갱신 어댑터는 검색 경로를 만들어 JSON을 해석하고, 갤러리 어댑터는 작품 HTML의 인라인 갤러리 데이터만 해석한다. 이 두 어댑터는 WebView 생성, JavaScript 실행과 콜백 형식을 알지 않는다.

같은 경로의 동시 요청은 하나로 합치며 요청별 제한 시간은 60초다. 전송 결과는 성공 상태와 본문을 Rust에서 검증한 뒤 호출자에게 전달한다. Windows의 동기 명령 WebView 생성 교착 위험을 피하기 위해 이 인터페이스를 사용하는 Tauri 명령은 항상 비동기로 실행한다.

### `remote_gallery` Rust 모듈

원격 작품을 뷰어가 사용할 페이지 목록으로 바꾸는 모듈이다.

인터페이스:

- `resolve_remote_gallery(work_id) -> ResolvedGallery`

Hitomi 해석을 먼저 시도하고 실패하면 `catalog_transport`의 K-Hentai 해석을 시도한다. 성공 결과에는 제공자, 페이지 수와 Lakomics 미디어 프로토콜 URL 목록이 포함된다. 호출자는 제공자별 URL 규칙과 헤더를 알지 않는다.

K-Hentai 어댑터는 `fetch_text("/r/{work_id}")`의 HTML에서 `const gallery = {...}` 데이터만 추출한다. 페이지 HTML 자체나 사이트 스크립트는 Lakomics 본창에서 실행하지 않는다. 현재 별도 Chromium 창에서 사이트 HTML을 표시하는 임시 빠른 보기는 이 어댑터와 내부 뷰어가 연결되면 제거한다.

### 공용 페이지 뷰어

기존 `MangaViewer`의 화면과 조작을 `PageViewer`로 추출한다.

인터페이스:

- 제목
- 페이지 URL 목록
- 최초 페이지
- 페이지 변경 콜백
- 닫기 콜백

로컬 만화는 기존 `/manga-page/...` URL을 만드는 어댑터를 사용하고, 온라인 작품은 `remote_gallery` 결과를 사용한다. 로컬과 원격이라는 두 실제 어댑터가 생기므로 이 시점에만 공용 seam을 만든다.

## 가져오기 흐름

1. 온라인 카탈로그 빈 상태에서 `VCK 데이터 가져오기`를 누른다.
2. 폴더 선택기로 VCK 루트를 선택한다.
3. `data/kdata.db`와 태그 번역 번들의 존재를 확인한다.
4. rusqlite 백업 기능으로 `catalogs/kdata.db.importing`에 일관된 SQLite 스냅샷을 만든다.
5. 임시 DB에 `PRAGMA integrity_check`를 실행하고 필수 테이블 `Works`, `Tags`, `CrawlState` 및 한 개 이상의 작품을 확인한다.
6. VCK의 `tag-ko-*.js`에 들어 있는 JSON 객체를 데이터로 해석해 `tag-ko.json`으로 저장한다.
7. `suggestion-cache.json`은 구조를 검증해 `suggestions.json`으로 저장한다. 파일이 없거나 오래됐으면 가져온 DB에서 다시 집계한다.
8. 검증이 모두 끝난 뒤 임시 파일을 실제 카탈로그 경로로 원자적으로 교체한다.
9. 가져오기 상태를 `library.sqlite`에 기록하고 온라인 카탈로그 화면을 연다.

원본 VCK 파일은 읽기 전용으로 취급하며 수정하거나 삭제하지 않는다. 가져온 뒤 VCK 폴더가 없어도 모든 포함 기능이 작동한다.

## 증분 갱신 흐름

1. 수동 버튼 또는 1시간 타이머가 갱신을 요청한다.
2. 프로세스 전체 갱신 mutex를 획득한다. 이미 갱신 중이면 새 요청은 시작하지 않고 현재 상태를 반환한다.
3. `SELECT MAX(Id)`로 기존 최고 작품 ID를 구한다.
4. 최신 검색 페이지부터 내려가며 최고 ID보다 큰 작품만 추린다.
5. 페이지 하나의 작품 upsert와 기존 태그 교체를 한 트랜잭션으로 커밋한다.
6. 기존 최고 ID 이하에 도달하거나 마지막 페이지에 도달하면 끝낸다.
7. 추천 항목은 새 작품의 태그·유형·업로더만 반영해 다시 집계한다.
8. 마지막 성공 시각과 추가 건수를 저장하고 검색 캐시를 무효화한다.

자동 갱신은 라이브러리가 열려 있는 동안만 실행한다. 앱 시작 직후 카탈로그가 설치되어 있고 마지막 성공 이후 한 시간 이상 지났다면 한 번 실행한 뒤 1시간 간격 타이머를 유지한다.

## 검색과 자동완성

검색은 제목, 일본어 제목, 업로더와 태그를 지원한다. 기본 검색어는 제목 부분 일치이며 `namespace:value` 형태의 추천 항목을 선택하면 해당 태그 조건을 추가한다.

자동완성은 `suggestions.json`의 빈도순 항목과 `tag-ko.json`의 한국어 번역을 결합한다. 사용자가 한국어 번역으로 검색해도 원래 `namespace:value`로 정규화한다. 최초 범위는 한 검색창에서 추천 항목을 선택하는 방식까지이며, 논리 연산자와 괄호를 포함한 고급 문법은 제외한다.

인기 정렬은 `Views`와 `Posted`를 사용한다.

- `hot_day`: 최근 24시간 게시 작품 중 조회수순
- `hot_week`: 최근 7일 게시 작품 중 조회수순
- `hot_month`: 최근 30일 게시 작품 중 조회수순

## UI

망가 화면 상단바에 `로컬`과 `온라인 카탈로그` 전환을 둔다. 로컬 화면은 현재 동작을 유지한다.

온라인 카탈로그 화면은 다음 요소만 제공한다.

- 검색창과 자동완성
- 최신·조회수·일간·주간·월간 정렬
- 전체 결과 수
- 카드 크기 조절
- 카탈로그 상태, 마지막 성공 시각과 `지금 갱신`
- 작품 카드의 썸네일, 제목, 작가·시리즈, 페이지 수와 조회수

카드를 누르면 마지막 페이지부터 `PageViewer`를 연다. 페이지가 처음 해석되는 동안 로딩 상태를 표시한다. 뷰어에는 원격 제공자 이름을 작게 표시하되 Hitomi와 K-Hentai 선택을 사용자 설정으로 노출하지 않는다.

카탈로그가 없으면 가져오기 빈 상태를 표시한다. 설정 화면에는 카탈로그 위치, 자동 갱신 토글, 갱신 간격, 다시 가져오기와 캐시 비우기를 둔다. 기본 간격은 1시간이다.

## 원격 미디어와 캐시

프론트엔드는 외부 이미지 URL을 직접 요청하지 않는다. 기존 Lakomics 미디어 프로토콜에 다음 읽기 경로를 추가한다.

- `/remote-manga-thumbnail/{workId}`
- `/remote-manga-page/{provider}/{workId}/{pageIndex}`

프로토콜 처리기는 제공자별 필수 헤더를 붙여 이미지를 가져오고 성공 응답을 `cache/remote-manga/`에 저장한다. 캐시 키에는 제공자, 작품 ID, 페이지 번호와 원격 URL 식별값을 포함한다. 썸네일이나 페이지 요청 실패는 오류 응답으로 끝내며 검색 DB나 열람 기록을 손상시키지 않는다.

초기 버전은 캐시 용량 설정을 추가하지 않는다. `캐시 비우기`만 제공하고 실제 사용량이 문제가 될 때 용량 제한을 추가한다.

## 열람 기록

`remote_reading_progress`는 `(provider, work_id)`를 기본키로 사용하고 마지막 페이지, 전체 페이지 수, 마지막 열람 시각을 저장한다. 페이지 변경은 프론트엔드에서 짧게 debounce해 기록한다. 작품을 다시 열 때 저장 페이지가 현재 페이지 수 안에 있으면 복원하고, 범위를 벗어나면 1페이지에서 시작한다.

이번 범위에는 별도 기록 목록이나 북마크 화면을 만들지 않는다. 온라인 검색 카드에 `최근 읽음` 상태를 표시할 수 있는 데이터만 남긴다.

## 오류 처리와 복구

- 가져오기 실패: 임시 파일을 제거하고 기존 카탈로그를 보존한다.
- 스키마 불일치 또는 손상: 필요한 테이블이나 무결성 검사 실패 원인을 표시한다.
- 갱신 네트워크 실패: 요청을 최대 3회 지수 지연으로 재시도한 뒤 중단한다.
- 갱신 중단: 이미 커밋된 페이지는 유지하고 다음 갱신이 최고 ID부터 이어간다.
- 요청 제한: 재시도 후에도 계속되면 별도 상태로 기록하며 자동 갱신 타이머는 다음 주기에 다시 시도한다.
- 바로 보기: Hitomi 실패는 K-Hentai 대체 경로로 숨기고 두 경로가 모두 실패했을 때만 오류를 표시한다.
- 썸네일 실패: 카드 자리표시자를 사용하고 검색 결과 전체는 유지한다.
- 페이지 실패: 현재 페이지 오류를 표시하되 이전·다음 이동과 닫기는 유지한다.

## 테스트

실제 외부 사이트를 자동 테스트에서 호출하지 않는다. 작은 SQLite와 응답 fixture로 다음 위험만 검증한다.

### Rust

- 정상 VCK 카탈로그 가져오기와 원본 보존
- 손상 DB 및 필수 테이블 없는 DB 거부
- 임시 파일 검증 후 원자적 교체
- 증분 갱신의 추가, 중복 방지와 기존 ID 도달 시 종료
- 페이지 단위 커밋 후 실패 및 다음 실행 재개
- 검색과 최신·조회수·기간별 인기 정렬
- 한국어 번역 자동완성 정규화
- Hitomi 실패 시 K-Hentai 대체 경로
- 동시에 두 번 갱신하지 않는 mutex

### React

- 로컬·온라인 전환
- 카탈로그 없는 상태와 가져오기 동작
- 검색 결과·정렬·갱신 상태 표시
- 카드 선택 후 바로 보기
- 마지막 페이지 복원과 변경 저장
- 원격 페이지 실패 상태에서 뷰어 조작 유지

기존 로컬 망가 뷰어 회귀 테스트와 관련 컬렉션 테스트만 함께 실행한다. 전체 저장소 테스트나 실제 네트워크 통합 테스트는 요구하지 않는다.

## 구현 순서

1. 카탈로그 저장 구조, 가져오기와 상태
2. 읽기 전용 검색, 정렬과 자동완성
3. 망가 탭 온라인 카탈로그 UI와 임시 Chromium 빠른 보기
4. 갱신과 갤러리가 공유하는 `catalog_transport`
5. 증분 갱신 파서·저장과 수동·자동 갱신
6. Hitomi/K-Hentai 페이지 해석과 원격 미디어 프로토콜
7. 공용 `PageViewer`, 바로 보기와 열람 진행 저장
8. 임시 웹사이트 빠른 보기 제거
9. 후속 Hitomi 다운로드 기능에서 해석 모듈 재사용

각 단계는 이전 단계의 작은 인터페이스만 사용한다. VCK 런타임, Node.js, `better-sqlite3`, 별도 웹 서버는 추가하지 않는다.
