# Lakomics 사이드바 폴더 모양 설계

## 목표

기존 분류 폴더 트리를 Eagle과 유사한 밀도 높은 폴더 탐색 UI로 다듬는다. 사용자는 폴더별 아이콘과 색상을 지정하고, 계층 연결선으로 중첩 구조를 빠르게 파악할 수 있어야 한다. 폴더 행의 `…` 버튼은 제거하고 모든 폴더 작업은 우클릭 메뉴와 기존 키보드 명령을 통해 수행한다.

이 설계는 `2026-08-11-lakomics-sidebar-folder-ux-design.md`에서 확정한 생성, 이름 변경, 이동, 삭제 및 자산 드롭 규칙을 유지하면서 표현과 꾸미기만 확장한다. 선행 설계의 DB 마이그레이션 제외 범위는 이번 꾸미기 필드 두 개에 한해서만 대체한다.

## 범위

- `저장소`, `미분류`, `최근`, `즐겨찾기`, `유사 검토`, `망가` 빠른 보기는 유지한다.
- 빠른 보기 아래의 분류 트리만 새 폴더 디자인으로 변경한다.
- 트리 위에 `폴더 (N)` 제목을 표시한다. `N`은 전체 항목 수가 아니라 최상위 폴더 수다.
- 폴더별 아이콘과 색상은 해당 라이브러리에 영구 저장한다.
- 확장 프로그램 연동과 운영체제 파일 경로는 변경하지 않는다.

## 데이터 모델

`classification_entries`에 다음 nullable 열을 추가한다.

- `icon_key TEXT NULL`
- `color_key TEXT NULL`

값이 `NULL`이면 종류별 기본 아이콘과 중립색을 사용한다. `work`는 기존 작품용 책 아이콘을, 나머지는 폴더 아이콘을 기본값으로 쓴다. 기본값 초기화는 두 열을 다시 `NULL`로 저장한다.

아이콘과 색상은 임의 SVG, CSS 또는 색상 문자열이 아니라 앱이 허용한 키만 저장한다. Rust 라이브러리 모듈은 저장 전에 키를 검증하며 잘못된 값이면 기존 값을 변경하지 않고 명시적 오류를 반환한다.

분류 조회 결과의 `ClassificationEntry`에는 nullable `iconKey`와 `colorKey`가 포함된다. 꾸미기 갱신은 이름 변경과 분리된 단일 명령 `update_classification_appearance(id, iconKey, colorKey)`로 처리한다.

5. 책 (`BookOpenIcon`)
6. 별 (`StarIcon`)
7. 하트 (`HeartIcon`)
8. 인물 (`UserIcon`)
9. 그룹 (`UserGroupIcon`)
10. 학습 (`AcademicCapIcon`)
11. 업무 (`BriefcaseIcon`)
12. 집 (`HomeIcon`)

색상은 다크 UI에서 구분되는 12개 고정 팔레트를 제공한다. 키와 디자인 토큰 값은 빨강 `#ef6b73`, 주황 `#f28c52`, 호박 `#dba84b`, 노랑 `#c9b94d`, 연두 `#8fbd52`, 초록 `#58b67a`, 청록 `#47b6a7`, 하늘 `#4fabc9`, 파랑 `#5b8def`, 남색 `#7c7ee8`, 보라 `#aa75df`, 분홍 `#df6fa7`로 고정한다.

폴더 이름에는 색상을 적용하지 않고 아이콘과 해당 폴더에서 자식으로 내려가는 계층선에만 사용한다. 새 폴더와 새 하위 폴더는 부모 꾸미기를 상속하지 않고 기본값으로 시작한다.

## 트리 디자인

각 폴더 행은 펼침 화살표, 폴더 아이콘, 이름 순서로 표시한다. 자식이 없는 행도 화살표 자리를 확보해 모든 이름의 시작 위치가 정렬되게 한다. 행 높이와 간격은 현재보다 촘촘하게 조정하고, 긴 이름은 한 줄 말줄임표로 처리한다.

선택된 행만 둥근 배경으로 강조한다. 키보드 포커스, 유효한 드롭 대상, 유효하지 않은 드롭 대상 표시는 기존 의미를 유지하며 선택 배경과 계층선을 가리지 않아야 한다.

펼쳐진 부모의 자식 그룹에는 부모 색상을 낮은 불투명도로 적용한 세로선을 표시한다. 각 직접 자식에는 세로선에서 행으로 이어지는 ㄴ자 연결선을 표시하며 마지막 자식에서 세로선이 끝난다. 중첩 그룹은 각 단계의 CSS 사용자 정의 색상을 사용하므로 조상별 세로선이 나란히 이어진다.

폴더 행의 `…` 추가 작업 버튼과 관련 여백은 완전히 제거한다. 폴더 행의 좌클릭은 선택, 펼침 화살표는 펼치기/접기, 우클릭은 작업 메뉴라는 역할을 유지한다.

## 우클릭 메뉴와 꾸미기 창

폴더 우클릭 메뉴 순서는 다음과 같다.

1. 하위 폴더 만들기
2. 이름 변경
3. 아이콘 및 색상…
4. 폴더 이동
5. 삭제

기존 이동·삭제 제한과 비활성 설명은 유지한다. 빈 트리 영역의 우클릭 메뉴는 계속 `새 폴더`만 제공한다.

`아이콘 및 색상…`을 선택하면 공통 Dialog를 사용한 작은 꾸미기 창을 연다. 창에는 현재 모양 미리보기, 24개 아이콘 그리드, 12개 색상 그리드, `기본값으로 초기화`, `취소`, `저장`을 제공한다. 현재 값은 처음부터 선택되어 있고, 저장에 실패하면 창을 유지한 채 오류를 표시한다. 저장 성공 후 분류 목록을 다시 불러와 트리와 다른 소비자가 같은 값을 보게 한다.

키보드 사용자는 폴더 행에 포커스한 뒤 `Shift+F10` 또는 키보드 메뉴 키로 같은 우클릭 메뉴를 열 수 있어야 한다. 기존 `Ctrl+Shift+N`, `Alt+N`, `F2`, `Delete` 단축키도 유지한다.

## 오류와 안전성

- 마이그레이션은 nullable 열만 추가해 기존 라이브러리의 분류와 백업을 그대로 읽을 수 있게 한다.
- 허용되지 않은 아이콘이나 색상 키는 저장하지 않는다.
- 꾸미기 저장은 폴더 이름, 부모, 자산 연결을 변경하지 않는다.
- 폴더 삭제·이동·이름 변경 로직은 이번 작업에서 수정하지 않는다.
- 임의 색상 입력과 사용자 SVG 업로드는 스타일 깨짐, 가독성 저하 및 검증 부담을 피하기 위해 제공하지 않는다.

## 테스트와 검증

자동 테스트는 다음을 검증한다.

- 기존 DB 마이그레이션 후 기존 분류가 기본 모양으로 조회됨
- 허용된 아이콘·색상 저장과 재조회
- 잘못된 키 거부 및 기존 값 보존
- 기본값 초기화가 두 값을 `NULL`로 되돌림
- `ClassificationEntry`의 새 필드가 프런트엔드까지 전달됨
- 트리 제목이 최상위 폴더 수를 표시함
- 폴더 행에서 `…` 버튼이 사라지고 우클릭 메뉴가 열림
- 메뉴에 `아이콘 및 색상…`이 정해진 순서로 표시됨
- 꾸미기 창의 현재 값, 저장, 취소, 초기화 및 오류 유지
- 지정 아이콘과 색상이 아이콘 및 자식 계층선에만 적용됨
- 중첩 그룹의 세로선과 마지막 자식 연결선 표시
- 새 하위 폴더가 부모 모양을 상속하지 않음
- `Shift+F10` 또는 메뉴 키로 우클릭 메뉴 접근 가능
- 기존 생성, 이름 변경, 이동, 삭제, 드래그 및 트리 키보드 테스트가 계속 통과함

실제 Tauri 개발 창에서는 우클릭 메뉴 열기, 아이콘·색상 변경, 중첩선 표시, 앱 새로고침과 재시작 후 꾸미기 유지까지 확인한다.

## 범위 밖

- 사용자 SVG 또는 이미지 아이콘 업로드
- 임의 색상 선택기와 직접 HEX 입력
- 부모 꾸미기의 자동 상속
- 폴더별 글자색 또는 행 배경색 변경
- 아이콘·색상을 기준으로 한 정렬과 검색
- 확장 프로그램에서 폴더 꾸미기 편집
