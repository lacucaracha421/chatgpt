# Lakomics 컬렉션 설계

날짜: 2026-08-16 (재정의)

상태: 사용자 확인 완료

## 제품 경계

Lakomics의 컬렉션은 앨범이나 단순 자산 묶음이 아니다. 컬렉션은 게임·만화·영화 작품을 표지·타입별 상세 정보·대표 이미지로 모아 감상하는 단위다. 타입마다 보여주는 상세 정보가 다르며, 외부 서비스(SteamDB·IGDB·알라딘·MangaDex·TMDB)에서 가져온 메타데이터를 보존한다. 작품을 위한 별도 엔티티는 두지 않고 컬렉션 하나로 통합한다.

구버전 whatthe3는 컬렉션별 실제 폴더, `info.txt`, `covers/`, `artworks/`로 작품을 관리했다. 현재 Lakomics는 미디어 금고가 자산 파일을 소유하는 자산 중심 모델이므로, 레거시의 폴더 기반 자산 구조는 가져오지 않는다. 컬렉션은 기존 자산을 참조만 하고, 레거시 데이터는 별도 마이그레이션 도구로 나중에 옮긴다.

## 컬렉션 유형

세 가지만 지원한다.

- **게임**: 이름, 제작사, 외부 점수(Metacritic 등), 내 점수
- **만화**: 작가, 출간 연도
- **영화**: 이름, 감독, 개봉 연도

첫 버전에는 메타데이터를 직접 입력한다. 외부 API 연동은 그 다음 단계에서 붙인다. 스키마에는 외부 ID와 출처 자리를 미리 만들어두어 나중에 매끄럽게 연결한다.

## 데이터 모델

SQLite 스키마 버전을 올리고 `collections` 테이블에 평평한 정형 컬럼과 JSON 원본 컬럼을 함께 둔다.

정형 컬럼(정렬·필터·표시용):
- `type` — game, manga, movie
- `title` — 작품 이름 (1~120자, 대소문자 무시 중복 금지)
- `sort_title`, `sort_year` — 정렬용
- `cover_asset_id` — 대표 자산(기존 자산 참조, nullable)
- `author` — 만화/게임 작가·제작사
- `year` — 출간/개봉 연도
- `director` — 영화 감독
- `release_date` — 영화 개봉일
- `external_score` — 외부 점수(Metacritic 등)
- `my_score` — 내 점수
- `genres`, `overview` — 장르·개요
- `external_id` — 외부 서비스 ID
- `external_source` — steamdb, igdb, aladin, mangadex, tmdb
- `external_synced_at` — 마지막 동기화 시각
- `showcase` — 즐겨찾기 여부
- `created_at`, `updated_at`

JSON 컬럼(외부 API 원본 응답 보존):
- `external_metadata_json` — 외부 서비스가 반환한 전체 원본. 재동기화 손실 방지와 상세 표시용.

관계 테이블:
- `collection_assets` — 컬렉션과 자산의 다대다 관계(유일 키 보장). 기존 스키마 유지.

`collections` 테이블의 평평한 구조는 필드가 적어 한 테이블로 충분하다. 타입별 별도 테이블이나 key-value 테이블은 만들지 않는다.

## 데이터 규칙

- 이름은 앞뒤 공백을 제거하고 1~120자로 제한한다. 대소문자를 무시한 중복 이름은 거부한다.
- 같은 자산을 같은 컬렉션에 반복 추가해도 관계는 하나만 존재한다.
- 컬렉션 삭제는 관계와 컬렉션 정보만 지우며 자산은 지우지 않는다.
- 자산을 휴지통으로 보내면 관계는 유지해 복원 시 다시 보인다. 영구 삭제되면 외래 키 cascade로 관계가 지워지고 대표 자산은 `NULL`이 된다.
- 휴지통 또는 검토 대기 자산은 컬렉션 상세와 자산 수, 대표 이미지 후보에서 제외한다.
- 대표 자산은 반드시 그 컬렉션에 속한 정상 자산으로만 설정할 수 있다.
- 존재하지 않는 컬렉션·자산, 대표 자산이 소속되지 않은 경우는 명시적 도메인 오류로 반환한다.
- 유사 이미지 검토에서 기존 자산을 후보로 교체할 때 기존 컬렉션 소속도 후보 자산으로 이전한다.
- 외부 메타데이터를 가져온 뒤에도 사용자가 직접 고칠 수 있으며, 원본 응답은 동기화 시각과 함께 보존한다.

## 사용자 경험

### 진입

사이드바 빠른 보기 맨 끝(망가 뒤)에 `컬렉션` 버튼을 추가한다. 클릭하면 컬렉션 목록 뷰가 열린다.

### 컬렉션 목록 뷰

전용 `CollectionBrowser`가 표지 중심 그리드를 표시한다.

- 카드: 표지 이미지(둥글지 않게, radius 0~2px, shadow 없음), 이름, 자산 수(낮은 대조). 타입 배지.
- 표지가 없으면 일관된 빈 표지 상태(중성 블록, skeleton/애니메이션 없음).
- 카드 클릭 → 상세. 카드 우클릭 → 편집/삭제 메뉴.
- 새 컬렉션은 `ViewToolbar` 우측 `+` 버튼. 빈 그리드 영역 우클릭 → 새 컬렉션.
- 정렬: 고정(최근 편집 순). 정렬 옵션 없음.
- **타입 전환**: 상단에 게임·만화·영화 세그먼트(전체/게임/만화/영화)로 한 타입만 보거나 전체를 본다.
- 긴 이름과 설명은 말줄임.

### 쇼케이스

즐겨찾기한 컬렉션만 모아보는 표지 그리드 보기다. 타입 구분 없이 섞이며 자동 정렬된다. 수동 배치는 사용하지 않는다. 컬렉션 목록의 모드 전환(전체/쇼케이스)으로 단순화한다.

### 상세 뷰

기존 `AssetBrowser`, `AssetGallery`, `AssetViewer`, 선택 도구와 정보 패널을 재사용한다.

- 정렬, 선택, 스크롤, 뷰어가 기존 자산 브라우저와 동일.
- 컬렉션 상세 툴바: 컬렉션 이름만(부제/설명 안 붙임). 정상 자산 정확히 1개 선택 시 `대표 이미지로 지정` 버튼 노출. `이 컬렉션에서 제거` 배치 액션.
- 컬렉션 상세 빈 상태: "이 컬렉션에 자산이 없습니다. / 원하는 자산을 이 컬렉션에 추가하세요." (앨범과 동일 문구).
- 타입별 상세 정보는 인스펙터(정보 패널)의 `컬렉션 정보` 섹션에서 표시. 자산 메타데이터와 함께. 툴바나 상단 헤더엔 표시하지 않는다.

### 생성·편집

생성·편집은 `Dialog`에서 한다. 이름 + 설명 + 타입 선택. 앨범의 인라인 이름 편집과 달리 설명 필드(최대 2,000자)가 있어 모달이 맞다. 기존 `Dialog`, `TextField`, `Button`을 재사용한다.

### 자산 추가

인스펙터 `정리` 섹션에 컬렉션 체크박스 목록을 추가한다. 앨범 체크박스와 동일한 멤버십 UX. 여러 자산 선택 시 일괄 추가/제거. 사이드바로 자산을 드래그하는 방식은 첫 버전엔 뺀다.

### 삭제 확인

"컬렉션 '{이름}'을 삭제합니다. 속한 자산은 라이브러리에 보존됩니다." (앨범과 동일 패턴).

### 단축키

첫 버전엔 컬렉션 전용 단축키 없음. UI 버튼/우클릭 메뉴로 조작. 단축키가 필요해지면 컬렉션 뷰 포커스일 때만 동작하도록.

## 외부 메타데이터 연동 (2단계)

만화는 알라딘 API·MangaDex, 게임은 SteamDB/IGDB, 영화는 TMDB에서 정보를 가져온다. 연동은 Rust 백엔드(`library::collection_metadata_sync` 모듈)에서 처리한다. HTTP 호출, API 키 관리, 레이트 리밋, 재시도·에러 처리를 백엔드에서 통제한다. 프론트엔드는 표현만 담당.

이 연동은 첫 버전(UI + 수동 입력) 다음 단계에서 붙인다. 첫 버전 스키마에 외부 ID·출처·동기화 시각 자리를 미리 만들어둔다.

## 레거시 마이그레이션 (별도 작업)

레거시 `whatthe3` 컬렉션 폴더(`info.txt`, `covers/`, `artworks/`)를 새 모델로 옮기는 작업은 첫 버전에 포함하지 않는다. 사용자가 원할 때 실행하는 별도 변환 명령으로 나중에 제공한다. `info.txt`를 파싱해 메타데이터를 채우고, 이미지는 직접 수집 후 연결한다.

## 검증 전략

Rust 단위 테스트로 스키마 마이그레이션, CRUD, 타입별 메타데이터 검증, 쇼케이스 즐겨찾기, 중복 소속, 삭제·휴지통·영구 삭제 일관성, 컬렉션 범위 페이지 조회를 검증한다. React 테스트로 목록의 빈/오류/생성/수정/삭제 상태, 타입 전환, 쇼케이스, 상세 이동, 인스펙터 메타데이터 표시와 소속 반영을 검증한다. 마지막으로 전체 `npm run check`, Rust 전체 테스트와 Tauri production build를 실행한다.
