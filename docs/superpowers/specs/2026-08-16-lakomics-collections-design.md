# Lakomics Collections Design

## Product boundary

Lakomics의 컬렉션은 앨범을 다시 부르는 이름이 아니다. 앨범은 계층형 자산 목록이고, 컬렉션은 표지와 설명을 가진 독립적인 감상 단위다. 하나의 자산은 여러 컬렉션에 들어갈 수 있으며 파일과 자산 레코드는 복제하지 않는다.

구버전 `whatthe3`는 컬렉션별 실제 폴더, `info.txt`, 표지 폴더와 썸네일 파일을 스캔해 만화·게임·영화 등 여러 유형의 상세 뷰를 제공했다. 생성·수정·삭제, 대표 이미지 교체, 검색·정렬·필터, 즐겨찾기와 수동 순서가 사용자에게 보이던 핵심 흐름이었다. 반면 MangaDex·IGDB·TMDB 같은 유형별 외부 연동과 파일명 기반 선반 규칙은 현재 Lakomics 자산 모델과 맞지 않아 옮기지 않는다.

## Chosen architecture

SQLite schema version 10에 `collections`와 `collection_assets`를 추가한다. `collections`는 이름, 설명, 대표 자산, 생성·수정 시각을 저장하고 `collection_assets`는 컬렉션과 자산의 다대다 관계를 유일 키로 보장한다. 대표 자산은 반드시 그 컬렉션에 속한 정상 자산으로만 설정할 수 있다.

Rust의 `library::collection` 모듈이 CRUD, 소속 변경, 대표 자산 검증을 한곳에서 책임진다. 기존 `list_assets` 쿼리는 `collection_id` 범위를 하나 더 받아 현재 커서 페이지네이션과 썸네일·영상 처리를 그대로 사용한다. 컬렉션 목록은 정상 자산 수와 사용할 수 있는 대표 자산 ID를 한 번의 집계 쿼리로 반환해 N+1 조회를 피한다.

React에서는 `AssetView`에 컬렉션 목록과 컬렉션 상세를 추가한다. 목록은 전용 `CollectionBrowser`가 표지 중심의 조밀한 그리드로 표시하고, 상세는 기존 `AssetBrowser`, `AssetGallery`, `AssetViewer`, 선택 도구와 정보 패널을 재사용한다. 생성·편집·삭제에는 기존 `Dialog`, `TextField`, `Button`, `ContextMenu`를 사용한다.

## Data rules

- 이름은 앞뒤 공백을 제거하고 1~120자로 제한한다. 대소문자를 무시한 중복 이름은 거부한다.
- 설명은 공백만 입력하면 `NULL`, 최대 2,000자로 제한한다.
- 같은 자산을 같은 컬렉션에 반복 추가해도 관계는 하나만 존재한다.
- 컬렉션 삭제는 관계와 컬렉션 정보만 지우며 자산은 지우지 않는다.
- 자산을 휴지통으로 보내면 관계는 유지해 복원 시 다시 보인다. 영구 삭제되면 외래 키 cascade로 관계가 지워지고 대표 자산은 `NULL`이 된다.
- 휴지통 또는 검토 대기 자산은 컬렉션 상세와 자산 수, 대표 이미지 후보에서 제외한다.
- 존재하지 않는 컬렉션·자산, 대표 자산이 소속되지 않은 경우는 명시적 도메인 오류로 반환한다.
- 유사 이미지 검토에서 기존 자산을 후보로 교체할 때 기존 컬렉션 소속도 후보 자산으로 이전한다.

## User experience

사이드바의 빠른 보기에 `컬렉션`을 추가한다. 컬렉션 목록에서 새 컬렉션을 만들고 이름·설명을 수정하며, 우클릭 메뉴에서 편집하거나 삭제할 수 있다. 표지가 없으면 일관된 빈 표지 상태를 표시한다. 긴 이름과 설명은 레이아웃을 깨지 않도록 말줄임한다.

컬렉션 상세는 기존 자산 브라우저와 같은 정렬·선택·뷰어 경험을 제공한다. 선택 도구 및 정보 패널에서 여러 컬렉션 소속을 추가하거나 제거할 수 있다. 컬렉션 상세에서는 선택 자산을 현재 컬렉션에서 바로 제거할 수 있고, 단일 정상 이미지/GIF/영상 자산을 대표 이미지로 지정할 수 있다.

빠른 연속 조작은 작업 중 버튼 비활성화와 DB 유일 제약으로 중복 실행을 막는다. 로드·저장 실패는 기존 명령 오류 매핑과 자동 소멸 알림을 사용한다.

## Deliberate omissions

첫 구현에는 구버전의 유형별 외부 메타데이터, 컬렉션 즐겨찾기, 검색·유형 필터, 파일시스템 스캔, 컬렉션 수동 정렬을 넣지 않는다. 현재 요구의 CRUD·표지·설명·다대다 소속·상세 감상 흐름에는 필요하지 않고, 기존 Lakomics 분류·앨범·자산 정렬 기능과 중복되거나 별도 제품 결정을 요구하기 때문이다.

## Verification strategy

Rust 단위 테스트로 schema migration, CRUD, 검증, 중복 소속, 삭제·휴지통·영구 삭제 일관성과 컬렉션 범위 페이지 조회를 검증한다. React 테스트로 목록의 빈/오류/생성/수정/삭제 상태, 상세 이동, 선택 도구와 정보 패널의 소속 반영을 검증한다. 마지막으로 전체 `npm run check`, Rust 전체 테스트와 Tauri production build를 실행한다.
