# Lakomics 데스크톱 셸과 기본 사용성 설계

날짜: 2026-08-01  
상태: 사용자 승인

## 목적

현재 Lakomics의 로컬 이미지 수집 기반을 기능 시연 화면에서 실제로 시험 사용할 수 있는 데스크톱 작업 화면으로 발전시킨다. 사용자는 검색보다 왼쪽 분류 트리를 빠르게 탐색하고, 최대 5만 장의 이미지를 훑고, 좋아요를 표시하고, 정렬하고, 현재 분류에 파일을 끌어놓을 수 있어야 한다.

이번 단계는 이미지 관리의 기본 수직 흐름을 완성한다. 유사 이미지 비교창, 브라우저 확장프로그램, 영상 재생, 컬렉션 편집, 검색은 포함하지 않는다.

## 디자인 방향

선택한 방향은 **A안: 조용한 작업실**이다.

- Eagle의 왼쪽 계층 탐색, 상단 도구막대, 넓은 중앙 갤러리 구조를 참고한다.
- Hallmark의 절제된 단일 강조색, 4px 간격 체계, 분명한 글자 계층, 불필요한 카드 장식 배제 원칙을 따른다.
- 어두운 중립색을 기본으로 하고 주황색은 선택, 진행, 핵심 동작에만 사용한다.
- 오른쪽 검사창은 상시 표시하지 않는다. 상세 정보는 이미지를 열었을 때 표시해 갤러리 너비를 보존한다.
- 중앙 갤러리는 기존 justified-row와 가상화를 유지한다.

전체 shadcn과 Tailwind는 도입하지 않는다. 기존 React, CSS 토큰, 공통 UI를 확장한다. 아이콘은 `lucide-react` 하나로 통일하고 외부 글꼴, 장식 이미지, 모션 라이브러리는 추가하지 않는다. 글꼴은 Windows 기본 `Segoe UI`를 사용한다.

## 화면 구조

### 앱 셸

화면은 네 영역으로 구성한다.

1. 왼쪽 분류 사이드바
2. 상단 현재 위치와 도구막대
3. 중앙 이미지 갤러리
4. 하단 상태막대

앱 이름과 라이브러리 경로는 큰 제목으로 공간을 차지하지 않는다. 라이브러리 이름은 사이드바 위쪽에 작게 표시하고, 전체 경로는 툴팁 또는 설정 화면에서 확인한다.

### 분류 사이드바

- `게임 → 블루 아카이브 → 캐릭터`와 같은 계층을 접고 펼친다.
- 각 행은 이름, 펼침 표시, 선택 상태를 한 줄에 보여준다.
- 상단 `+` 버튼은 현재 선택에 맞는 하위 분류를 추가한다.
- 분류 행의 우클릭과 `···` 버튼은 같은 공통 메뉴를 연다.
- 메뉴에는 이름 변경, 이동, 삭제를 표시한다.
- `좋아요`와 `최근 추가`는 분류가 아닌 빠른 보기 항목이다.
- 사이드바 너비와 펼침 상태는 로컬 UI 환경설정으로 저장한다.

### 도구막대

왼쪽에는 현재 위치를 `게임 / 블루 아카이브`처럼 표시한다. 오른쪽에는 다음 컨트롤을 둔다.

- 정렬: 최신순, 오래된순, 좋아요순, 랜덤
- 범위: 하위 분류 포함 또는 현재 항목만
- 메타데이터 표시 켜기/끄기
- 선택한 이미지의 좋아요 켜기/끄기

검색 입력창은 만들지 않는다.

### 갤러리와 선택

- 기존 가상화된 justified-row 배치를 유지한다.
- 썸네일 한 번 클릭은 이미지 하나를 선택한다.
- 썸네일 두 번 클릭 또는 선택 후 Enter는 상세창을 연다.
- 선택한 썸네일은 얇은 주황색 테두리와 명확한 접근성 상태로 표시한다.
- 빈 공간을 클릭하면 선택을 해제한다.
- 메타데이터 표시가 켜져 있으면 썸네일 위에 출처의 짧은 호스트명과 가져온 날짜를 낮은 대비로 표시한다.
- 메타데이터 표시는 기본값이 켜짐이며 사용자의 마지막 선택을 저장한다.

이번 단계에서 다중 선택과 일괄 작업은 만들지 않는다.

### 상세창

- 원본 비율을 유지한 큰 이미지
- 원본 파일명
- 출처 URL
- 가져온 날짜
- 좋아요 상태
- 연결된 분류

기존 분류 편집 기능을 유지한다. Escape로 닫고, 저장 중에는 중복 제출을 막으며, 다른 이미지로 전환되거나 닫힌 뒤 도착한 비동기 응답은 무시한다.

### 상태막대와 드롭

- 현재 목록의 이미지 수 또는 현재까지 불러온 수
- 선택 상태
- 드롭 처리 진행률
- 기본 안내 문구

파일 드롭은 현재 선택한 실제 분류에 저장한다. `좋아요` 또는 `최근 추가` 빠른 보기에서는 분류가 없으므로 드롭을 받지 않고 분류를 선택하라는 안내를 표시한다. 기존 FIFO 드롭 처리, 완전 중복 차단, 원본 보존 규칙을 바꾸지 않는다.

## 데이터와 조회 계약

### 보기 상태

프론트엔드는 보기 대상을 다음 합 타입으로 관리한다.

- 실제 분류 보기: 분류 ID와 `directOnly`
- 좋아요 보기
- 최근 추가 보기

목록 요청은 보기 대상, 정렬, 커서, 페이지 크기를 명시한다. 전체 이미지 목록을 프론트엔드로 한 번에 가져오지 않는다.

### 좋아요

초기 스키마에 이미 존재하는 `assets.favorite` 필드를 사용한다. 기본값은 거짓이며 별도 스키마 마이그레이션은 추가하지 않는다.

- 선택된 이미지 하나의 좋아요를 켜거나 끈다.
- `좋아요` 빠른 보기는 좋아요가 켜진 이미지만 조회한다.
- 좋아요 변경 후 현재 목록의 정렬 또는 필터 결과가 달라지면 첫 페이지를 안전하게 다시 조회한다.

### 정렬

정렬의 동률 해소 기준까지 고정해 페이지 누락과 중복을 막는다.

- 최신순: 가져온 날짜 내림차순, ID 내림차순
- 오래된순: 가져온 날짜 오름차순, ID 오름차순
- 좋아요순: 좋아요 먼저, 그 안에서 최신순
- 랜덤: 콘텐츠 해시의 균등 분포를 셔플 키로 사용하고 화면 세션의 피벗을 기준으로 한 번 순환시킨다.

랜덤 피벗은 사용자가 랜덤 정렬을 선택하거나 다시 섞을 때 한 번 생성한다. 피벗이 유지되는 동안 페이지 순서는 안정적이다. 랜덤 정렬 때문에 전체 행을 프론트엔드에서 섞거나 데이터베이스를 매번 갱신하지 않는다.

커서는 정렬별 다음 행을 고유하게 식별하는 불투명 값이다. 프론트엔드는 커서 내부 구조에 의존하지 않는다.

### UI 환경설정

다음 값만 프론트엔드 로컬 저장소에 보관한다.

- 메타데이터 표시 여부
- 사이드바 너비
- 펼친 분류 ID
- 마지막 정렬

분류, 좋아요, 이미지 메타데이터는 SQLite가 유일한 영구 자료원이다.

## 모듈 경계

### `app`

현재 라이브러리, 보기 대상, 선택 상태를 조립한다. 데이터베이스, 파일, 갤러리 배치 알고리즘을 직접 처리하지 않는다.

### `layout`

앱 셸, 도구막대, 상태막대와 각 영역 사이의 배치만 소유한다.

### `classification`

분류 트리, 펼침 상태, 생성·이름 변경·이동·삭제 메뉴를 소유한다. 자산 조회를 직접 수행하지 않는다.

### `assets`

목록 조회, 커서 페이지 이동, 정렬, 단일 선택, 좋아요, 상세창을 소유한다. 분류 저장 규칙이나 SQL을 직접 알지 않는다.

### `ingestion`

Tauri 파일 드롭 구독, FIFO 처리, 진행 상태와 결과 변환을 계속 소유한다.

### `shared/ui`

버튼, 텍스트 입력, 선택 컨트롤, 토글, 메뉴, 다이얼로그, 토스트, 스켈레톤, 빈 상태의 공통 인터페이스를 소유한다. 우클릭과 `···`는 같은 `Menu` 항목 모델과 포커스 처리를 사용한다.

### `styles`

색상, 4px 간격 단계, 글자 크기, 모서리, 테두리, 포커스 표시, 영역 크기를 의미 기반 토큰으로 정의한다. 기능 코드에 사용자 변경 가능 값이나 반복되는 시각 상수를 하드코딩하지 않는다.

Rust 라이브러리 모듈은 SQLite, 마이그레이션, 정렬 쿼리, 좋아요 저장을 감춘다. Tauri 명령은 작은 입출력 인터페이스만 노출한다.

## 화면 상태와 오류

- 최초 로딩은 갤러리 크기를 유지하는 스켈레톤으로 표시한다.
- 빈 목록은 공통 빈 상태와 드롭 안내를 표시한다.
- 다음 페이지 실패는 이미 보이는 목록을 유지하고 다시 시도 동작을 제공한다.
- 첫 페이지 실패는 오류와 다시 시도를 표시한다.
- 저장 성공, 완전 중복, 파일별 실패는 공통 토스트를 사용한다.
- 분류 또는 정렬 변경으로 이전 요청이 늦게 도착하면 세대 번호로 무시한다.
- 현재 목록에서 선택한 이미지가 사라지면 선택을 해제한다.
- 드롭 중에는 하단 상태막대에 `5개 중 2번째 저장 중`처럼 표시한다.

## 키보드와 접근성

- 모든 버튼과 메뉴는 키보드로 접근할 수 있다.
- 메뉴는 위·아래 방향키, Enter, Escape를 지원하고 닫힐 때 원래 트리거로 포커스를 돌린다.
- 선택한 썸네일은 색상뿐 아니라 `aria-selected`로도 표시한다.
- Enter는 선택한 이미지의 상세창을 연다.
- 다이얼로그는 제목, 초기 포커스, Escape 닫기, 포커스 복귀를 제공한다.
- 아이콘 단독 버튼은 접근 가능한 이름과 툴팁을 가진다.

## 성능 기준

- 5만 장 라이브러리를 전제로 페이지 크기는 기존 100개를 유지한다.
- DOM에는 가상화 범위의 행만 렌더링한다.
- 분류, 정렬, 좋아요 변경 시 필요한 페이지 요청만 다시 수행한다.
- 썸네일과 원본은 기존 안전한 미디어 프로토콜을 사용한다.
- 메타데이터 표시를 꺼도 DB 재조회는 하지 않고 썸네일 오버레이만 숨긴다.
- 정렬 변경이나 이미지 추가 때 전체 이미지의 배치 정보를 미리 계산하지 않는다.

## 테스트와 완료 조건

### Rust

- 초기 스키마의 기존 좋아요 필드 사용과 기존 라이브러리 호환
- 좋아요 켜기·끄기와 좋아요 전용 조회
- 최신순, 오래된순, 좋아요순의 동률 처리
- 랜덤 피벗을 유지한 안정적인 다중 페이지 조회
- 분류 하위 포함과 `directOnly` 조합

### React

- 빠른 보기와 실제 분류 전환
- 정렬과 토글의 요청 계약
- 단일 클릭 선택, 더블클릭과 Enter 상세 열기
- 좋아요 변경과 필요한 경우의 목록 갱신
- 우클릭과 `···`가 같은 메뉴를 열고 같은 동작을 수행
- 로딩, 빈 상태, 첫 페이지 오류, 다음 페이지 오류
- 늦은 요청과 닫힌 상세창의 응답 무시
- 환경설정 저장과 잘못된 저장값의 안전한 기본값 처리

### Playwright와 Tauri

- 일반 데스크톱 크기와 좁은 창에서 영역이 겹치지 않음
- 사이드바, 도구막대, 갤러리, 상세창의 핵심 흐름
- 키보드 포커스와 Escape
- 실제 Windows 탐색기에서 Tauri 창으로 PNG/JPEG/GIF 드롭
- 드롭 결과, 원본 보존, 완전 중복 차단

자동화할 수 없는 실제 OS 드롭은 자동 테스트 통과로 대신했다고 주장하지 않는다. 실행 환경에서 수동 확인이 불가능하면 정확한 미확인 항목과 자동화된 대체 증거를 최종 보고에 남긴다.

## 작업 원칙

- 구현 서브에이전트는 `gpt-5.6-terra`, high로 명시한다.
- 서브에이전트 지시는 영어만 사용한다.
- 구현 에이전트는 한 번에 하나만 공유 작업 폴더를 수정한다.
- 각 작업 지시에는 역할, 수정 허용 파일, 수정 금지 파일, 인터페이스, 테스트, 보고서 경로를 명시한다.
- 구현자와 다른 새 에이전트가 작업별 명세·품질 검토를 수행한다.
- 하드코딩, 공통 UI, 모듈 설계는 `docs/agents/implementation.md`를 따른다.
