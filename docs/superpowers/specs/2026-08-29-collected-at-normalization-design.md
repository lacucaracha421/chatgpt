# `collected_at` UTC 정규화 설계

## 목적

RFC 3339 오프셋 원문을 SQLite `TEXT`에 그대로 저장해 실제 시각과 문자열 정렬이 달라지는 문제를 없앤다. 자산의 시간순 정렬, 날짜 버킷, 양방향 커서 페이지네이션이 같은 시간축을 사용해야 한다.

## 저장 형식

- 모든 `assets.collected_at` 값은 UTC 밀리초 형식인 `YYYY-MM-DDTHH:MM:SS.sssZ`로 저장한다.
- 수집 요청에 값이 있으면 RFC 3339로 파싱한 뒤 UTC로 변환한다.
- 값이 없으면 현재 UTC 시각을 같은 형식으로 생성한다.
- 파싱할 수 없는 값은 기존과 같이 `InvalidCollectedAt` 오류로 거부한다.

## 새 수집과 중복 갱신

`Library::ingest_media` 진입점에서 값을 한 번 정규화해 요청에 다시 넣는다. 이미지, 비디오, 완전 중복 메타데이터 갱신이 모두 이 값을 공유하며, 각 경로에 별도 변환 로직을 두지 않는다.

## 기존 데이터 마이그레이션

스키마 버전을 26으로 올리고 `0026_collected_at_utc.sql`을 추가한다. 마이그레이션은 SQLite 날짜 함수를 이용해 기존 RFC 3339 값을 UTC 밀리초 문자열로 갱신한다. 기존 인덱스 구조는 유지하며, 이후 조회는 현재의 `TEXT` 비교와 커서를 그대로 사용한다.

마이그레이션은 기존 라이브러리 개방 시 사전 백업 뒤 트랜잭션 안에서 실행되는 현재 절차를 따른다. 이번 개발·검증에서는 운영 라이브러리를 열거나 변경하지 않고 임시 라이브러리만 사용한다.

## 오류와 호환성

- 과거 앱이 저장한 값은 수집 단계에서 RFC 3339 검증을 통과했으므로 정상 변환 대상으로 본다.
- 예상 밖의 변환 불가 값은 원문을 임의로 지우지 않는다. 마이그레이션 SQL은 변환 결과가 유효한 행만 갱신한다.
- API 응답의 `collected_at` 필드와 프런트엔드 자료형은 바꾸지 않는다.

## 검증

1. 오프셋 입력이 UTC 밀리초 문자열로 저장되는 실패 테스트를 먼저 만든다.
2. 이미지와 완전 중복 메타데이터 갱신이 같은 정규화 값을 쓰는지 확인한다.
3. v25 데이터의 서로 다른 오프셋 값이 v26 마이그레이션 후 실제 시간순으로 정렬되는지 확인한다.
4. 관련 Rust 테스트 후 전체 `cargo test`와 프런트 `npm test`를 실행해 기존 미완성 변경의 상태까지 보고한다.
