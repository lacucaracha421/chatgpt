# Lakomics Edge 방사형 X 수집 설계

## 목적

Windows PC의 Microsoft Edge에서 X 이미지를 살짝 끌어 방사형 분류 메뉴를 열고, 마우스 버튼을 누른 채 계층을 탐색한 다음 원하는 분류 위에서 놓아 Lakomics 미디어 금고로 바로 수집한다.

참고 구현은 `C:\Users\namwoojun\Desktop\x_radial_touch_v1.6.user.js`다. 이 파일에서 X 이미지 탐색, 원본 URL 판별, SVG 방사형 메뉴 렌더링의 검증된 동작만 추출한다. Tampermonkey 저장소, 브라우저 직접 다운로드, 메타데이터 기록·백업, 터치 지원과 단일 파일 구조는 가져오지 않는다.

## 기존 결정과의 관계

이 설계는 다음 결정을 그대로 따른다.

- Chromium 확장 프로그램을 주 수집 경로로 사용한다.
- 도넛 UX는 유지하되 확장 프로그램은 작은 인터페이스로 새로 구성한다.
- 확장 프로그램과 앱은 인증된 `127.0.0.1` HTTP로 연결한다.
- X에서 사용자가 직접 끈 이미지 한 장만 수집한다.
- 분류 트리, 중복 판단과 파일 저장은 Lakomics 앱이 소유한다.
- 태그 이름이나 상위 분류 이름으로 앱 동작을 결정하지 않는다.

## 범위

### 포함

- Windows용 Microsoft Edge Manifest V3 확장 프로그램
- X와 Twitter 도메인의 이미지 한 장 수집
- 왼쪽 마우스 연속 드래그 기반 방사형 분류 선택
- 깊이 제한 없는 기존 Lakomics 분류 트리 탐색
- 확장 프로그램 설정의 WYSIWYG 도넛 슬롯 편집
- 설치별 인증 키를 사용하는 로컬 HTTP 인터페이스
- 앱이 수행하는 원본 이미지 다운로드, 중복 처리와 분류 연결
- 신규 수집, 완전 중복, 유사 이미지 검토 결과 표시

### 제외

- 터치와 모바일 브라우저
- X 게시물의 모든 이미지 일괄 저장
- 영상, GIF 전용 주소 탐색, Pixiv와 일반 사이트 어댑터
- 브라우저 다운로드 폴더 경유
- 앱이 꺼졌을 때의 오프라인 대기열
- AI 태깅, 자동 태그 추천, 사용 빈도 기반 슬롯 자동 재배치
- 확장 프로그램이 소유하는 별도 태그 데이터베이스

## 사용자 흐름

1. 사용자가 X 이미지에서 왼쪽 버튼을 누른다.
2. 포인터가 시작점에서 12px 미만으로 움직이면 아무것도 가로채지 않는다. 일반 클릭은 X의 원래 동작을 유지한다.
3. 콘텐츠 스크립트는 수집 가능한 X 이미지의 브라우저 기본 `dragstart`만 막는다. 이동 거리가 12px를 넘으면 시작점을 중심으로 도넛을 표시한다. 일반 클릭은 계속 X가 처리한다.
4. 사용자는 버튼을 계속 누른 채 원하는 분류 섹터로 이동한다.
5. 자식이 있는 섹터에 300ms 머물면 그 자식들을 보여주는 다음 도넛으로 전환한다.
6. 300ms 전에 섹터에서 놓으면 자식 유무와 관계없이 그 분류를 최종 선택한다.
7. 하위 도넛의 중앙에서 놓으면 현재 상위 분류를 최종 선택한다.
8. 최종 선택 시 확장 프로그램이 원본 이미지 URL, X 게시물 URL과 분류 ID를 Lakomics에 전달한다.
9. 앱이 수집을 끝내면 이미지 근처 상태 표시로 결과를 알린다.

도넛 밖에서 놓기, `Esc`, `pointercancel`, 창 포커스 이탈은 아무 요청도 만들지 않고 취소한다.

## 방사형 메뉴

### 항목 수

- 형제 항목 1~6개: 6개의 고정 슬롯을 사용한다.
- 형제 항목 7~12개: 12개의 고정 슬롯을 사용한다.
- 13개 이상: 페이지마다 최대 12개를 표시한다.
- 이전·다음 페이지 영역은 도넛 좌우 바깥에 두어 분류 슬롯을 차지하지 않는다. 포인터가 해당 영역에 300ms 머물면 페이지가 바뀐다.
- 하위 단계에서는 도넛 바깥에 한 단계 위로 돌아가는 영역을 표시하며, 이 영역도 300ms 머물러 작동한다.

빈 슬롯은 재분배하지 않는다. 같은 분류는 항상 같은 방향에 남아 손의 위치 기억을 유지한다.

### 계층 탐색

도넛 렌더러는 1층·2층을 별도 구현하지 않는다. 현재 부모 ID를 입력받아 직계 자식 한 단계만 그리는 동일한 렌더러를 반복 사용한다. 루트 화면은 부모 ID 대신 확장 프로그램 내부의 루트 식별자를 사용한다.

각 단계는 다음 정보를 가진다.

- 현재 경로의 분류 ID 목록
- 현재 부모 ID 또는 루트
- 현재 페이지
- 강조된 슬롯
- 하위 단계 진입 타이머

### 슬롯 편집

분류의 이름, 종류와 부모 관계는 앱에서 조회한다. 확장 프로그램은 화면 배치만 `chrome.storage.local`에 저장한다.

배치 키는 부모 분류 ID이며 값은 페이지별 분류 ID 배열이다. 최상위 항목은 예약된 루트 키 아래에 저장한다. 분류가 이름을 바꿔도 ID가 같으면 위치가 유지된다.

분류 트리를 새로 받았을 때 다음처럼 조정한다.

- 삭제된 분류 ID는 배치에서 제거한다.
- 다른 부모로 이동한 분류 ID는 이전 부모 배치에서 제거한다.
- 새 항목과 아직 배치되지 않은 항목은 해당 부모의 첫 빈 슬롯에 넣는다.
- 빈 슬롯이 없으면 마지막 페이지 뒤에 추가한다.

설정 화면은 참고 userscript의 WYSIWYG 편집기를 축소해 현재 도넛과 같은 위치에서 슬롯을 선택·교체·비우게 한다. 태그 생성, 이름 변경과 계층 이동은 앱에서만 한다.

## 확장 프로그램 구조

### X 콘텐츠 스크립트

다음 책임만 가진다.

- X의 동적 DOM에서 수집 가능한 이미지 감지
- 사용자가 실제로 끈 이미지 한 장 식별
- X 썸네일 URL을 원본 `pbs.twimg.com` 이미지 URL로 정규화
- 해당 이미지의 X 게시물 URL 추출
- 포인터 제스처 상태 관리
- 방사형 메뉴와 결과 상태 표시
- 서비스 워커에 분류 조회와 수집 요청 전달

X DOM 변경에 대응하는 사이트별 선택자와 URL 규칙은 이 어댑터 안에만 둔다.

### 백그라운드 서비스 워커

다음 책임을 가진다.

- 설치별 인증 키 보관
- Lakomics 로컬 API 호출
- 마지막으로 성공한 분류 트리의 짧은 메모리 캐시
- `chrome.storage.local`의 슬롯 배치 읽기·쓰기
- 콘텐츠 스크립트와 설정 화면 사이의 메시지 중계

분류 목록은 서비스 워커가 시작됐을 때 또는 캐시가 없거나 마지막 조회 후 30초가 지났을 때 다시 조회한다. 앱이 꺼져 있으면 오래된 목록으로 수집을 시도하지 않고 앱 실행 안내를 반환한다.

### 설정 화면

다음 항목만 제공한다.

- Lakomics 연결 상태
- 인증 키 입력과 저장
- 분류 목록 새로고침
- WYSIWYG 슬롯 편집
- 슬롯 배치를 기본 자동 배치로 되돌리기

## Lakomics 로컬 HTTP 인터페이스

서버는 앱이 실행 중일 때만 `127.0.0.1`에 바인딩한다. 외부 인터페이스에 바인딩하지 않는다. 모든 기능 요청은 설치별 Bearer 인증 키를 요구한다.

### 분류 조회

`GET /v1/classifications`

```json
{
  "entries": [
    {
      "id": "tag-id",
      "kind": "tag",
      "name": "시로코",
      "parentId": "work-id"
    }
  ]
}
```

응답은 기존 `ClassificationEntry` 계약을 그대로 직렬화한다. 도넛 전용 이름이나 순서 필드는 앱 데이터 모델에 추가하지 않는다.

### X 이미지 수집

`POST /v1/ingestions`

```json
{
  "source": "x",
  "mediaUrl": "https://pbs.twimg.com/media/example.jpg?format=jpg&name=orig",
  "sourceUrl": "https://x.com/example/status/123/photo/1",
  "classificationId": "tag-id"
}
```

응답 상태는 다음 네 가지다.

- `added`: 새 자산 수집 완료
- `duplicate_tagged`: 기존 자산에 요청한 분류 추가
- `duplicate_unchanged`: 파일과 분류 연결이 모두 이미 존재
- `review_pending`: 유사 이미지 검토 대기

응답에는 결과 확인에 필요한 자산 ID 또는 검토 ID만 함께 보낸다. 확장 프로그램은 라이브러리 내부 경로나 파일명을 받지 않는다.

## 인증과 요청 검증

- 인증 키는 앱 설치 단위로 생성하며 라이브러리 데이터와 분리해 보관한다.
- 사용자는 Lakomics 설정에서 키를 복사해 확장 프로그램 설정에 한 번 입력한다.
- 확장 프로그램은 키를 `chrome.storage.local`에 저장하고 페이지 콘텐츠에는 노출하지 않는다.
- 서비스 워커만 인증 헤더를 만들며 콘텐츠 스크립트는 키를 직접 받지 않는다.
- `mediaUrl`은 `https`와 `pbs.twimg.com` 호스트만 허용한다.
- `sourceUrl`은 `https`와 `x.com` 또는 `twitter.com` 호스트만 허용한다.
- 요청한 분류 ID가 현재 라이브러리에 존재하는지 다운로드 전에 검증한다.
- HTTP 본문의 크기를 제한하고 알 수 없는 필드는 동작에 사용하지 않는다.

브라우저 페이지에서 로컬 API를 직접 호출하지 못하도록 콘텐츠 스크립트는 서비스 워커 메시지만 사용한다. 확장 프로그램은 공개 manifest key로 설치 ID를 안정적으로 유지하고, 로컬 서버는 그 ID의 `chrome-extension://` Origin만 허용한다. 비밀 인증 키는 manifest에 넣지 않는다.

## 원격 이미지 수집

HTTP 어댑터는 원격 URL을 기존 수집 모듈이 소유하는 스테이징 경로로 내려받는다.

1. URL과 분류 ID를 검증한다.
2. 제한된 크기로 이미지를 스테이징 파일에 스트리밍한다.
3. 서버의 `Content-Type`과 파일 확장자를 신뢰하지 않고 기존 이미지 검사로 실제 형식과 크기를 판별한다.
4. 기존 콘텐츠 해시, 유사 이미지 검사, 금고 설치와 썸네일 생성을 사용한다.
5. 성공 또는 검토 대기 결과를 반환한다.
6. 어느 단계에서든 실패하면 이 요청이 만든 스테이징 파일만 제거한다.

기존 파일·폴더 끌어놓기의 수집 계약은 바꾸지 않는다.

## 중복 정책

새 자산이면 선택한 최종 분류 ID 하나를 직접 연결한다. 상위 분류 소속은 조회 시 계층 규칙으로 계산하며 상위 ID를 중복 저장하지 않는다.

완전 중복이면 새 파일이나 새 자산을 만들지 않는다. HTTP 수집 어댑터가 기존 자산에 요청 분류가 있는지 확인하고 다음처럼 처리한다.

- 분류가 없으면 기존 `patch_asset_classifications` 경로로 추가하고 `duplicate_tagged`를 반환한다.
- 이미 있으면 변경 없이 `duplicate_unchanged`를 반환한다.

이 동작은 확장 프로그램의 HTTP 수집에만 적용한다. 현재 파일 끌어놓기에서 완전 중복이 기존 분류를 유지하는 정책은 변경하지 않는다.

## 사용자 피드백과 오류 처리

상태 표시는 사용자가 끈 이미지 근처에 작게 나타나며 X의 레이아웃을 밀지 않는 오버레이다.

- 요청 중: `Lakomics로 수집 중`
- 신규 완료: `수집 완료`
- 중복 분류 추가: `기존 자산에 분류 추가`
- 중복 무변경: `이미 저장됨`
- 유사 이미지: `유사 이미지 검토 대기`
- 앱 미실행: `Lakomics를 실행해주세요`
- 인증 실패: `확장 프로그램 설정에서 연결 키를 확인해주세요`
- 분류 불일치: 분류를 새로고침하고 다시 선택하도록 안내
- 다운로드 실패: 오류와 재시도 동작 제공

재시도는 같은 수집 요청을 다시 보낸다. 콘텐츠 해시 중복 처리와 분류 존재 확인 때문에 반복 요청은 새 자산을 중복 생성하지 않는다.

## 테스트

### 확장 프로그램 자동 검사

- 12px 미만 이동이 일반 클릭을 가로채지 않는다.
- 12px 이상 이동에서만 도넛이 열린다.
- 섹터 진입·이탈 시 300ms 타이머가 올바르게 시작·취소된다.
- 타이머 전에 놓으면 상위 분류가 선택된다.
- 타이머가 끝나면 하위 단계로 전환된다.
- 도넛 밖 놓기, `Esc`, 포인터 취소와 포커스 이탈이 요청 없이 종료된다.
- 6슬롯, 12슬롯과 다중 페이지 배치가 안정적이다.
- 분류 삭제·이동·추가 시 슬롯 배치가 정리된다.
- X 이미지와 게시물 URL이 올바르게 정규화된다.

가능한 순수 로직은 추가 프레임워크 없이 Node의 기본 테스트 러너로 검사한다. 실제 DOM 연결은 최소한의 Edge 수동 인수 검사로 보완한다.

### Rust 자동 검사

- 인증 키 누락과 불일치 거부
- 루프백 외부 바인딩 방지
- 허용되지 않은 스킴과 호스트 거부
- 존재하지 않는 분류 ID를 다운로드 전에 거부
- 다운로드 크기 제한과 잘못된 이미지 거부
- 실패 시 스테이징 파일 정리
- 신규 자산 수집과 직접 분류 연결
- 완전 중복에서 분류 추가 및 무변경 구분
- 유사 이미지 검토 대기 반환
- 기존 파일 끌어놓기 중복 정책 유지

### Windows Edge 인수 검사

1. Lakomics에서 인증 키를 확인하고 압축 해제 Edge 확장 프로그램에 입력한다.
2. X 단일 이미지 게시물에서 일반 클릭이 그대로 동작하는지 확인한다.
3. 이미지를 12px 이상 끌어 도넛을 열고 여러 계층을 한 번의 연속 드래그로 탐색한다.
4. 최종 분류에서 놓아 자산이 미디어 금고에 들어오고 출처 URL과 직접 분류가 보존되는지 확인한다.
5. 같은 이미지를 다른 분류로 다시 수집해 파일은 늘지 않고 분류만 추가되는지 확인한다.
6. 13개 이상의 형제 분류에서 페이지 이동과 슬롯 위치 유지가 동작하는지 확인한다.
7. 앱 종료, 잘못된 인증 키, 삭제된 분류와 네트워크 실패 안내를 확인한다.

## 완료 기준

- Edge의 일반 X 이미지 클릭을 깨뜨리지 않는다.
- 사용자가 이미지 드래그 시작부터 최종 분류 선택까지 마우스 버튼을 한 번만 누른다.
- 최종 분류 하나만 직접 저장되고 상위 소속은 기존 계층 규칙으로 조회된다.
- 브라우저 다운로드 폴더를 거치지 않고 앱이 원본 파일의 생명주기를 소유한다.
- 같은 이미지를 반복 수집해도 자산 파일은 하나만 존재한다.
- 분류 이름·계층 변경이 확장 프로그램의 별도 태그 복제본을 만들지 않는다.
- 앱이 꺼졌거나 요청이 실패했을 때 불완전한 자산이나 오프라인 대기열이 남지 않는다.
