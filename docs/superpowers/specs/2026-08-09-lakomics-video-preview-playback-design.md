# Lakomics 영상 미리보기와 재생 설계

## 1. 목표

Lakomics가 MP4, WebM, MOV 영상을 이미지와 같은 자산으로 수집·분류하고, Eagle처럼 갤러리 타일에서 음소거 미리보기와 시간 탐색을 제공한다. 더블클릭하면 앱 내부 전체화면 플레이어에서 직접 재생 가능한 영상은 원본 품질로, 비호환 영상은 감상용 호환 재생본으로 재생한다.

짧은 웹 클립과 20분 이상의 애니메이션·방송·영화가 한 라이브러리에 섞이는 사용을 전제로 한다. 모든 영상을 일괄 변환하지 않고, 원본이 Windows WebView2에서 재생 가능하면 구간 단위로 직접 제공하며 재생할 수 없는 원본에만 호환 재생본을 만든다.

이 단계는 ADR-0016의 영상 재생 보류 결정을 끝내고 ADR-0025의 원본 우선 재생 정책을 구현한다. 이미지 5만 개와 영상 5천 개라는 ADR-0015의 성능 목표는 유지한다.

## 2. 범위

이번 단계에 포함한다.

- MP4, WebM, MOV 수집과 SHA-256 완전 중복 차단
- 영상 재생시간, 원본 형식, 영상·음성 코덱과 해상도 저장
- 대표 썸네일과 전체 시간대 탐색 프레임 생성
- 원본 재생 적합성 판정과 필요한 경우에만 호환 재생본 생성
- SQLite에 기록되는 재개 가능한 백그라운드 준비 상태
- 갤러리의 200ms 지연 음소거 호버 재생
- 갤러리 진행 막대의 실시간 시간 탐색
- 전체화면 플레이어의 재생, 일시정지, 타임라인, 음량과 전체화면
- 긴 영상의 HTTP Range 호환 구간 전송
- 이미지와 동일한 분류, 즐겨찾기, 출처, 수집일, 휴지통과 탐색기 복사
- 짧은 WebM 두 개와 별도 긴 시험 영상을 이용한 실제 Windows 검증

이번 단계에 포함하지 않는다.

- 재인코딩되거나 잘린 영상의 유사도 감지
- 자막, 배속, 5초 앞뒤 이동과 프레임 단위 이동
- 대표 썸네일 수동 지정
- 재생 위치 저장, 구간 북마크, 재생목록과 영상 주석
- MKV, AVI, WMV 등 추가 컨테이너
- 오디오 전용 자산과 만화 읽기

## 3. 도메인과 저장 상태

영상은 별도 콘텐츠 계층이 아니라 기존 `자산`의 한 종류다. 분류와 파일 생명주기 규칙은 이미지와 공유한다. 대표 썸네일, 탐색 프레임, 호환 재생본은 독립 자산이 아닌 `파생 미디어`이며 원본에서 다시 만들 수 있다.

스키마 마이그레이션은 기존 `assets.media_kind`에 `video`를 허용하고 영상 전용 행을 저장하는 `video_assets` 테이블을 추가한다. 기존 이미지 행은 그대로 보존하고 마이그레이션 전에 검증된 메타데이터 백업을 만든다.

`video_assets`는 최소한 다음 정보를 소유한다.

- 자산 ID
- 재생시간 밀리초
- 원본 컨테이너, 영상 코덱과 nullable 음성 코덱
- `pending`, `processing`, `ready`, `failed` 준비 상태
- nullable 공개 오류 코드
- 원본 또는 호환 재생본 중 선택된 재생 변형
- 파생 미디어 생성 정책 버전
- Module 내부에서만 쓰는 nullable 관리 상대 경로와 탐색 프레임 개수

기존 `thumbnail_relative_path`는 준비 중인 영상에서 nullable일 수 있다. 화면에 전달하는 `AssetSummary`는 흩어진 nullable 필드 대신 미디어 종류로 구분되는 공개 요약을 가진다.

```text
image | gif
video { durationMs, preparationState, scrubFrameCount }
```

SQLite와 내부 상대 경로, 코덱별 정책, FFmpeg 명령줄은 React에 노출하지 않는다.

## 4. Module 구조와 Interface

Rust 라이브러리 안의 깊은 `VideoMedia` Module이 영상 복잡성을 소유한다.

- 파일이 실제 MP4, WebM 또는 MOV인지 검사한다.
- 메타데이터를 읽고 직접 재생 가능 여부를 판정한다.
- 대표 썸네일과 전체 시간대 탐색 프레임을 만든다.
- 필요한 경우에만 H.264/AAC MP4 호환 재생본을 만든다.
- 임시 파생 파일을 완성된 파일로 원자적으로 설치한다.
- 준비 상태, 오류, 재시도와 재시작 복구를 관리한다.
- 휴지통 영구 삭제와 라이브러리 검사에 필요한 파생 미디어 목록을 숨긴다.

프론트엔드가 사용하는 Library Interface는 작게 유지한다.

```text
ingest_media(request) -> IngestOutcome
prepare_pending_videos(limit) -> VideoPreparationProgress
retry_video_preparation(assetId) -> VideoPreparationState
get_asset(assetId) -> AssetSummary
```

`ingest_media`가 이미지와 영상 분기를 숨기고 현재 `ingest_image` Interface를 대체한다. 묶음 크기, 직접 재생 코덱 목록, 탐색 프레임 수, 호환 재생본 품질과 동시 처리 수는 `VideoMedia` Module이 소유한다. 화면 설정이나 분류 이름으로 이 정책을 바꾸지 않는다. 첫 정책은 탐색 프레임을 영상의 1초마다 한 장씩 최대 240장 균등 추출하고, 호환 재생본은 원본 비율을 유지하면서 최대 1920×1080, 최대 30fps의 H.264/AAC MP4로 만든다.

FFmpeg와 FFprobe는 Windows용 Tauri sidecar로 Rust에서만 실행한다. JavaScript에 임의 명령 실행 권한을 주지 않는다. 배포 가능한 LGPL 구성만 사용하고 GPL/nonfree 옵션, 바이너리 출처, 빌드 설정, 정확한 버전과 라이선스 고지를 검증 가능한 형태로 기록한다. Tauri의 공식 sidecar 방식은 `externalBin`으로 실행 파일을 묶는다. FFmpeg 공식 문서는 Media Foundation의 `h264_mf`와 내장 AAC 인코더를 제공하므로 호환 재생본은 외부 `libx264` 없이 만드는 Windows 구성을 사용한다.

참고:

- https://v2.tauri.app/develop/sidecar/
- https://ffmpeg.org/legal.html
- https://ffmpeg.org/ffmpeg-codecs.html

## 5. 수집과 백그라운드 준비

영상 한 개의 수집 흐름은 다음과 같다.

1. 외부 원본을 관리 임시 위치로 복사하면서 SHA-256을 계산한다.
2. 컨테이너와 최소 메타데이터를 빠르게 검사한다.
3. 완전 중복이면 새 자산을 만들지 않고 기존 자산 ID를 반환한다.
4. 지원 영상이면 원본을 미디어 금고에 원자적으로 설치하고 정상 자산과 `pending` 영상 행을 한 SQLite 트랜잭션에 기록한다.
5. 즉시 갤러리 목록에 표시하고 작업창은 `미리보기 준비 중` 상태를 보여준다.
6. 백그라운드 작업이 대표 썸네일, 탐색 프레임과 필요 시 호환 재생본을 순서대로 만든다.
7. 모든 필수 파생 미디어가 설치되면 `ready`로 바꾸고 화면을 갱신한다.

파생 미디어 준비는 동시에 하나만 실행한다. 앱이 종료되면 `pending`은 그대로 남고, 열려 있던 `processing`은 다음 실행에서 안전하게 `pending`으로 되돌려 다시 처리한다. 같은 자산에 여러 준비 작업이 겹치지 않게 SQLite 상태 전이를 원자적으로 예약한다.

반복 실패를 피하기 위해 `failed`는 자동으로 계속 재시도하지 않는다. 사용자가 재시도하거나 라이브러리 검사가 파생 미디어 문제를 확인했을 때만 `pending`으로 되돌린다. 외부 사용자 원본은 성공, 중복, 실패와 관계없이 삭제하지 않는다.

## 6. 미디어 전송

현재 자산 ID 기반 미디어 프로토콜을 확장하되 내부 경로는 계속 숨긴다.

```text
thumbnail(assetId)
playback(assetId)
scrubFrame(assetId, frameIndex)
```

`playback`은 준비된 영상의 정책 결과에 따라 원본 또는 호환 재생본을 선택한다. React는 어떤 파일이 선택됐는지 알지 않는다. HTTP `Range` 요청을 검증하고 필요한 바이트 구간만 반환해 긴 영상을 통째로 메모리에 읽지 않는다. 잘못된 범위, 휴지통·누락 자산, 관리 루트 밖 경로와 디렉터리 교체 공격은 기존 미디어 소유권 규칙으로 거부한다.

탐색 프레임은 영상 전체 구간에서 1초당 한 장, 최대 240장을 균등하게 생성한다. UI는 포인터 위치를 공개 `scrubFrameCount`의 인덱스로 바꾸고, 프로토콜은 해당 WebP 프레임 하나만 반환한다. 프레임 파일 배치와 생성 정책 버전은 Module 내부 구현이다.

## 7. Eagle식 갤러리 미리보기

영상 타일은 준비 전에도 목록에 나타난다.

- 준비 중: 공통 영상 자리표시자와 작은 진행 상태
- 준비 완료: 대표 썸네일, 영상 아이콘과 오른쪽 아래 재생시간
- 준비 실패: 대표 자리표시자, `미리보기 준비 실패`와 재시도 동작

마우스가 타일에 200ms 머물면 항상 음소거로 자동 재생한다. 스크롤 중 잠깐 스친 타일은 미디어를 열지 않는다. 동시에 활성화되는 영상은 하나뿐이며 다른 타일이 활성화되거나 화면 밖으로 가면 이전 `<video>`의 재생, `src`와 버퍼를 해제한다.

호버 중 타일 아래에 얇은 진행 막대를 표시한다. 포인터 이동 즉시 미리 만든 탐색 프레임을 보여주고, 포인터가 짧게 안정되면 실제 영상의 `currentTime`을 해당 위치로 옮겨 계속 재생한다. 진행 막대가 포인터 입력을 소유해 기존 단일·다중 선택과 탐색기 드래그를 시작하지 않게 한다. 타일의 나머지 영역은 현재 선택과 드래그 Interface를 그대로 사용한다.

마우스가 타일을 벗어나면 재생을 멈추고 대표 썸네일로 돌아간다. 더블클릭과 Enter는 전체 플레이어를 연다. 호버 미리보기는 보조 기능이므로 키보드 사용자는 전체 플레이어로 같은 내용을 감상할 수 있다.

## 8. 전체 영상 플레이어

현재 전체화면 `AssetViewer`는 자산 미디어 종류에 따라 이미지 또는 영상 표시 Module을 선택한다. 이전·다음 자산 이동, 닫기와 기존 정보 패널은 공유하고 영상 재생 상태는 영상 표시 Module 안에 둔다.

첫 버전은 다음 동작만 제공한다.

- 재생과 일시정지
- 현재 시간과 전체 재생시간
- 타임라인 클릭·드래그 탐색
- 타임라인 호버 프레임 미리보기
- 음소거와 음량 조절
- 전체화면 전환
- 좌우 버튼으로 이전·다음 자산 이동
- Space 재생·일시정지와 Escape 닫기

플레이어는 `playback(assetId)`만 사용한다. 원본 또는 호환 재생본 선택은 미디어 프로토콜 뒤에 숨긴다. 정보 패널은 항상 원본 영상의 형식, 해상도, 파일 크기, 재생시간, 출처와 수집일을 표시한다. 자산을 바꾸거나 닫을 때 이전 영상 연결을 해제한다.

## 9. 오류와 생명주기

- 실제 영상이 아니거나 지원 컨테이너가 아니면 자산을 만들지 않고 작업창에 외부 전체 경로가 아닌 파일명과 공개 오류를 표시한다.
- 원본 설치와 자산·영상 행 등록은 현재 수집 트랜잭션 규칙을 재사용한다.
- 각 파생 미디어는 관리 임시 파일에 쓴 뒤 파일 동기화와 소유권 확인을 거쳐 최종 경로에 설치한다.
- 파생 미디어 실패는 정상 원본 자산, 분류, 출처, 수집일과 즐겨찾기를 변경하지 않는다.
- 호환 재생본 생성이 실패하면 원본이 직접 재생 가능한 경우 `ready`를 유지하고, 그렇지 않으면 `failed`로 남겨 재시도할 수 있게 한다.
- 휴지통 이동은 원본과 파생 미디어를 제자리 보존한다. 복원 시 재생 준비 상태를 그대로 사용한다.
- 영구 삭제만 원본, 대표 썸네일, 탐색 프레임과 호환 재생본을 함께 제거한다. 일부 삭제 실패는 기존 휴지통 재시도 규칙을 따른다.
- 라이브러리 검사는 원본을 임의로 교체하지 않는다. 파생 미디어 누락이나 생성 정책 버전 불일치는 `pending`으로 바꿔 다시 만들 수 있다.
- 공개 결과와 오류에는 FFmpeg 명령, 표준 오류 원문, 내부 상대·절대 경로를 포함하지 않는다.

## 10. 검증

Rust 테스트는 다음을 증명한다.

- 기존 이미지 라이브러리가 영상 스키마로 마이그레이션되고 기존 행과 썸네일이 보존된다.
- MP4, WebM, MOV의 컨테이너와 메타데이터를 검증한다.
- 영상 완전 중복은 새 자산과 준비 작업을 만들지 않는다.
- 원본 설치와 `pending` 등록이 원자적이다.
- 직접 재생 원본은 호환 재생본을 만들지 않고, 비호환 원본만 호환 재생본을 만든다.
- `pending`과 중단된 `processing`이 재시작 후 이어지고, `failed`는 자동 반복되지 않는다.
- 파생 미디어 임시 파일은 실패 후 노출되지 않으며 재시도가 완성 파일만 설치한다.
- `Range`의 정상, suffix, open-ended, 잘못된 범위 요청을 처리하고 전체 파일을 읽지 않는다.
- 파생 미디어 경로와 오류가 직렬화되지 않는다.
- 휴지통, 복원, 영구 삭제와 라이브러리 검사 규칙이 원본과 파생 미디어에 함께 적용된다.

React 테스트는 다음을 증명한다.

- 영상 타일이 준비 중, 준비 완료와 실패 상태를 정확히 표시한다.
- 호버 200ms 전에는 재생하지 않고 시작 후 항상 음소거다.
- 동시에 영상 하나만 활성화되고 화면 밖 타일의 미디어 연결을 해제한다.
- 진행 막대 위치가 탐색 프레임과 재생 시간으로 안정적으로 변환된다.
- 진행 막대 조작이 선택, 다중 선택과 내부·외부 드래그를 시작하지 않는다.
- 플레이어가 재생, 일시정지, 타임라인, 음량, 전체화면과 키보드를 처리한다.
- 영상 기능 추가 후 이미지 뷰어, 가상화된 갤러리와 5만 이미지 성능 테스트가 유지된다.

실제 Windows 검증은 라이브러리 미등록 시 `C:\Users\namwoojun\Desktop\test`를 사용한다. 이미 복사된 `망니메이션 1화.webm`, `망니메이션 2화.webm`과 별도 MP4, MOV, 20분 이상 영상으로 다음을 확인한다.

- 외부 원본 보존과 정확한 중복 차단
- 즉시 목록 표시와 백그라운드 준비 상태
- 앱 종료·재실행 후 준비 재개
- 호버 후 0.5초 안의 음소거 재생 시작
- 타임라인 탐색 프레임의 즉각적인 갱신
- 긴 영상 탐색 중 앱 전체 멈춤과 전체 파일 메모리 적재가 없음
- 전체 플레이어와 이전·다음 자산 이동
- 영상의 탐색기 복사본이 원본 SHA-256과 일치

## 11. 완료 기준과 후속 범위

완료 조건은 자동 검증, Windows 실제 MP4·WebM·MOV 검증, 짧고 긴 영상 검증, 정상·좁은 화면 캡처와 사용자 시각 승인을 모두 만족하는 것이다. FFmpeg sidecar를 포함한 디버그와 일반 Windows 빌드가 별도 사용자 설치 없이 동작해야 한다.

후속 단계에서는 실제 사용 피드백에 따라 자막, 배속, 건너뛰기, 재생 위치, 수동 대표 썸네일과 영상 유사도 중 우선순위를 다시 정한다. 이번 Interface에 아직 쓰지 않는 설정이나 추측성 확장점을 추가하지 않는다.
