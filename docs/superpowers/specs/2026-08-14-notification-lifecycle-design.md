# 알림 수명과 긴 내용 표시 설계

## 목적

Lakomics의 일시 알림과 수집 작업 결과가 화면을 계속 가리거나 긴 파일명 때문에 레이아웃을 깨뜨리지 않게 한다. 사용자는 알림을 기다려서 없애거나 즉시 닫을 수 있어야 하며, 재시도가 필요한 지속 오류는 실수로 사라지지 않아야 한다.

## 범위

- 공용 `Toast`를 사용하는 일시 알림
- `WorkTray`에 표시되는 일반 수집, 메타데이터 폴더 수집, 영상 준비 결과
- 긴 제목, 파일명, 오류 메시지의 표시 규칙

데이터를 불러오지 못해 `다시 시도`가 필요한 인라인 오류는 작업 결과 알림이 아니다. 이 오류는 현재처럼 원인이 해소되거나 다시 시도할 때까지 유지한다.

## 동작

### 일시 알림

- 기존 수명인 5초를 유지한다.
- 오른쪽에 아이콘 형태의 `닫기` 버튼을 제공한다.
- 본문은 한 줄만 표시하고 사용 가능한 너비를 넘으면 말줄임표로 생략한다.
- 알림의 전체 문자열은 접근성 이름과 `title` 속성으로 보존하여 생략된 내용을 확인할 수 있게 한다.

### 작업 결과 알림

- 실행 중인 작업은 자동으로 닫지 않는다.
- 완료 또는 실패한 결과는 표시된 시점부터 8초 뒤 자동으로 닫는다.
- 포인터가 결과 알림 위에 있거나 내부 버튼에 키보드 포커스가 있으면 남은 시간을 보존한 채 타이머를 일시정지한다. 상호작용이 끝나면 남은 시간부터 다시 센다.
- 모든 결과 알림 오른쪽 위에 아이콘 형태의 `닫기` 버튼을 제공한다.
- 제목, 요약, 파일명과 메시지는 각 행에서 한 줄 말줄임 처리한다.
- 건너뜀과 실패 상세는 합쳐서 최대 3개만 표시하고, 더 있으면 `외 N건`으로 요약한다.
- 기존 `폴더 다시 가져오기`, 실패 재시도, 중복 자산 열기, 검토 대기 열기 동작은 유지한다.

## 구조

`Toast`는 표현과 수동 닫기만 담당한다. 부모가 `onDismiss`로 실제 메시지 상태를 지우며, 기존 `useAutoDismiss`가 5초 수명을 계속 담당한다. 지속 오류처럼 닫을 수 없어야 하는 사용처는 `onDismiss`를 전달하지 않는다.

`WorkTray`는 작업 상태가 `running`에서 종료 상태로 바뀐 시점을 감지해 작업별 타이머를 관리한다. 타이머가 만료되면 기존 `dismissWork(work.id)` 경로를 사용한다. 별도의 전역 알림 저장소나 큐는 추가하지 않는다.

긴 문자열 처리는 새 데이터 가공 대신 CSS의 `min-width: 0`, `overflow: hidden`, `text-overflow: ellipsis`, `white-space: nowrap`을 사용한다. 상세 개수 제한만 렌더링 직전에 배열을 자른다.

## 접근성

- 닫기 버튼의 접근 가능한 이름은 `알림 닫기` 또는 `결과 닫기`로 명확히 구분한다.
- 실행 중 진행률은 기존 `aria-live="polite"` 동작을 유지한다.
- 결과 알림을 가리키거나 내부를 탐색하는 동안 자동 종료하지 않는다.
- 말줄임은 시각적 표현에만 적용하고 원문 문자열은 DOM 속성에 보존한다.

## 테스트

- 공용 Toast가 닫기 버튼을 노출하고 콜백을 실행하는지 검증한다.
- 완료된 작업 결과가 8초 후 닫히는지 검증한다.
- 실행 중인 작업은 시간이 지나도 닫히지 않는지 검증한다.
- 포인터 오버와 포커스 동안 자동 종료가 정지하고 이후 남은 시간부터 재개되는지 검증한다.
- 상세 오류가 3개로 제한되고 나머지 개수가 요약되는지 검증한다.
- 긴 문자열에 말줄임용 클래스와 전체 내용 속성이 적용되는지 검증한다.
- 기존 전체 프런트엔드 테스트와 프로덕션 빌드를 실행한다.

## 제외 사항

- 여러 알림을 쌓고 순서를 관리하는 전역 알림 큐
- 알림 기록 화면
- 불러오기 재시도 오류의 자동 종료
- 수집 성능 개선
