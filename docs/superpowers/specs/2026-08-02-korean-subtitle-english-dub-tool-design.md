# 한글 자막·영어 더빙 영상 합성 도구 설계

## 목적

사용자가 다운로드와 편집 권한을 가진 두 YouTube 영상에서 한글 자막이 삽입된 영상 스트림과 영어 더빙 오디오 스트림을 받아 하나의 MP4 파일로 합친다. Windows에서 별도 Python·FFmpeg 설치 없이 단일 실행 파일로 사용할 수 있어야 하며, 특정 영상에 한정하지 않고 같은 편집본의 한국어·영어 영상 쌍에 반복 사용할 수 있어야 한다.

## 범위

첫 버전은 다음 기능만 제공한다.

- 한글 자막 영상 URL과 영어 더빙 영상 URL 입력
- 결과 MP4 저장 위치 선택
- 영어 오디오 시작 위치를 초 단위로 조정
- 다운로드 및 합성 진행 상태 표시
- 실행 중인 작업 취소
- 기존 출력 파일의 무단 덮어쓰기 방지
- 두 원본의 재생 시간 차이 감지와 경고

서로 장면 구성이나 편집 순서가 다른 영상을 자동으로 잘라 맞추는 기능, 음성 기반 자동 동기화, 계정·지역 제한 우회, DRM 우회, 자막 추출은 제공하지 않는다.

## 사용자 인터페이스

하나의 Windows 창에 다음 요소를 둔다.

1. 한글 자막 영상 URL 입력란
2. 영어 더빙 영상 URL 입력란
3. 결과 MP4 경로 입력란과 파일 선택 버튼
4. 영어 오디오 오프셋 입력란(초, 기본값 `0.0`)
5. `만들기` 버튼
6. 작업 중에만 활성화되는 `취소` 버튼
7. 현재 단계와 오류를 보여주는 진행 로그

작업 중에는 URL, 저장 경로, 오프셋과 `만들기` 버튼을 잠가 같은 창에서 작업이 겹치지 않게 한다. 완료·실패·취소 후에는 다시 입력할 수 있게 한다.

## 처리 흐름

1. 두 URL이 지원되는 HTTP(S) 주소인지, 결과 경로가 MP4인지, 오프셋이 유한한 숫자인지 검증한다.
2. 앱 전용 데이터 폴더에서 `yt-dlp`와 FFmpeg를 확인한다.
3. 도구가 없으면 프로젝트가 안내하는 Windows 배포처에서 고정된 버전을 내려받고, 앱의 도구 명세에 기록한 SHA-256과 대조한 뒤 원자적으로 설치한다.
4. 두 영상의 제목과 재생 시간을 조회한다.
5. 두 재생 시간의 차이를 판단한다.
6. 한글 영상에서는 사용 가능한 최고 품질의 영상 스트림을 받고, 영어 영상에서는 최고 품질의 오디오 스트림을 받는다.
7. 영어 오디오에 사용자가 지정한 시작 오프셋을 적용한다.
8. 영상 스트림은 재인코딩하지 않고 결과 MP4로 복사한다. 오디오가 MP4와 호환되지 않을 때만 AAC로 변환한다.
9. 결과를 작업용 임시 경로에 완성하고 유효성을 확인한 뒤 사용자가 선택한 경로로 이동한다.

오프셋이 양수면 영어 오디오를 그만큼 늦게 시작하고, 음수면 영어 오디오 앞부분을 그만큼 잘라 일찍 시작한다. 결과 길이는 한글 자막 영상의 영상 스트림 길이를 기준으로 한다.

## 재생 시간 불일치

오프셋을 반영한 두 스트림의 예상 종료 시점 차이가 2초 이하면 별도 확인 없이 진행한다. 2초 초과 10초 이하이면 GUI 로그에 경고를 표시하고 진행한다. 10초를 초과하면 합성을 시작하지 않고, 두 길이와 현재 오프셋을 표시해 사용자가 입력을 확인하게 한다.

이 기준값은 첫 버전의 정책을 소유하는 처리 모듈 한곳에 둔다. 실제 사용에서 오탐이 확인되기 전에는 설정 화면을 추가하지 않는다.

## 오류와 파일 안전

- 작업마다 운영체제 임시 폴더 아래에 고유 작업 폴더를 만든다.
- 다운로드나 합성 실패 시 최종 출력 경로에 불완전한 파일을 만들지 않는다.
- 사용자가 선택한 출력 파일이 이미 있으면 작업 시작 전에 다른 이름을 선택하도록 알린다.
- 취소 시 실행 중인 자식 프로세스를 종료하고 임시 작업 폴더를 정리한다.
- 도구 다운로드 실패, URL 분석 실패, 비공개·삭제 영상, 사용 가능한 스트림 없음, 디스크 공간 부족, FFmpeg 실패를 사용자 행동이 가능한 한국어 메시지로 표시한다.
- 로그에는 URL의 인증 정보나 쿠키를 기록하지 않는다.

## 구조

첫 버전은 추측성 계층을 만들지 않고 네 부분으로만 나눈다.

- `app`: Tkinter 창, 입력 상태, 작업 시작·취소
- `workflow`: 검증, 길이 판단, 다운로드와 합성 순서
- `tools`: `yt-dlp`·FFmpeg 준비와 자식 프로세스 실행
- `media`: FFmpeg 명령 생성과 결과 검증

GUI 스레드에서는 외부 프로세스를 직접 기다리지 않는다. 작업은 하나의 백그라운드 스레드에서 실행하고, 상태 메시지만 스레드 안전 큐로 GUI에 전달한다. 동시에 하나의 작업만 허용한다.

## 배포

Python 표준 라이브러리와 Tkinter를 사용하고 PyInstaller로 Windows 단일 EXE를 만든다. EXE에는 Python 런타임과 앱 코드만 포함한다. `yt-dlp`와 FFmpeg는 첫 실행 때 앱 전용 데이터 폴더에 자동 준비하고 이후 재사용한다.

도구 위치는 사용자 프로필의 로컬 애플리케이션 데이터 아래 앱 전용 폴더로 고정한다. 자동 준비는 별도 설치 마법사나 관리자 권한을 요구하지 않는다. 영상 다운로드 자체가 인터넷 연결을 필요로 하므로 내부 도구의 첫 실행 다운로드는 독립 실행 요구와 충돌하지 않는다.

다운로드 URL, 버전, SHA-256은 하나의 도구 명세가 소유한다. 새 도구 버전은 명세와 검증 테스트를 갱신한 새 앱 버전으로 배포하며, 실행 중에 검증되지 않은 최신 바이너리로 자동 교체하지 않는다.

## 테스트

테스트 우선으로 다음 행위를 검증한다.

- URL, MP4 경로, 오프셋 입력 검증
- 양수·음수 오프셋의 FFmpeg 인자 생성
- 재생 시간 차이에 따른 진행·경고·중단 판단
- 기존 출력 파일 보호
- 자식 프로세스 실패와 취소 상태 변환
- 짧은 로컬 영상과 오디오 샘플을 합친 뒤 영상 코덱이 복사되고 오디오 스트림이 존재하는지 확인하는 통합 테스트

실제 YouTube 요청은 외부 상태에 의존하므로 자동 테스트에 넣지 않는다. 배포 후보 EXE에서 승인된 공개 테스트 영상 두 개를 사용해 메타데이터 조회, 다운로드, 합성, 재생을 수동 검증한다.

## 완료 기준

- 새 Windows 환경에서 EXE 하나를 실행해 내부 도구를 자동 준비할 수 있다.
- 두 URL과 저장 경로를 입력해 한글 삽입 자막 화면과 영어 더빙 오디오가 포함된 MP4를 만든다.
- 영상 스트림은 원본 코덱이 MP4와 호환되는 한 재인코딩되지 않는다.
- 길이 차이, 기존 파일, 실패, 취소가 설계된 방식으로 처리된다.
- 단위 테스트와 로컬 미디어 통합 테스트가 통과한다.
