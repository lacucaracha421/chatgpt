# 최상위 분류 폴더 이동 설계

## 목적

사용자가 만든 최상위 분류 폴더를 다른 분류 폴더 아래로 이동할 수 있게 한다. 폴더의 하위 구조와 연결된 자산은 그대로 유지하며, 분류 계층에서의 위치에 맞게 내부 종류만 자동 조정한다.

## 현재 문제

분류 항목의 `kind`가 `root`이면 프런트엔드와 라이브러리 모듈이 부모 지정을 모두 거부한다. 실제 `리버스` 폴더는 `root`로 저장되어 있으므로, 하위 폴더 8개나 직접 연결 자산 20개와 무관하게 `게임` 아래로 이동할 수 없다.

## 선택한 접근

이동 명령이 목적지에 맞춰 일반 분류 폴더의 종류를 자동 전환한다.

- `root`를 다른 분류 폴더 아래로 이동하면 `tag`로 변경한다.
- `tag`를 최상위로 이동하면 `root`로 변경한다.
- `tag`를 다른 폴더 사이에서 이동하면 종류를 유지한다.
- `work`는 작품 모델이므로 기존처럼 `root` 바로 아래에서만 이동할 수 있다.

대안으로 종류 변환 메뉴를 별도로 추가할 수 있지만 사용자가 이동 전에 내부 모델을 이해해야 한다. `root`와 `tag` 구분을 제거하는 전체 모델 개편은 이번 문제에 비해 범위가 크다.

## 데이터 흐름

사이드바 드래그와 `폴더 이동` 대화상자는 최상위 폴더를 유효한 목적지로 허용한다. 최상위가 아닌 일반 폴더에는 `최상위` 목적지도 제공한다.

라이브러리 모듈의 기존 `move_classification(id, parent_id)` 명령은 한 SQLite 트랜잭션에서 다음을 수행한다.

1. 현재 항목과 목적지 부모를 읽는다.
2. 목적지에 따라 `root` 또는 `tag` 종류를 계산한다.
3. 계산된 종류와 부모 조합을 기존 규칙으로 검증한다.
4. 순환과 같은 이름의 형제 충돌을 기존처럼 거부한다.
5. `kind`와 `parent_id`를 함께 갱신한다.

자산 연결 테이블과 하위 항목의 `parent_id`는 수정하지 않는다. 따라서 직접 자산, 하위 폴더, 하위 폴더의 자산은 그대로 보존된다.

## 오류 처리

- 자기 자신이나 자신의 하위 폴더로 이동할 수 없다.
- 목적지에 같은 이름의 형제가 있으면 이동할 수 없다.
- 작품 폴더를 최상위나 일반 태그 아래로 이동할 수 없다.
- 실패하면 트랜잭션이 롤백되어 종류와 부모가 함께 원래 상태로 남는다.

## 테스트

- Rust 라이브러리 테스트에서 자산과 하위 폴더가 있는 `root`를 다른 `root` 아래로 이동하고 `tag` 전환, 부모 변경, 자산 연결, 하위 구조 보존을 검증한다.
- 같은 항목을 최상위로 되돌려 `root` 전환을 검증한다.
- 프런트엔드 드래그 테스트에서 `root`를 다른 `root`에 놓을 수 있고 기존 이동 명령을 호출하는지 검증한다.
- 이동 대화상자 테스트에서 `root`의 다른 폴더 목적지와 `tag`의 `최상위` 목적지가 노출되는지 검증한다.
- 기존 순환, 중복 이름, 작품 부모 제약 테스트를 유지한다.

## 제외 사항

- 기존 라이브러리 데이터의 일괄 마이그레이션
- 작품과 일반 폴더 종류의 자동 전환
- 자산 또는 하위 폴더 이동 방식 변경
- 새 이동 API나 별도 종류 변환 UI
