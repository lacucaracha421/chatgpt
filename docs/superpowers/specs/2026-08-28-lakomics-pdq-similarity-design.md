# Lakomics PDQ 유사 이미지 판정 설계

## 1. 목표

Lakomics의 64비트 difference hash 판정을 256비트 PDQ 판정으로 교체한다. 리사이즈, 재압축, 포맷 변경, 가벼운 크롭과 작은 워터마크가 적용된 같은 이미지는 검토 대상으로 유지하면서, 흰 배경과 비슷한 명암 배치만 공유하는 서로 다른 일러스트의 오탐을 크게 줄인다.

정확한 중복은 계속 SHA-256으로 자동 차단한다. PDQ는 파일 내용은 다르지만 시각적으로 같은 이미지일 가능성이 있는 대상만 사용자의 검토 대기로 보낸다.

## 2. 관찰된 문제와 근거

현재 `library::similarity`는 이미지를 9×8 회색 이미지로 축소하고 가로 밝기 변화만 비교하는 64비트 dHash를 사용한다. Hamming distance가 6 이하이면 유사 후보로 선택한다.

활성 실사용 라이브러리 `C:\New_lakomics_assets`에는 2026-08-28 조사 시점에 자산 7,933개, 생성된 지각 해시 7,599개, 해결된 유사 검토 5건이 있었다. 이 중 4건이 `keep_both`였으므로 작은 표본이지만 관찰된 판정의 80%가 서로 다른 이미지였다. 오탐의 dHash 거리는 각각 1, 6, 2, 6이었다. 따라서 임계값만 6에서 3으로 낮춰도 거리 1과 2의 오탐이 남는다.

같은 네 쌍에 표준적인 64비트 DCT pHash를 임시 계산한 거리는 30, 24, 16, 32였다. 원본을 절반으로 줄이고 JPEG 품질 70으로 재인코딩한 변형은 모두 거리 0이었다. pHash만으로도 현재 표본은 분리되지만, 승인된 범위에 가벼운 크롭과 워터마크가 포함되므로 더 넓은 변형에 맞춰 설계된 PDQ를 선택한다.

`C:\Users\namwoojun\Desktop\새 폴더 (2)`는 활성 라이브러리가 아니다. 파일 검색으로 발견한 과거 DB를 활성 상태로 추론하지 않는다.

## 3. 범위

이번 변경에 포함한다.

- 원본 방향 하나에 대한 256비트 PDQ 해시와 품질 점수 생성
- 엄격한 거리, 품질, 종횡비 정책
- 기존 dHash의 안전한 무효화와 백그라운드 재생성
- 과거 검토 기록의 알고리즘 종류 보존
- 실제 오탐 형태를 재현하는 합성 회귀 fixture
- 리사이즈, 재압축, 포맷 변경, 5% 크롭, 작은 워터마크 검증
- 5만 개 후보 선형 검색 성능 검증
- 활성 실사용 라이브러리 경계의 에이전트 문서화

이번 변경에 포함하지 않는다.

- 회전 또는 좌우반전 전용 해시
- 큰 크롭, 합성, 스크린샷 속 삽입 이미지 탐지
- SSCD, CLIP 또는 다른 신경망 모델
- 사용자가 조정하는 임계값 설정
- 근사 최근접 검색, 별도 검색 인덱스 또는 병렬 검색
- 영상 유사도
- 유사 검토 화면 변경

## 4. 검토한 접근

### 엄격한 PDQ 256비트

Meta의 PDQ는 256비트 DCT 기반 해시와 0~100 품질 점수를 제공한다. 리사이즈, 품질 저하, 가벼운 크롭, 작은 워터마크와 같은 변형을 대상으로 하며 대규모 선형 Hamming 비교가 저렴하다. 승인된 범위와 가장 잘 맞으므로 채택한다.

Rust에서는 `pdq-rs = "=1.0.0"`을 고정 사용한다. 이 crate는 `image 0.25`의 `DynamicImage`를 받고 vendored Meta C++ reference를 얇게 감싼다. Windows 릴리즈 빌드는 이미 MSVC 도구 체인을 요구하므로 별도 런타임이나 모델 파일을 추가하지 않는다. 구현 시 crate의 MIT 라이선스와 vendored PDQ의 BSD 라이선스를 기존 third-party notice 흐름에 반영한다.

### pHash 64비트

현재 오탐 표본은 잘 분리하고 구현도 가장 작다. 그러나 가벼운 크롭과 워터마크에 대한 여유가 PDQ보다 작으므로 차선으로 남긴다. PDQ 빌드나 배포가 현재 도구 체인에서 성립하지 않는다는 구체적 증거가 생길 때만 pHash 설계로 돌아간다.

### SSCD 신경망

큰 변형까지 잡을 수 있지만 모델 파일, CPU 추론, 임베딩 저장과 배포 부담이 크다. 공식 연구 저장소도 보관 상태이므로 7,933개 규모의 로컬 라이브러리에는 과도하다.

## 5. Module 구조

PDQ 세부 계산은 `app/src-tauri/src/library/image_fingerprint.rs`라는 라이브러리 내부 Module에 둔다. React, Tauri command와 공개 `Library` Interface는 해시 표현이나 품질 정책을 알지 않는다.

내부 Interface는 다음 의미를 가진다.

```rust
pub(crate) struct ImageFingerprint {
    bytes: [u8; 32],
    quality: u8,
}

pub(crate) fn fingerprint(image: &DynamicImage) -> Result<ImageFingerprint, LibraryError>;
pub(crate) fn hamming_distance(left: &[u8; 32], right: &[u8; 32]) -> u32;
pub(crate) fn dimensions_are_compatible(
    left: (u32, u32),
    right: (u32, u32),
) -> bool;
```

`similarity.rs`는 이 내부 Interface로 다음 정책만 조립한다.

- `PDQ_QUALITY_MIN = 50`
- `PDQ_DISTANCE_MAX = 20`
- `ASPECT_RATIO_MAX_FACTOR = 1.15`
- `INDEX_BATCH_SIZE = 50`

알고리즘 Adapter나 사용자 설정 계층은 만들지 않는다. 실제 Implementation은 PDQ 하나뿐이며 다음 교체가 생기기 전까지 내부 Module 하나가 충분하다.

## 6. 판정 정책과 데이터 흐름

수집은 파일마다 다음 순서를 따른다.

1. 관리 임시 위치에 복사하면서 SHA-256을 계산한다.
2. 완전 중복이면 기존 흐름대로 새 자산을 만들지 않는다.
3. 첫 디코딩 이미지로 원본 방향 PDQ 해시와 품질 점수를 한 번 계산한다. GIF는 기존 정책처럼 첫 프레임을 사용한다.
4. 해시와 품질 점수는 후보 여부와 관계없이 자산에 저장한다.
5. 대상 품질이 50 미만이면 유사 검색을 생략하고 정상 자산으로 수집한다.
6. 기존 정상 이미지 중 해시가 있고 품질이 50 이상인 자산을 순회한다.
7. 두 종횡비의 큰 값을 작은 값으로 나눈 값이 1.15를 넘으면 Hamming 비교 전에 제외한다.
8. PDQ Hamming distance가 20 이하인 후보 중 거리가 가장 작은 하나를 선택한다.
9. 거리가 같으면 기존처럼 `collected_at`, 자산 ID 오름차순으로 결정한다.
10. 후보가 있으면 검토 대기로, 없으면 정상 자산으로 등록한다.

품질이 낮은 이미지를 정상 수집하는 것은 false negative를 허용하는 대신 신뢰할 수 없는 해시가 검토 대기를 오염시키지 않도록 하는 고정 정책이다. 정확한 중복은 PDQ 품질과 무관하게 SHA-256으로 계속 차단된다.

회전과 반전용 8개 dihedral hash는 생성하지 않는다. 현재 요구 범위 밖이며 저장량과 비교량을 여덟 배로 늘릴 근거가 없다.

## 7. 스키마 v25와 마이그레이션

`0025_pdq_similarity.sql`과 DB 등록을 추가해 스키마를 25로 올린다. 기존 마이그레이션 전 검증 백업을 그대로 사용한다.

`assets`에는 nullable `perceptual_hash_quality INTEGER`를 추가하고 값이 있으면 0~100인지 검사한다. 기존 `perceptual_hash` BLOB은 컬럼을 늘리지 않고 32바이트 PDQ 저장소로 재사용한다.

`similarity_reviews`는 SQLite의 기존 거리 CHECK를 바꿀 수 없으므로 같은 트랜잭션에서 새 테이블로 재작성한다.

- `distance` 범위를 0~256으로 확장한다.
- `fingerprint_kind TEXT NOT NULL`을 추가한다.
- 기존 행은 `dhash-v1`으로 복사한다.
- 신규 행은 `pdq-v1`으로 기록한다.
- 기존 ID, 자산 참조, 상태, 결정과 시각을 모두 보존한다.
- 외래키와 `ON DELETE SET NULL`, 열린 후보의 UNIQUE 제약, 상태 CHECK와 인덱스를 유지한다.

모든 자산의 `perceptual_hash`, `perceptual_hash_quality`, `perceptual_hash_error`를 NULL로 초기화한다. 과거 디코딩 실패도 새 Implementation에서 한 번 다시 시도할 수 있게 오류를 함께 비운다. 정상 이미지는 기존 `index_missing_similarity_hashes()` 배치가 50개씩 다시 생성한다.

기존 열린 dHash 검토는 자동으로 승인, 삭제 또는 재분류하지 않는다. 사용자 결정 전 자산 상태를 코드가 바꾸지 않는 ADR-0007 원칙을 따른다. 해당 후보가 이후 `keep_both`로 정상화되어 해시가 비어 있으면 기존 백그라운드 인덱서가 PDQ를 생성한다.

## 8. 오류와 복구

- PDQ 품질 50 미만은 오류가 아니라 신뢰도 부족 상태다. 해시와 품질은 저장하되 후보 검색에서 제외한다.
- 디코딩 또는 PDQ 생성이 실패하면 기존 공개 오류 코드 흐름으로 `perceptual_hash_error`를 기록한다.
- 잘못된 길이의 저장 해시는 `InvalidPerceptualHash`로 거부한다. PDQ 행은 정확히 32바이트여야 한다.
- 일부 기존 해시가 아직 재생성되지 않았어도 완전 중복 검사와 정상 수집은 계속 동작한다.
- 마이그레이션이나 foreign-key 검증이 실패하면 라이브러리를 열지 않고 기존 pre-migration snapshot을 남긴다.
- 개발 검증은 임시 라이브러리에서만 수행한다. `C:\New_lakomics_assets`를 여는 첫 릴리즈 실행은 별도 실행 승인 뒤 진행한다.

## 9. 성능

후보 검색은 SQLite에서 정상 이미지의 ID, 32바이트 해시, 품질, 너비와 높이를 읽고 Rust에서 종횡비와 네 번의 64비트 XOR/popcount를 계산한다. 50,000개 후보에서 릴리즈 빌드 기준 1초 이내라는 기존 목표를 유지한다.

현재 라이브러리 규모에서는 이미지 디코딩과 PDQ 생성이 검색보다 비싸다. 기존 50개 백그라운드 배치와 즉시 저장 방식을 유지해 앱 재시작 후 이어서 처리한다. 별도 ANN, 캐시 테이블, 병렬 작업 큐는 측정된 실패가 생기기 전에는 추가하지 않는다.

## 10. 검증

Rust의 가장 관련 있는 라이브러리 테스트로 다음을 증명한다.

- 같은 이미지의 절반 리사이즈, JPEG 품질 70 재압축과 포맷 변경은 거리 20 이하이다.
- 각 변을 5% 자른 이미지와 작은 모서리 워터마크를 추가한 이미지는 거리 20 이하이다.
- 흰 배경과 큰 어두운 실루엣 때문에 dHash가 가까워지는 서로 다른 두 합성 이미지는 거리 20을 넘는다.
- 종횡비 factor가 1.15를 넘는 쌍은 해시 거리와 무관하게 제외된다.
- 단색 또는 저정보 fixture는 품질 50 미만으로 후보 검색에서 제외된다.
- 32바이트가 아닌 저장 해시는 안정적인 오류가 된다.
- 거리, 수집일, 자산 ID 순서의 후보 선택이 유지된다.
- v24 라이브러리의 자산과 해결·열린 검토를 v25로 옮긴 뒤 기록과 외래키가 보존되고 해시만 초기화된다.
- 50,000개 PDQ 해시 검색은 ignored release performance test에서 1초 이내이다.

실제 사용자 이미지 네 쌍은 저장소 fixture로 복사하지 않는다. 구현 후 읽기 전용 분석 명령으로 `C:\New_lakomics_assets`의 보존된 `keep_both` 쌍이 새 기준에서 모두 제외되는지만 확인할 수 있다. 이 분석은 DB와 자산을 수정하지 않는다.

프론트엔드 Interface와 화면 동작이 바뀌지 않으므로 React 테스트나 시각 검증은 추가하지 않는다.

## 12. 완료 기준

- 합성 positive fixture가 PDQ 거리, 품질과 종횡비 정책을 통과한다.
- 합성 dHash 충돌 negative fixture가 거부된다.
- 실사용 라이브러리의 보존된 `keep_both` 네 쌍이 읽기 전용 PDQ 분석에서 모두 거부된다.
- v24→v25 마이그레이션 테스트가 기록 보존과 해시 무효화를 증명한다.
- 50,000개 검색 성능 목표를 유지한다.
- 타깃 Rust 검증과 Windows 릴리즈 빌드가 성공한다.
- 실사용 라이브러리는 별도 승인 전까지 수정되지 않는다.
