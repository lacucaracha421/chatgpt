# AV performer grid (2026-10-28)

Status: proposal (design mockup). App source is unchanged. User request: "프로필을 그리드식으로 배열하고, 배우의 나이, 키, 사이즈, 작품 수 등 간단한걸 아래에 적어놓고 정렬같은걸로 특정 컵 수나 키 순 배열이나 뭐 그런거 가능하게". Structure agreed beforehand: the AV collection screen gets a **작품 | 배우** switch; 작품 is today's view unchanged (묶기 안 묶음 / 배우 stays); 배우 is the new grid; a card opens the existing performer page. This is a new area; no earlier redesign round touched it.

## Decisions (user, 2026-10-28)

- **Switch placement:** 작품 | 배우 sits in the section bar right after the type segmented control (AV only), on PC and in the tablet section bar/shade. The two levels are kept apart by a 1px vertical divider and a different control shape: the type keeps the segmented control with the ivory slab (location), the view is face-less text tabs (brighter text, weight 600). This needs a small variant of the shared `Tabs`, proposed as `.ui-tabs--inline` (no rule under the row, compact height). In 배우 the list's 전체 heading row is gone and the grid starts right under the bar; 작품 keeps today's 전체 row and 내 별점 chip. The choice is remembered per library.
- **Top bar title follows the tab** (`AV` / `AV 배우`, count follows too): the section bar still scrolls away with the list (DESIGN.md §3, it drops back on top-bar hover), so the title is what tells the current view. Search becomes performer-name search in 배우. The tablet top bar stays `컬렉션` as today (it does not name the type either).
- **Sort lives in 보기**, the existing `ViewOptionsMenu` (PC) / bottom sheet (tablet), not an inline control (2026-10-22 rule: one 보기 menu owns sort; DESIGN §11: no duplicated function). In 배우 the menu holds 배치 (한 줄에 N개 only: PC 3–10, default 6; tablet 2–5, default 3) and 정렬. 내 별점 is a works filter and is not shown.
- **기준** has six options, too many for a segmented control (2–4), so it is a radio list in the menu-item look (current = weight 600 + 5px accent square at the right). New shared piece for the PC menu and the tablet sheet. **순서** stays a segmented control with per-key words: 작품 수 많은순/적은순, 이름 가나다순/역순, 나이 어린순/많은순, 키·컵 큰순/작은순, 최근 작품 최신순/오래된순. A new key starts at its first (left) word.
- **Card:** 3:4 portrait (the stored crop is already 3:4, `portraitCrop`), radius `--radius-tile`, PC 6 per row; name (body, 500), favourite star if any, `N편` right-aligned (meta, tabular); then two meta lines: `만 27세 · 158cm` and `B88 (F) W58 H86` (the same forms as `ProfileRows` on the performer page; inches → cm). No Japanese name on the card. The square alternative (B, 8 per row) was rejected.
- **Favourite performers:** a still solid star after the name, the performer page's favourite button in its on state (`StarIcon` solid, `--color-accent`). Mark only: no reordering, no toggle on the card.
- **Missing values:** a missing value is left out; lines fill from the top; two meta lines are always reserved so rows stay level. Year-only birth date shows `1998년생`; cup without measurements shows `F컵`; no portrait (or privacy mode) shows the `AvPortrait` initial. No dashes, no "정보 없음" on cards.
- **Sort-key emphasis:** the chosen value turns `--color-text` / 600 and the other stats on the card step down to `--color-faint`. No badge, colour or stripe. 이름 needs nothing. Under 최근 작품 the count slot reads `38편 · 10.14` (newest work's date via `displayDate`).
- **Missing sort values go last** in both directions, after one quiet `SectionLabel` (`컵 정보 없음 3명`); no per-cup sections. Inside that group, and for ties (e.g. same cup), order is 작품 수 descending.
- **Scrubber bubble** shows the sort value (`F컵`, `160cm`, `만 27세`, `38편`, name initial) instead of a date.
- **Interaction:** click/tap opens the existing `AvPerformerPage` (tablet `AvPerformerScreen`), unchanged; back returns to the same scroll position. Hover lightens the portrait only; keyboard focus is the blue outline around the portrait. No new gestures.
- **Filters** (cup/height range) are out of scope. If added later: a leading section in 보기 and an active-filter chip at the start of the list, like the 작품 tab's 내 별점 chip.

## Not verified

- Rendered only as a static mockup in headless Edge (PC page at 1600 wide, tablet frames at 800 × 1280); not in the app or on the tablet.
- Real portrait crops, very long names (truncate with ellipsis; the star and count stay), and privacy mode were not rendered with real data.
- Whether the section bar fits on narrow PC windows with the extra 작품 | 배우 (the shortcut labels already collapse under 1100 px) was not checked.
- Performance of a large performer grid (portrait loading, virtual rows) is an implementation question, not designed here.
