# 작업 패널과 할 일 섹션 추가 (2026-10-13)

사용자 의견 2026-10-13의 2번(상태 패널 작업 칸)과 3번(메모 할 일의 섹션 추가 버튼)에 대한 시안이다. `index.html`은 앱의 실제 CSS(`tokens.css`, `shared-base.css`, `controls.css`, `chrome.css`, `layout/StatusCenter.css`, `notes/notes.css`, `notes/memo/memo.css`)를 읽어 그렸다. 숫자와 이름은 예시다. 두 영역 모두 이번 계획에 있던 곳이다(작업 칸은 `1fb7e67d`, 할 일 버튼은 10.03 섹션 개편).

## 추천

### 작업 칸: A안 (상태별 한 목록)

- 작업 칸 안에 **진행 중 → 대기 → 최근 끝남(접힘)** 순서로 같은 모양의 행을 쌓는다. 묶음 머리 없이 16px 아이콘이 종류를 알려 준다.
- 행: 한 줄 32px(둘째 줄이 있으면 48px), 아이콘 · 이름(body 15) · 숫자(meta 12, 표 숫자) · 48×4 회색 막대(전체를 알 때만) · 28px 일시 정지 아이콘(멈출 수 있을 때만). 행 사이 1px 선. 아이보리·색 띠·행별 스피너 없음.
- 짧은 일이 깜빡이지 않게 **1초 넘게 걸릴 때만** 진행 중에 올리고, 올라가면 적어도 1초 머문다. 행이 들고 날 때 높이·투명도 140ms, 숫자만 바뀔 때는 그대로.
- 대기는 일이 남아 차례를 기다리는 것만(정해진 시각을 기다리는 타이머는 넣지 않음). 절약 모드·일시 정지로 쉬는 일은 대기에 남고 숫자 옆에 이유(`312개 · 절약 모드`).
- 캐릭터 작업은 담당자 하나가 순서대로 일하고 정지 하나를 공유한다. 캐릭터 행 어디서 멈춰도 캐릭터 대기 행이 모두 `일시 정지됨`이 된다.
- 최근 끝남: 이 실행 동안 최근 1시간 · 많아야 10개, 기본 접힘(펼침 기억), 갈 곳이 있는 결과는 › 로 연다. 가져오기 결과의 8초 자동 닫힘은 없앤다.
- 실패는 빨간 문제 행으로 맨 위에 남고 다시 시도하거나 닫을 때까지 접히지 않는다.
- 머리 버튼은 지금처럼 직접 시작한 일만 센다. 배경 일만 돌면 `상태` 그대로. 알림·토스트·자동 열림 없음.
- 동기화 칸의 `동기화 중 · N개 남음`은 작업 칸의 클라우드 업로드 행(일시 정지 포함)으로 옮기고, 동기화 칸은 문제·꺼짐·일시 정지일 때만 남긴다.

B안(담당별 묶음: 이 PC · 캐릭터 · 서버 · 갱신, 머리에 정지)은 주인과 순서가 잘 보이지만 머리가 늘 붙어 같은 일이 3~4줄 길어진다. "무엇이 돌고 있는지"에 가장 짧게 답하는 A를 추천한다.

### 할 일: A안 (머리에 ＋ · 복사 · ⋯ 항상 보임)

- 마지막 섹션 아래의 면·테두리 있는 `섹션 추가` 버튼을 없애고, 섹션 머리의 복사·⋯ 앞에 같은 28px 조용한 ＋ 아이콘(`아래에 섹션 추가`)을 둔다. ⋯도 글자 대신 `EllipsisHorizontalIcon`으로 맞춘다.
- ＋는 **누른 섹션 바로 아래**에 새 섹션을 만들고 이름 입력을 연다(마지막 섹션에서 누르면 지금과 같은 결과).
- 이름 있는 섹션이 아직 없는 메모는 머리가 없으므로, 첫 섹션을 만들 길로 `＋ 항목 추가`와 같은 조용한 글자 버튼 `＋ 섹션 추가`(faint, meta 12, 면·테두리 없음)만 남긴다. 첫 섹션이 생기면 사라진다.
- B안(세 아이콘을 머리에 포인터·포커스가 있을 때만 보이기)은 가장 조용하지만 지금 늘 보이던 복사·⋯까지 숨는다.

## 사용자가 정할 것

1. 작업 칸 A안(상태별 한 목록) / B안(담당별 묶음) — 추천 A.
2. 머리 버튼 숫자: 직접 시작한 일만(추천) / 배경 일까지(거의 늘 `작업 N`이 뜸).
3. 최근 끝남: 둔다(추천, 1시간 · 10개, 접힘) / 뺀다.
4. 동기화 칸의 `동기화 중 · N개 남음`을 작업 칸으로 옮기기 — 추천 옮김.
5. 할 일 A안(늘 보임) / B안(포인터가 있을 때만) — 추천 A.
6. ＋의 위치: 누른 섹션 바로 아래(추천) / 늘 맨 끝(지금 동작).

## 태블릿

- 작업 칸의 일은 모두 PC에서만 돈다. 태블릿에는 상태 패널이 없으므로 이번 라운드에 태블릿 화면은 바뀌지 않는다. 행 부품은 공용 조각으로 만들어 두어 나중에 서버 쪽 일을 보여 줄 때 쓴다.
- 할 일은 태블릿도 같은 `MemoEditor`를 써서 같은 라운드에 바뀐다. 세 아이콘은 44 터치 영역, B안을 골라도 태블릿은 늘 보임, `섹션 추가` 줄은 높이 44.

## 구현 메모 (작업 칸)

`index.html` 2절에 코드에서 찾은 배경 작업 32개와 지금 표시 여부를 표로 정리했다. 그중 10개만 지금 작업 칸에 나온다. 나머지는 상태를 읽을 길이 없거나(레퍼런스 보강, 보조 인식 준비, 학습 인식 점수, 아트워크 썸네일 채우기, 표지 초점, 태블릿용 게시 lane들, 신간 확인 진행, 캡처 받기, 썸네일 새로고침, 화풍 순위) 설정 화면에서만 읽는다(Claude 자동 판단 `claude_status`, 과거 이미지 점수 `character_shadow_backfill_status`, 영상 유사 검사 `latest_video_similarity_scan`).

- 화면이 작업마다 따로 묻지 않도록, 네이티브 쪽에 한 번에 읽는 활동 목록(예: 각 작업의 종류 · 상태 running/queued/paused/failed/done · 처리 수 · 전체 수 · 이유 · 시작/끝 시각)과 바뀔 때 한 번 오는 이벤트를 두는 편이 맞다. 폴링을 늘리지 않는다.
- 캐릭터 담당자의 순서(`character_incremental.rs`: 보강 → 새 이미지·재검토·수동 → 과거 갱신 → 보조 인식 → 학습 인식 점수 → 과거 점수 채우기 → Claude)와 공용 정지(`character_autotag_control.paused`)를 그대로 쓴다. 지금 일시 정지 버튼은 재검토·과거 갱신이 있을 때만 생기는데, 새 행에서는 캐릭터 행마다 같은 정지를 쓴다.
- 할 일 ＋를 "누른 섹션 아래"로 하면 `addMemoSection`에 위치 인자가 필요하다. 지금 `.memo-section-head .ui-button { margin-left: auto }`는 버튼마다 걸려 있어 버튼이 늘면 벌어지므로, 세 버튼을 한 묶음(`.memo-section-actions`)으로 감싸 묶음에만 건다.
