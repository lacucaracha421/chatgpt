USER-REQ-20260926B · 전송(보내기/받기) 재설계 목업 — 태블릿 800 × 1280 · PC 1680 × 1050

PC 앱과 태블릿이 같은 디자인 언어를 쓰는 전송 화면 세 가지 방향입니다. 앱의 실제 색·글꼴·반경 토큰을 그대로 썼고, 파일 이름·크기·시각은 모두 가상입니다. 각 방향마다 작업 중 화면(보내는 중 진행률, 받는 중·받기 대기, 저장된 파일 열기, 실패와 재시도, 여러 파일 묶음, 폴더 zip)과 빈 화면을 태블릿과 PC로 보여 줍니다. 노란 NEW 표시는 지금 데이터나 동작에 없는 것이라 구현 때 새로 만들어야 하는 부분입니다.

지금 동작 (목업이 지키는 전제)

  • 전송 한 건 = 파일 한 개. 여러 개를 고르면 같은 batchId의 여러 건이 됩니다(한 번에 최대 100개).
  • 폴더 보내기는 보내는 기기에서 zip 하나로 압축(압축 중 → 업로드). 읽지 못한 항목은 빼고 “N개 제외”로 표시.
  • 파일당 최대 2GB, 서버 보관 합계 10GB. 받으면 서버에서 바로 삭제, 안 받으면 24시간 뒤 만료, 보낸 기록은 7일.
  • 받기는 자동 저장: PC는 트레이에서도, 태블릿은 앱이 열려 있을 때 다운로드/Lakomics 폴더로. 저장 후 “열기”(PC는 “폴더에서 보기”도).
  • 네트워크·서버 오류는 자동 재시도(버튼 없음). 업로드 중단·손상·저장 공간 부족 등은 재시도 / 취소(받지 않기).
  • PC는 창에 끌어 놓기로도 보냄. 태블릿은 다른 앱의 공유 메뉴 → Lakomics로도 보냄. 기기 전용 토큰이 필요(이 화면들 밖의 설정 흐름은 그대로).

A대화형 타임라인 — 기기끼리 주고받은 파일이 대화처럼 쌓임

상대 기기 하나를 고르면 그 기기와 주고받은 모든 파일이 시간순으로 한 줄에 쌓입니다. 내가 보낸 것은 오른쪽, 받은 것은 왼쪽. 한 번에 보낸 여러 파일은 한 덩어리(묶음 진행률 + 썸네일 줄)로, 폴더는 zip 한 건으로 보입니다. 보내기는 아래쪽 입력줄(파일 · 폴더)과 PC의 끌어 놓기. 지금 무엇이 오갔는지 맥락으로 읽기 좋음, 다만 “받은 파일만 모아 보기”는 약함.

구현: 기존 스냅샷의 incoming/outgoing(태블릿) · outgoing/incoming/received(PC)를 상대 기기별로 합쳐 시간순 정렬 — 데이터는 대부분 있음(peer, createdAt, receivedAt, batchId). NEW: PC 스냅샷의 보낸/받은 행에 batchId와 상대 deviceId(지금은 이름만) · 묶음 단위 진행률 합산(클라이언트 계산) · 이미지 썸네일(보낸 쪽은 원본, 받은 쪽은 저장된 파일에서 로컬 생성, 서버 변경 없음) · 태블릿 받은 행의 저장 시각. 기기 목록의 “받는 중 2” 같은 기기별 개수는 클라이언트 계산.

B받은 파일 / 보낸 파일 두 칸 — 지금 화면의 정돈판

PC는 본문을 받은 파일 | 보낸 파일 두 칸으로 나누고, 태블릿은 같은 두 칸을 가운데 밑줄 탭(컬렉션 유형 탭 B와 같은 모양)으로 바꿉니다. 탭과 상관없이 지금 오가는 것이 위에 고정 줄로 보이고, 목록은 “받기 대기 · 오늘 · 어제”로 나뉩니다. 여러 파일은 접히는 묶음 한 줄. 보내기는 태블릿 아래쪽 막대(받는 기기 + 폴더 + 파일 보내기), PC는 보낸 파일 칸 머리. 지금 구조와 가장 가까워 위험이 적음.

구현: 지금 스냅샷 그대로 거의 충분(행 상태·진행률·재시도/취소·열기·폴더에서 보기). 받는 기기 선택을 PC 인덱스의 기기 목록으로, 태블릿은 아래 막대의 선택기로. NEW: 묶음 접기(PC 스냅샷에 batchId 추가 필요, 태블릿은 이미 있음) · 날짜 구분(태블릿 받은 행 저장 시각) · 기기의 마지막 접속 표시(태블릿은 lastSeenAt 있음, PC 스냅샷에는 없음).

C끌어 놓기 + 대기열 카드 + 받은 파일 갤러리 — 보내는 동작이 주인공

맨 위에 보낼 곳(큰 기기 슬랩, 선택은 아이보리 슬랩 + 1px 잔상)과 크게 고르는 버튼(PC는 넓은 끌어 놓기 영역). 가운데는 묶음 단위 대기열 카드 — “사진 12개 · 7/12”처럼 합산 진행률과 단계(압축 → 확인 → 업로드 → 상대가 받음)를 보여 줍니다. 아래는 받은 파일 갤러리: 이미지는 썸네일, 그 밖은 확장자 타일. 미디어 아카이브답게 받은 그림이 눈에 먼저 들어옴. 여러 파일을 zip 하나로 묶어 보내기 선택지도 여기서 제안.

구현: 가장 많은 새 작업. NEW: 묶음 합산 카드(batchId, 묶음 전체 크기·완료 수) · 단계 표시(PC는 zipping/hashing/uploading/waiting 상태가 있음, 태블릿은 zipping/preparing/uploading/ready) · 받은 이미지 썸네일(로컬 생성, 서버 변경 없음) · 여러 파일을 zip으로 묶기 옵션(지금 zip은 폴더 보내기만; PC/태블릿 zip 코드를 재사용하되 합계 2GB 한도 동일) · 끌어 놓을 때 개수 미리보기(Tauri drop 이벤트의 경로 수로 가능).
