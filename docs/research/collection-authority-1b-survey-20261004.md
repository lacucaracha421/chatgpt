**2. Server gaps**

- Command fields omit `status/ownedPlatform`, mutable type, ranges and tracking. `saveAvDetails` is **not implemented**, despite appearing in the design; dispatch contains no AV/person commands (`A:119`, `154`, `1755`).
- Staging accepts spine, AV/credits/people, focus and published volume values; commands do not. Add their validation, revisions, change events and replica materialization—not just storage (`A:2170`, `2193`, `2228`, `2245`).
- `selectArtwork` changes only work selection. Explicit staged artwork `selected` overrides slot-derived selection, producing disagreement. Update flags atomically; support spine/back semantics (`A:938`, `1581`, `1925`).
- Artwork/volume feed projections omit new selected/order/focus/published fields; people lack a feed section and entity revision (`A:835`, `850`, `393`, `2829`).
- Tracking needs count replacement, explicit-zero tracking, subscriptions, event acknowledgement and refreshed derived schedules; existing ownership is per-volume only (`A:140`, `1691`, `1978`).
- Personal-edit shim must accept tracking and records, preserve receipts/conflicts and advertise capabilities correctly. Currently active authority rejects both; shim maps only score/showcase/memo. “v3” is handshake capability; request `version` remains `1` (`collection_personal_edits.py:148`, `373`, `420`; `A:2783`).
