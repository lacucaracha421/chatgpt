# Lakomics approved chrome direction — B 좌측 중심 / Codex handoff

## 2026-09-06 후속 UX 보정 — 아래의 이전 표현보다 우선

사용자가 열 가지 보정 항목의 계획·구현을 요청했다. B의 레일/인덱스 구조는 유지하며 다음 항목은 이전 상시 요약·문구 규칙을 대체한다.

- 창 제목의 브랜드/부제, 인덱스의 반복 영역 제목/내 라이브러리, 보기 설정 요약과 안내 문장을 상시 표시하지 않는다. 필요한 조작명·검색 해제·오류·진행 상태는 보존하고 부가 힌트는 툴팁으로 제공한다. 하단 자산 수·파일 드롭 안내는 제거하고 실제 작업 진행/오류 때만 상태 영역을 표시한다.
- 정보 표시는 기존 기본값 `true`를 유지한다. 조작명은 **정보 숨기기**, 체크 상태는 `!metadataVisible`이다. 기존 저장된 가시성 값을 뒤집어 해석하거나 재설정하지 않는다.
- 사이드바는 각진 기하학 선 아이콘과 중성색 직각 트리 연결선을 사용한다. 사용자 지정 분류의 이름·아이콘 키·색과 탐색 동작은 유지한다.
- 컬렉션의 정렬/방향/전체 별점 범위, 카탈로그의 언어/정렬/숨김 표시/관리 진입은 인덱스에 배치한다. 이 화면에는 비활성 보기 설정 버튼을 남기지 않는다. 에셋의 보기 설정은 기존 플로팅 패널을 유지한다.
- 컬렉션·로컬 망가·온라인 카탈로그 검색은 사이드바 돋보기에서 연다. 카탈로그 상단 검색창 예외는 없다. 기존 검색 범위·자동완성·적용/해제 계약을 유지하며, 에셋의 미지원 텍스트 검색 엔진을 새로 도입한 것은 아니다.
- 에셋 선택은 기존 좌상단 사각 표식을 유지하고 이미지에만 중성 회색 음영을 적용한다. 선택 외곽선과 작가/시간 영역의 색·여백 변화는 제거한다. 키보드 초점 표시는 선택과 별도로 유지한다. 빠른 미리보기 아이콘은 이미지 내부에 두고 정보 영역과 겹치지 않는다.
- 게임 표지는 이미지 로딩 전에도 동일한 입체 케이스 투영으로 빈 쉘을 그린다. 평면 표지가 먼저 노출되는 fallback은 사용하지 않는다. 기존 DPR 보정·오프스크린 캔버스 해제·표지 오류 처리를 유지한다.

검증: 관련 10개 파일의 고유 테스트 221개 통과(재실행 중복 제외), TypeScript 통과. 메모리 gateway로 실제 React 화면을 렌더링해 사이드바 검색, 6→2개 카탈로그 결과, 정보 표시, 선택 외곽선 제거, 돋보기/시간 분리 및 800×640 창의 가로 넘침 없음을 확인했다. 네이티브 프로세스 응답은 확인했으나 실제 라이브러리 데이터·파일 대화상자·OS 조작 수용 검증을 대신하지 않는다.

> 상태: 사용자가 Chrome 03b를 좋아한다고 확인하고 문서화를 요청한 탐색 구조·표현 기준.
> 기준일: 2026-09-06 (Asia/Seoul). 원본: `lakomics_chrome_structure_lab_03b.html`.
> 최초 요청은 문서 작성이었다. 이후 2026-09-06 사용자가 이 문서 기반의 실제 앱 개편과 사소한 UX 판단을 승인하여 아래 구현 체크포인트를 반영했다. commit/push, 배포, 운영 데이터 변경은 여전히 별도 승인 대상이다.

## 1. 채택한 방향과 문서의 역할

**좁은 좌측 영역 레일 + 현재 영역의 탐색 인덱스 + 넓은 자료 화면**을 사용한다. 상단에 나열하던 이동·검색·보기 도구를 왼쪽에 정리하고, 보기 설정만 필요할 때 독립적인 플로팅 패널로 연다. 분류 트리는 계속 보인다.

- B 좌측 중심을 채택한다. A의 상단 중심, C의 분류 서랍, Chrome 02의 기존 위치 보존안은 이번 구현의 경쟁 후보가 아니다.
- **03b가 기준이다.** 03 B의 항상 펼쳐진 하단 보기 설정은 최종 형태가 아니다.
- 검색은 상시 입력창이 아니라 돋보기로 시작한다. 자료의 보관·탐색·분류가 장식이나 검색창보다 우선한다.
- 기존 `docs/agents/approved-design-direction.md`는 콘텐츠와 공통 선택 색·물성의 기준이다. 이 문서는 그 위에 놓이는 PC 탐색 shell과 일시적인 도구 표면의 기준이다. 콘텐츠 방향을 재투표하지 않는다.
- `DESIGN.md`의 위임 범위에서 이 문서의 배치 규칙을 우선한다. 도메인·안전·기존 데이터 소유권과 이 문서가 다루지 않는 디자인 규칙은 유지한다.
- 사용자의 “기능 유지하란 것 무시”는 **위치·그룹·노출 방식의 재구성 허용**으로 반영한다. 기존 명령을 모두 같은 자리에 둘 필요는 없지만, 파일/데이터 기능을 조용히 삭제하거나 의미를 바꾸라는 허가는 아니다.
- 승인된 시각 방향과 실제 기능 동등성·성능·접근성 검증은 구분한다. 이 문서나 HTML만으로 구현 상태를 DONE 처리하지 않는다.

### 이전 제약과의 관계

| 이전 표현 | 이번 적용 |
| --- | --- |
| 사이드바·상단바의 위치와 모든 슬롯을 그대로 유지 | 위치와 묶음은 B 구조로 재편한다. 사용 중 갑자기 슬롯이 밀리거나 선택에 따라 레이아웃이 흔들리지 않는다는 안정성 원칙은 유지한다. |
| 사이드바와 상단바 후보는 항상 독립 축 | 이번에는 사용자가 두 영역을 함께 재설계하도록 요청했다. B 전체 구조를 하나의 채택 대상으로 보되, 콘텐츠 디자인까지 임의로 바꾸지 않는다. |
| 상단의 상시 검색창 | 왼쪽 인덱스 머리의 검색 아이콘 → 필요할 때 입력 UI. 검색 중임을 알리는 표시와 해제 경로는 남긴다. |
| B 하단에 정렬·필터·크기 상시 노출 | 하단에는 보기 설정 버튼과 요약만 둔다. 실제 조절은 오른쪽에 뜨는 패널에 모은다. |
| 분류도 함께 접히는 서랍 | 채택하지 않는다. 보기 설정을 닫아도 레일·분류·앨범은 그대로 남는다. |

## 2. 화면의 구조

```text
┌────────┬─────────────────────┬──────────────────────────────────┐
│ 영역   │ 현재 영역 이름  ⌕ + │ 얇은 창 제목 영역 / 창 제어       │
│ 레일   ├─────────────────────┼──────────────────────────────────┤
│        │ 문맥별 범위/유형    │ 현재 위치 · 검색 적용 상태 · 수량 │
│ 에셋   │                     ├──────────────────────────────────┤
│ 컬렉션 │ 분류 폴더 / 앨범    │                                  │
│ 망가   │ 독립 스크롤         │       기존 승인 콘텐츠 화면      │
│        │                     │                                  │
│        │                     │  ┌──────────────────┐            │
│ 휴지통 ├─────────────────────┤  │ 보기 설정 패널   │            │
│ 관리   │ 보기 설정  요약  ⋯  │  │ 필요할 때만 겹침 │            │
└────────┴─────────────────────┴──┴──────────────────┴────────────┘
```

위 도식은 역할 관계다. 패널은 고정된 별도 열이 아니며, 열기·닫기로 본문 폭을 줄이지 않는다.

| 영역 | 담당 역할 | 두지 않을 것 |
| --- | --- | --- |
| 가장 왼쪽 레일 | 에셋·컬렉션·망가의 큰 영역 이동. 아이콘과 짧은 이름. 하단의 휴지통/관리 진입 | 전체 폴더 트리, 길게 펼친 검색, 모든 설정의 상시 나열 |
| 인덱스 머리 | 현재 영역 이름, 검색 아이콘, 추가 진입 | 같은 기능을 다시 상단 툴바에 중복 배치 |
| 인덱스 본문 | 현재 영역에 맞는 범위·분류·앨범 또는 작품 유형. 낮은 대비의 수량 | 분류 폴더 이름을 고정 제품 유형으로 해석하는 분기 |
| 인덱스 하단 | 고정된 보기 설정 버튼, 짧은 상태 요약, 보조 명령 | 접기 전에도 모든 필터가 보이는 큰 상시 설정 폼 |
| 본문 상단 | 작은 창 제목 영역과 창 제어, 현재 위치·필요한 검색 상태·수량 | 예전의 전체 수평 툴바를 그대로 중복 재생성 |
| 자료 영역 | 기존 승인 갤러리/컬렉션/상세, 필요할 때의 선택 작업 바 | 장식 패널, 샘플 비교용 안내·통계·반응 입력 UI |

레이아웃을 게임 메뉴가 아니라 아카이브의 작업 공간으로 읽히게 한다. 에셋을 중심 진입점으로 두되, 기존 앱의 저장된 시작 위치/복원 정책을 임의로 무시하지 않는다. 프로토타입의 “개인 라이브러리” 같은 반복 부제나 장식용 큰 제목을 모든 화면의 필수 요소로 삼지 않는다.

## 3. 보기 설정 패널 — 핵심 동작 계약

### 열기와 배치

- 기본 상태는 닫힘이다. 인덱스 맨 아래의 **보기 설정** 버튼으로 연다.
- 패널은 버튼이 있는 인덱스의 **오른쪽**, 본문 위에 겹쳐 뜬다. 기본은 버튼 하단을 기준으로 위치를 잡되 화면 안에 들어오도록 조정한다.
- 모달 화면이나 별도 OS 창이 아니다. 분류를 덮는 전체 화면 차단막도 만들지 않는다.
- 좁거나 낮은 창에서는 패널 위치와 최대 크기를 제한하고 패널 내부를 스크롤한다. 닫기와 현재 조작에 접근할 수 있어야 한다. 공간 확보를 위해 분류 트리를 숨기거나 본문 열 수를 바꾸지 않는다.
- 인덱스의 탐색 부분만 스크롤하고, 보기 설정 진입은 하단에 남긴다.

### 닫기와 값 유지

| 입력/상황 | 처리 |
| --- | --- |
| 같은 보기 설정 버튼 재클릭 | 닫기 |
| 패널의 닫기 버튼 | 닫기, 보기 설정 버튼으로 초점 복귀 |
| `Esc` | 가장 안쪽 열린 메뉴부터 닫는다. 패널을 닫는 동작은 값 취소가 아니다. 같은 입력이 자산 선택 해제/뷰어 종료까지 전파되지 않게 한다. |
| 바깥 클릭 | 닫되 클릭한 대상의 정상 동작은 유지한다. 배경 클릭을 일괄 삼키거나 의도하지 않은 별도 명령을 발생시키지 않는다. |
| 영역·분류 이동, 다른 메뉴/대화상자 열기 | 설정 패널은 닫고 새 문맥으로 이동한다. 설정값 자체는 기존 소유 범위에 남긴다. |
| 키보드 초점이 패널/트리거 밖으로 이동 | 비모달 패널을 닫는다. 패널이 연 하위 팝업/포털로의 초점 이동은 내부 조작으로 취급한다. |
| 패널 안의 정렬·필터·슬라이더 변경 | 변경을 즉시 반영하며 패널은 유지한다. 매번 입력 UI를 다시 만들어 초점/드래그를 잃지 않는다. |

**단순히 열고 닫을 때** 갤러리 폭·열 수·타일 배치·본문 스크롤·트리 펼침과 스크롤·현재 선택을 바꾸지 않는다. 정렬·필터·크기 등 **실제 값을 변경했을 때** 관련 결과나 배치가 달라지는 것은 정상이며 기존 앱 계약을 따른다.

`적용`/`저장`을 매번 누르게 하지 않는다. 패널을 닫는다고 설정을 되돌리거나 필터를 초기화하지 않는다. 다만 닫힘 상태와 설정값의 저장 범위를 구분한다. 참조 HTML은 페이지 세션 안에서 값만 유지하므로, 이를 근거로 새 영구 설정 파일/DB 컬럼을 만들지 않는다. 기존 `uiPreferences`와 뷰별 상태 소유권을 먼저 확인한다.

### 내용과 요약

패널은 **현재 화면의 보기 설정**이지 앱 전체 설정창이 아니다.

| 문맥 | 옮길 설정의 범주 | 주의 |
| --- | --- | --- |
| 에셋 | 정렬, 미디어/비율 필터, 폭포수/같은 높이 배치, 미리보기 크기, 정보 표시·비공개·현재 분류만 | 최근/앨범/작가 등 현재 view에 따라 제공 가능한 설정이 다르다. 기존 조건부 동작을 확인한다. “현재 분류만”은 경로 열기가 아니다. |
| 컬렉션 라이브러리 | 정렬 기준·방향, **내 별점** 필터 | 별점은 즐겨찾기가 아니다. 실제 앱의 전체 평점 범위를 유지한다. HTML의 축약된 선택지를 그대로 가져오지 않는다. |
| 쇼케이스 | 실제로 지원하는 표시 설정만 | 수동 선별/순서를 일반 정렬·필터로 덮어쓰지 않는다. 데모의 공용 컨트롤 노출을 제품 동작으로 간주하지 않는다. |
| 로컬 망가 | 현재 구현이 제공하는 탐색/표시 설정 | 데모의 이름이나 범용 정보/비공개 토글을 근거로 새 기능을 만들지 않는다. 실제 독서 뷰어 도구와도 구분한다. |

닫힌 버튼 아래에는 `최신순 · 폭포수`, `필터 2`처럼 핵심 상태만 한 줄로 요약한다. 비공개 등 중요한 활성 상태가 묻히지 않게 하되 모든 값을 나열하지 않는다. 요약은 같은 실제 상태에서 계산하고, 패널 값과 서로 다른 복사본을 만들지 않는다.

## 4. 검색은 아이콘으로

- 왼쪽 인덱스 머리에 돋보기 하나를 둔다. 긴 검색 입력란을 상시 예약하지 않는다.
- 돋보기를 누르면 검색 입력 UI를 열고 현재 범위를 알려 준다. 검색 실행 뒤에는 입력 UI를 접고 결과를 보여 준다.
- 적용된 검색은 작은 상태 표시와 해제 동작으로 알린다. 검색 UI를 닫는 것과 적용된 검색을 지우는 것은 다르다.
- 다시 열면 현재 검색어를 편집할 수 있어야 한다. 키보드만으로 열기·입력·실행·닫기가 가능해야 한다.
- 참조의 `Ctrl+F`는 진입 방식의 예다. 실제 앱의 기존 단축키·뷰어·텍스트 입력과 충돌하지 않도록 연결한다.
- 검색의 범위·필드·쿼리 보존은 해당 화면의 현재 계약을 먼저 확인한다. HTML이 여러 자료를 같은 함수로 검색한다고 프로덕션에서 하나의 전역 검색으로 합치지 않는다.
- 기존에 없는 검색 엔진·인덱스·AI/명령 팔레트를 이번 shell 문서로 승인하지 않는다. 미지원 범위는 정직하게 처리하고 필요한 새 기능은 별도 구현 범위로 표시한다.

## 5. 미학과 공통 표면

니어를 연상시키는 것은 **사각 선택 면, 작은 표식, 절제된 선·구획과 시각적 위계**다. 게임의 HUD, 기계 장식, 스캔라인, 복고 질감, 거대한 탭을 복제하는 것이 아니다.

- 다크모드 중심의 조용한 표면, 선 아이콘, 낮은 대비의 보조 정보와 수량을 유지한다. 콘텐츠보다 레일/패널이 먼저 눈에 들어오지 않게 한다.
- 주요 단일 선택은 기존 승인 아이보리 `#DDD8CA`와 작은 사각 표식의 문법을 유지한다. 모든 하위 행과 토글까지 같은 강도로 강조하지 않는다.
- 여러 필터가 켜지는 선택 상태는 **중성 회색**, 반복 사각 표식 없음이라는 기존 규칙을 유지한다. 03b HTML의 일부 olive/green 원시 색을 복사해 누런 복수 선택을 재도입하지 않는다.
- 툴팁·메뉴·팝오버는 Chrome 02에서 호감을 받은 **얇은 경계**를 기준으로 한다. 작은 radius, 얕은 표면 구분, 필요한 부유 그림자만 사용한다.
- 짧은 툴팁을 모두 제목 있는 대화상자로 만들지 않는다. 인터랙티브 조작은 팝오버/메뉴, 파괴적 확인은 기존 대화상자의 역할을 유지한다.
- 선택과 키보드 초점을 분리한다. 아이콘 버튼의 이름, 열린 상태, 선택 상태, disabled와 위험 동작을 공통 UI 방식으로 드러낸다.
- 전역 폰트 교체·새 아이콘 패키지·전역 녹색/베이지 테마는 승인하지 않았다. 반복 수치는 기존 디자인 토큰에 역할별로 연결한다.

### 참조 치수 — 조정 가능한 출발점

HTML에서 확인한 값은 레일 70px(좁은 창의 예 61px), 창 제목 영역 33px, 인덱스 머리 83px, 보기 설정 패널 318px, 패널과 인덱스 사이 8px, 화면 가장자리 여유 12px다. **이 수치나 breakpoint를 제품의 고정 규격으로 승인한 것이 아니다.** 기존 사용자 너비 설정, 글자 확대, 긴 이름과 창 크기에 맞춰 동일한 위계를 유지한다.

## 6. 에셋 저장소의 역할과 기존 기능의 연결

위치를 바꾸되 도메인을 합치지 않는다.

- **에셋**: 전체 자산, 미분류, 다시보기, 사용자 분류와 앨범을 쉽게 오갈 수 있게 한다. 분류/앨범은 파일의 실제 보관 경로가 아니다.
- **컬렉션**: 라이브러리/쇼케이스와 게임·만화·영화 구분을 인덱스로 모은다. 작품 아트워크를 자동으로 자산으로 편입하지 않는다.
- **망가**: 로컬 망가 루트·시리즈 탐색 영역이다. 컬렉션 유형 “만화”, 사용자가 이름 붙인 분류 “만화”, 온라인 카탈로그를 같은 항목으로 합치지 않는다.
- **추가**: 인덱스 머리의 `+`에서 현재 문맥에 맞는 실제 가져오기/작품 추가 흐름으로 연결한다. 분류/앨범 생성과 자산 수집은 별개다.
- **선택 작업**: 자산 다중 선택은 본문의 별도 선택 바/컨텍스트 메뉴에서 처리한다. 선택 때문에 레일·본문 머리·창 제어가 밀리지 않는다.
- **관리**: 휴지통, 유사 검토, 앱 설정은 레일 하단이나 조용한 관리 메뉴로 접근한다. 그 밖의 기존 목적지는 현재 App의 라우팅을 확인해 접근 경로를 보존한다.
- **폴더/앨범 명령**: 생성·이름·아이콘/색·이동·삭제·드래그·키보드 탐색의 실제 의미와 데이터 보호를 유지한다. 상위 폴더 삭제 제한 등을 데모용 조건으로 대체하지 않는다.
- **창 제어**: 얇은 제목 영역에 실제 최소화/최대화/닫기와 드래그 가능 영역을 남긴다. 입력·메뉴·슬라이더 조작이 창 드래그로 처리되지 않게 한다.

프로토타입에서 보이지 않는 기능을 자동 폐기하지 않는다. 반대로 기존 기능 수를 채우려고 예전 툴바를 다시 붙이지도 않는다. 구현 범위 안의 기존 명령은 **새 진입 위치 / 문맥 / 기존 callback**으로 대응시키고, 실제로 없앨 기능이 필요하면 별도 결정으로 분리한다.

## 7. 구현 연결 원칙

이 문서는 새 앱이나 framework를 만드는 명세가 아니다. React/Tauri, 현재 공통 UI와 데이터 소유 구조에 의도를 옮긴다. HTML 전체 삽입, 샘플 상태 객체의 이식, 화면별 메뉴 재구현은 하지 않는다.

다음 경로는 문서 작성 시 존재를 확인한 진입점이다. 현재 코드와 미커밋 변경을 다시 읽고 정확한 책임을 확인한다.

| 책임 | 진입 경로 |
| --- | --- |
| 영역 라우팅과 shell | `app/src/app/App.tsx`, `app/src/layout/ViewToolbar.tsx`, `app/src/layout/WindowControls.tsx` |
| 인덱스·분류·앨범·너비 | `app/src/classification/ClassificationSidebar.tsx`, `app/src/layout/sidebarWidth.ts` |
| 에셋 보기 도구와 선택 작업 | `app/src/assets/AssetToolbar.tsx`, `app/src/assets/SelectionBar.tsx` 및 기존 Browser/Gallery |
| 작품 문맥과 독서 영역 | `app/src/collections/CollectionBrowser.tsx`, `app/src/manga/MangaBrowser.tsx` |
| 공통 표면 | `app/src/shared/ui/Menu.tsx`, `ContextMenu.tsx`, `Dialog.tsx` 및 관련 기존 primitive |
| 설정과 시각 토큰 | `app/src/preferences/uiPreferences.ts`, `app/src/styles/tokens.css`, `app/src/styles/global.css` |

권장 연결 순서는 현재 명령/문맥/상태 소유권 확인 → B shell의 진입 위치 재구성 → 보기 설정 팝오버 → 아이콘 검색·공통 표면 → 관련 상태 회귀 점검이다. 이는 의존 관계의 안내이며 새 작업 우선순위표가 아니다. 구체적인 진행 상태는 기존 living backlog 한곳에서 관리한다.

상태는 UI가 보이는 위치와 분리한다. 패널 unmount로 값이 사라지거나, 에셋 필터가 컬렉션에 누출되거나, 검색/영역 이동마다 동일 자료를 불필요하게 다시 가져오지 않게 한다. 단순 패널 토글에 갤러리 전체 재생성·렌더러 재초기화·원격 요청을 결합하지 않는다.

기존 공통 팝오버/메뉴가 부족하면 해당 primitive의 실제 필요 변형을 추가한다. 포털을 사용하는 하위 select/menu가 바깥 클릭으로 잘못 분류되어 부모 패널을 닫지 않도록 하고, 비모달 패널에 불필요한 전체 화면 focus trap을 만들지 않는다.

## 8. 구현 시 수용 기준

아래는 향후 구현에서 확인할 기준이다. 이번 문서 작성으로 통과했다는 뜻이 아니다.

1. **구조**: B의 레일과 인덱스가 남고 기존 전체 수평 툴바는 중복되지 않는다. 에셋이 충분한 화면을 차지하며 큰 제목/장식이 자료를 밀어내지 않는다.
2. **설정 개폐**: 버튼·닫기·Esc·바깥 클릭·초점 이동이 일관된다. 설정 변경 중에는 패널/포커스가 유지되고, 닫고 다시 열어도 값은 남는다.
3. **무변경 토글**: 설정을 단순 개폐할 때 갤러리 폭/배치/스크롤/선택과 인덱스 상태가 달라지지 않는다. 하위 메뉴에서의 Esc가 자산 선택까지 지우지 않는다.
4. **문맥**: 자산/컬렉션/쇼케이스/망가의 허용된 설정이 다르게 연결된다. 전체 별점 범위, 정렬 방향, 조건부 현재 분류만과 수동 쇼케이스 순서가 유지된다.
5. **검색**: 평소 아이콘만 보인다. 현재 범위와 적용 상태가 분명하며 입력 창 닫기와 검색 해제가 구분된다. 지원하지 않는 검색을 가짜 결과로 보여주지 않는다.
6. **표면·색**: 얇은 경계, 아이보리 단일 선택과 중성 회색 복수 선택을 유지한다. 긴 이름/정보, 비활성·위험·초점 상태도 읽힌다.
7. **창/접근성**: 좁거나 낮은 창, DPR 1.125/1.25 등 실제 사용 조건에서 도구가 잘리지 않는다. 트리 키보드·메뉴 초점·창 드래그/버튼의 기존 동작을 보존한다.
8. **기존 콘텐츠/데이터**: 날짜별 폭포수의 작가/HH:mm, 닫힌 케이스와 경계 품질, hero/표지/빈 배경 배치를 바꾸지 않는다. 파일·provider·삭제/복구·원본 보존 규칙에 새 동작을 섞지 않는다.

현재 작업은 문서뿐이므로 앱 전체 테스트나 production build는 하지 않는다. 이후 구현은 `AGENTS.md`의 위험 기반 검증을 따르고, 브라우저 표현·네이티브 Tauri·운영 데이터 검증을 구분해 보고한다. 실제 데이터에 테스트 쓰기나 완료된 backfill 재실행을 하지 않는다.

- `app/src/layout/SearchSurface.tsx` / `ChromeSearch.tsx`: 돋보기 진입, Ctrl+F, 입력 초안 취소와 적용/해제 구분. 컬렉션·로컬 망가의 실제 검색과 온라인 카탈로그의 기존 자동완성 입력을 연결한다.
- `AssetToolbar`, `CollectionBrowser`, `MangaBrowser`, `OnlineCatalogBrowser`: 기존 제어값과 콜백을 연결하고 정렬/필터/크기를 보기 설정으로 이동. 컬렉션의 0~5점 전체 별점과 쇼케이스 조건부 노출을 보존한다. 카탈로그 전송·DB·조회 엔진은 변경하지 않는다.
- `App.tsx` / `ViewToolbar`: 공통 창 제어는 상단에 한 번만 유지한다. 특수 화면의 작업 도구는 해당 문맥 내부에 유지하며, 일반 자산/컬렉션/망가의 이전 상시 도구 행은 새 shell로 옮긴다.
- `useFileDrop`: 명시적 파일 선택도 기존 순차 수집 큐와 선택 분류를 사용한다. 새로운 수집/중복 판정 경로를 만들지 않는다.
- `TooltipLayer`, `styles/chrome.css`: 명시적 아이콘 힌트만 얇은 경계로 표시하고 키보드 초점/설명 연결을 제공한다. 주요 선택 아이보리와 복수 필터의 중성 회색은 유지한다.

### 경계와 UX 확인

자산의 기존 query 계약에는 텍스트 검색이 없다. 이번 shell 구현에서 가짜 전역 검색이나 새 검색 엔진을 만들지 않았으며, 지원되지 않는 화면의 검색 아이콘은 비활성/설명 상태다. 컬렉션·로컬 망가·온라인 카탈로그에서는 실제 검색 경로를 연결했다.

설정 변경은 기존 화면 state와 preference 소유권을 따른다. 패널의 개폐 상태 자체는 저장하지 않으며 다른 범위로 이동하면 닫힌다. 검색 창 취소는 입력 초안을 버리되 적용된 검색을 지우지 않는다. 일반 필터 조작·정렬 변경과 단순 패널 개폐를 구분한다.

### 검증 기록

- `node node_modules/typescript/bin/tsc --noEmit`: 통과.
- focused Vitest 8개 파일 127개 테스트 통과: `App`, `WorkspaceChrome`, `AssetToolbar`, `ViewToolbar`, `useFileDrop`, `MangaBrowser`, `OnlineCatalogBrowser`, `ContextMenu`. 패널 개폐/제어값/선택/갤러리 마운트 보존, 중첩 메뉴/Esc, 검색 취소·적용, 파일 선택의 기존 큐 연결과 실제 앱 탐색을 포함한다.
- 앞선 영향 범위 점검에서 `ClassificationSidebar` 47개와 `CollectionBrowser` 22개 기존 테스트도 통과했다. 중복 실행 건수를 합쳐 전체 테스트 수처럼 보고하지 않는다.
- 별도의 Edge headless 프로필, loopback Vite 서버, 메모리 gateway fixture로 실제 React 앱을 렌더링했다. 1476×1000 / 800×640, DPR 1.25에서 설정 패널이 화면 밖으로 나가지 않으며 상단바 때문에 생긴 수평 overflow를 제거했다. 동일 범위에서 패널 전후 갤러리 폭은 1170px로 유지되었다. 실제 컬렉션 검색 입력/적용으로 fixture 결과가 12개에서 2개로 바뀌고 검색창은 닫혔다.
- 이 브라우저 검증은 운영 라이브러리·실제 미디어 프로토콜과 연결하지 않았다. fixture의 비공개 썸네일을 사용했으며 native Tauri 파일 대화상자, OS 창 제어, 실제 드래그 및 운영 데이터 성능의 수용 검증을 뜻하지 않는다.
- 기존 미커밋 작업은 보존한다. 이 구현 요청으로 commit/push/배포를 수행하지 않는다.

브라우저 검증 환경 메모: 초기 HMR 시 검증용 native-event shim에 `unregisterListener`가 없어 Tauri event 해제에서 예외 1건이 기록되었다. 실제 native runtime이 아닌 테스트 shim의 범위 한계이며, 이를 운영 앱의 native 통과 근거로 사용하지 않는다. 최종 레이아웃/검색 확인은 fixture 응답을 보완하고 페이지를 다시 로드한 상태에서 수행했다.
