# Lakomics approved design direction — Codex handoff

> 상태: 사용자 승인된 시각 방향. 최종 6차 반영본에 대해 "올그린" 확인.
> 비교 보드 표기일: 2026-09-05. 승인 인계 문서 작성일: 2026-09-06 (Asia/Seoul).
> 이번 변경은 문서화와 문서 커밋뿐이다. 앱 구현, 배포, 데이터 변경의 완료를 뜻하지 않는다.

## 1. 적용 범위와 우선순위

이 문서는 여러 레퍼런스와 1~6차 비교를 거쳐 승인된 PC Lakomics의 시각 방향이다. 취향 탐색은 종료한다. 이전 반응표의 "최종 채택 아님"은 탐색 당시의 상태이며, 이후 사용자의 올그린 승인을 취소하는 문구가 아니다.

- 승인 대상은 영역별 표현과 마지막 보정 결과다. 전체 앱을 합성한 최종 화면, 성능 수치, 접근성 적합성 또는 실제 Tauri 동작을 승인한 것은 아니다.
- 5차에서 사용자가 별도로 언급하지 않은 조건은 괜찮았던 것으로 유지한다. 이미 수용된 항목을 다시 미결정으로 돌려 반복 비교판을 만들지 않는다.
- 서로 다른 레퍼런스를 성급하게 섞지 않는다는 원칙은 유지한다. 구현에서는 승인된 표현을 기존 공통 구조 안에 단계적으로 연결하며, 새 테마나 독자적인 재디자인을 발명하지 않는다.
- `DESIGN.md`가 위임하는 범위에서 이 문서가 최신 시각 기준이다. 아래 충돌표 외의 제품/구조/안전 규칙은 바꾸지 않는다.
- `CONTEXT.md`, Accepted ADR, `AGENTS.md`, `docs/agents/implementation.md`의 도메인·권한·검증 경계는 유지한다.
- 코드가 현재 구현의 근거이며, 문서의 승인 상태만으로 미구현 기능을 DONE 처리하지 않는다. 작업 상태와 우선순위는 `docs/roadmap/lakomics-backlog.md` 한곳에서 관리한다.
- Mobile, 온라인 카탈로그, Phosphor 미니게임의 별도 디자인을 이 방향으로 자동 교체하지 않는다.

### 기존 문서와의 충돌 해소

| 기존 표현 또는 해석 | 이번 승인에 따른 적용 |
| --- | --- |

| 모든 선택에 하나의 accent | 주요 위치/단일 선택은 아이보리와 안쪽 사각형, 복수 필터는 중성 회색과 표식 없는 선택 상태로 구분한다. |

| 기존 Works v6 HTML이 모든 최신 시각 기준 | 기존 파일은 제품 구조·상호작용의 참고다. 이 문서가 다룬 배치·색·케이스·겹침은 Lab 06 final 승인 방향을 우선한다. |

기존 `docs/agents/works-viewer-design.md`와 `docs/roadmap/works-collection-visual-redesign-plan.md`의 확장 기능, 데이터 계약, 우선순위를 이 문서로 일괄 승인하거나 폐기하지 않는다. 특히 Film/Series, provider 확장, 완전한 앞/책등/뒷표지 수집, 별도 Display 모드는 별도 범위다.

## 2. 전체 인상과 고정 경계

깔끔하고 미디어가 주인공인 개인 아카이브다. 다크모드 중심, 단정한 사각 컨트롤, 절제된 구획과 선 아이콘을 사용한다. 기능만 남긴 무미건조한 도구도, 오래 보면 피로한 테마 장식도 목표가 아니다.

- mymind/Cosmos에서는 자산 배치와 정돈감, Raindrop에서는 사각 구성, NieR에서는 버튼·표식과 절제된 인상을 참고했다. 제품 전체를 복제하지 않는다.
- teenage engineering에 대한 호감은 아이콘·심볼에서 출발했다. 이후 직접 비교에서는 선으로 그린 기호가 우세했다. 장비 노브, 면 아이콘, 기계 패널 도입으로 해석하지 않는다.
- Criterion/A24/Delicious Library의 소장감과 전시 방식은 매체별로 제한해 해석한다. 나무 책장, 가짜 레트로, 방 시뮬레이션, 모든 화면의 페르소나식 연출은 채택하지 않는다.
- 폰트 교체, 전역 베이지 테마, 화면 전체의 큰 radius/그림자/blur/hover 회전은 승인하지 않았다. 기존 폰트 폴백·공통 UI·토큰 체계를 유지한다.
- Assets, Collections/Works, WorkArtwork, Volume/Edition, Online Catalog, Showcase는 구분한다. 표지/배경을 자동으로 자산으로 승격하거나 provider 갱신으로 사용자 선택을 덮어쓰지 않는다.

## 3. 자산 — 날짜별 폭포수 + 작가/시각

**승인 형태:** 같은 너비·다른 높이의 masonry/waterfall. 수집일별 구획으로 나누고 이미지 바깥 바로 아래에 한 줄 정보를 둔다.

```text
오늘 · 2026.09.05                 [구획: 수집일]
[원본 비율의 이미지]
작가명                     21:30 [하단: 작가 / 수집 시각]
```

- 그룹 제목이 날짜를 맡는다. 각 이미지 아래 오른쪽에는 `HH:mm` 24시간제 시·분만 표시하고 날짜를 반복하지 않는다. 왼쪽은 작가명이다.
- 초기 반응의 이미지 안쪽 하단 오버레이는 최종안이 아니다. 이미지 아래 한 줄이 최종 승인 위치다.
- 기준은 라이브러리에 들어온 수집일(Collected At)이다. 출처 게시일, 파일 생성/수정일, 작품 출시일로 대체하지 않는다. 실제 `collectedAt` 계약과 nullable 값을 먼저 확인한다.
- 정렬, 날짜 그룹, 하단 시각, 전체 일시 표시를 같은 timestamp와 표시 시간대에서 계산한다. 프로토타입의 고정 KST/예시 시간 생성기를 앱에 복사하지 않는다.
- 같은 분에 들어온 자료도 원 timestamp와 안정적인 tie-breaker로 순서를 유지한다. `HH:mm` 문자열로 정렬하지 않는다.
- 전체 날짜·시간과 긴 작가명은 tooltip 및 키보드로 접근 가능한 기존 상세/정보 경로에서 확인할 수 있어야 한다. 마우스 hover만 유일한 정보 경로로 두지 않는다.
- 긴 작가명은 시간 영역을 밀어내지 않도록 줄임 처리한다. 작가가 없으면 작가 미상처럼 정직한 상태를 쓰고, 수집 시각이 없으면 가짜 현재 시각을 채우지 않는다.
- 들쭉날쭉한 날짜별 수량과 48개 혼합 샘플은 수용되었다. 한 날짜의 페이지 경계, 그룹 합치기, 리사이즈와 가상화에서 중복/누락/스크롤 점프가 없어야 한다.
- 현재의 같은 높이 justified 보기 자체를 싫어한 것은 아니다. 새 방향 때문에 기존 보기 선택, 검색, 정렬, 선택/드래그, 영상 프리뷰, 스크롤 복원 계약을 임의로 없애지 않는다.

## 4. 컨트롤과 아이콘

### 주요 위치 / 단일 선택

정돈된 사각 컨트롤에 안쪽의 작은 사각 표식을 사용한다. 선택 면은 옅은 아이보리 `#DDD8CA`, 그 위의 글자/표식은 어두운 색이다. 참조안의 on-selection 색은 `#202628`이다.

- 주요 탭과 단일 정렬처럼 하나의 현재 상태를 나타내는 곳의 방향이다. 모든 버튼·아이콘·상태에 아이보리를 칠하지 않는다.
- 선택과 키보드 초점은 별개다. 포커스 이동만으로 선택 상태가 바뀌어 보이거나 표시가 사라지면 안 된다.
- 안쪽 사각형 8px는 비교판 수치다. 역할·버튼 크기를 유지하면서 토큰화하고, 바깥 마름모나 복고 띠로 되돌리지 않는다.

### 복수 선택 필터

중성 회색의 낮은 밝기 선택 면을 사용하고 사각 표식은 반복하지 않는다. 누런/올리브색 선택 면은 명시적으로 거절되었다. 여러 개 선택할 일이 적더라도 이 역할 구분을 유지한다.

| 역할 | 최종 참조값 |
| --- | --- |
| Dark: 선택 배경 / 글자 / 테두리 | `#383838` / `#E7E7E7` / `#808080` |
| Dark: 선택 hover 배경 / 테두리 | `#444444` / `#A0A0A0` |
| Light: 선택 배경 / 글자 / 테두리 | `#E5E5E5` / `#303030` / `#808080` |
| Light: 선택 hover 배경 / 테두리 | `#D8D8D8` / `#707070` |

위 값은 최종 HTML에서 확인한 구현 출발점이다. 반복되는 raw color 대신 역할별 토큰으로 옮긴다. Light 값은 참조에 존재하는 폴백이며, 별도의 전면 라이트 테마 검증을 마쳤다는 뜻은 아니다.

필터는 한 개만 켜져도 같은 복수 선택용 스타일이다. 선택 개수에 따라 아이보리와 회색 사이를 오가지 않는다. 선택 여부, hover, disabled, focus가 구분되어야 하며 적절한 상태 semantics를 유지한다.

아이콘은 선 기반을 우선하고 크기·stroke·정렬을 일관되게 다듬는다. 기존 아이콘/공통 UI로 가능한 범위부터 적용하며, 특정 외부 아이콘 세트를 통째로 새로 도입하라는 승인이 아니다.

## 5. 컬렉션 — 매체별 물성

- 영화/영상: 일반 목록은 평면 포스터. 게임 케이스나 만화책 효과를 강제하지 않는다.
- 만화: 얇은 책의 물성, 권 순서, 표지 감상을 유지한다. 물성에 대한 승인을 두꺼운 나무 선반·방 꾸미기 또는 새로운 판본 모델 승인으로 확대하지 않는다.
- 게임: **접합부 쪽이 보이는 닫힌 SteelBook-inspired 케이스**. 아래 규칙이 일반 목록 크기에서도 읽혀야 한다.
- 기존 타입별 탐색과 별도 Showcase의 수동 선별/순서는 유지한다. 모든 타입을 섞은 새 기본 화면을 만들지 않는다.

### 닫힌 게임 케이스

그림에 그림자만 붙인 판이 아니라, 앞뒤 쉘이 닫혀 맞물린 소장품이어야 한다. 앞표지의 인식성과 케이스의 구조가 동시에 남아야 한다.

1. 앞면: 아트가 넓게 차는 면과 얇게 말린 가장자리, 둥근 모서리의 굴곡.
2. 열리는 쪽/상하단: 앞뒤 쉘과 그 사이의 어두운 접합선. 열린 틈이나 두꺼운 책의 페이지 단면처럼 보이지 않게 한다.
3. 책등/뒷면: 데이터가 없으면 무지/중립 구조. 기본은 책등보다 접합부 쪽을 노출하고, 제목·로고·뒷표지 아트를 지어내지 않는다.
4. 깊이: 얇은 접지 그림자와 절제된 가장자리 명암. 과한 반사, 플랫폼 띠, 콘솔 로고, 장식 프레임으로 물성을 설명하지 않는다.

실물 제품의 실측 복제도, 해당 게임이 실제로 보유한 스틸북 에디션도 아니다. 이 UI를 근거로 소장/에디션 메타데이터를 생성하지 않는다.

### 상단 경계/계단 현상 보정

5차 CSS 입체 면의 상단 경계가 작은 목록에서 지그재그하게 보였다. 6차는 면과 표지의 좌표를 공유하는 **일체형 투영 + 표시 DPR 기반 고해상도 샘플링**으로 수정했고 사용자가 개선을 확인했다. 물성을 평면으로 없애거나 표지 전체를 blur 처리하는 해결은 채택하지 않는다.

- 참조 렌더러: `closedCaseDraw` 및 `paintCaseCanvas`. Canvas 2D에서 같은 투영 좌표로 쉘/접합부/전면을 그리고, 중복된 상단 1px 경계 대신 일관된 lip을 그린다.
- 참조 표지 좌표: 154×231, 깊이 15, 모서리 6; canvas 논리 영역 224×300. 접합부 시점은 X=-8°, Y=-26°, 투영 거리 1100이다.
- 샘플링 참조: `ratio = min(8, max(1, DPR * 2 * displayScale))`, `displayScale = nominalCoverWidth / 154`. backing store는 논리 크기×ratio를 올림하고 high-quality image smoothing을 사용한다.
- 이 수치와 알고리즘은 시각 재현을 위한 출발점이지 전역 상수/강제 아키텍처가 아니다. 동일한 닫힌 형상과 경계 품질을 더 적절한 기존 구조로 유지할 수 있다면 가능하다. 단순 CSS 분리 면으로 회귀하며 결함을 재도입하지 않는다.

- renderer는 목록에서 상시 회전/재그리기하지 않는다. 표시 중인 카드, 썸네일 해상도, 재사용/해제, 비동기 결과의 취소·stale 방지, DPR/크기 변경 시 갱신을 함께 설계한다.
- Canvas가 상호작용과 접근성 트리를 대체하지 않게 한다. 선택/키보드/컨텍스트 메뉴/드래그/제목은 기존 DOM과 공통 UI 계약에 남긴다.
- 원본 파일이나 대량 고해상도 캔버스를 모든 항목에 계속 유지하지 않는다. cross-origin 이미지와 기존 로컬 WorkArtwork 캐시 경로를 먼저 확인하며, 새 원격 다운로드/자산 변환 파이프라인을 만들지 않는다.
- 104 / 154 / 196 CSS px, 특히 DPR 1.125와 1.25에서 정면·접합부의 상단/모서리를 목록 크기로 점검한다. 확대해서만 멋져 보이면 충분하지 않다.
- 2:3와 채우기 크롭은 비교 조건이었다. 모든 게임/만화 표지의 비율 고정 또는 강제 잘림은 별도 승인되지 않았다. 기존 비율/fit 선택과 원본 감상 경로를 보존한다.

## 6. 상세 — 원본 배경, 겹치는 표지, 넓은 하단 페이드

배경이 있는 게임/영화 상세는 별도 hero/backdrop을 뒤에 넓게 놓고 앞표지를 그 위에 겹친다. 하단의 넓은 gradient가 본문 배경으로 자연스럽게 이어지되, 배경과 표지 둘 다 존재감을 유지한다.

- 표지와 hero는 독립적인 artwork 역할이다. 한 장으로 양쪽을 강제 생성하거나, provider 갱신으로 사용자의 역할 선택을 덮어쓰지 않는다.
- **원본 배경 + 겹침 + 넓은 페이드**를 유지한다. 비교판의 밝기 증가·확대·하단 이동은 스트레스 조건이었으며 채택할 효과가 아니다.
- 페이드는 배경 계층에만 걸린다. 앞표지까지 흐려지거나 gradient가 표지와 텍스트 위를 덮으면 안 된다.
- 배경 전체를 과하게 어둡게/흐리게 만들어 해결하지 않는다. 읽을 정보가 놓이는 하단을 중심으로 조절하고 focal position은 실제 artwork/기존 사용자 선택을 따른다.
- 긴 제목과 정보는 줄바꿈되고 본문으로 이어져야 한다. 배경을 감상할 여백과 실제 정보 밀도를 함께 유지한다.
- 만화의 권별 표지/선반 중심 상세를 이 hero 공식으로 자동 교체하지 않는다.

### 배경이 없는 경우

빈 hero 자리를 강요하지 않고 상단 공간을 접어 표지와 제목·정보를 나란히 모은다. 최종 비교의 132px 표지/상단 압축은 허전함을 줄이는 방향으로 수용되었다.

- 132×198 표지, 25px gap, 상단 17px, 본문까지 20px는 비교판 참고 수치다. 작은 화면/긴 제목에서는 기존 반응형 구조에 맞춰 조정한다.
- 표지를 확대/blur한 가짜 배경, 장식 패널, 새로운 provider fetch를 fallback으로 추가하지 않는다.
- 표지마저 없으면 가짜 큰 이미지 자리보다 제목/정보 중심의 정직한 빈 상태로 접는다.
- 배경 있는 화면에는 이 compact 보정을 적용하지 않는다. 배경 실패/없음과 사용자가 고른 원본 배경을 구분한다.

8. 테스트는 변경 위험에 맞춘 가장 관련 있는 범위부터 실행한다. 순수 스타일 변경에 의례적인 전체 테스트/production build를 요구하지 않고, 배치·정렬·상호작용·renderer 동작 변경은 관련 회귀를 확인한다.
9. 실제 앱 통합 후 같은 자료/같은 크기로 비교한다. native 확인이 필요할 때는 `AGENTS.md`의 Tauri 실행 규칙과 격리된 fixture를 따른다. 사용자 운영 라이브러리에 테스트 데이터를 쓰지 않는다.
10. 결과는 구현한 범위, 유지한 범위, 실행한 검증과 미검증 환경을 구분해 보고한다. 새 시각 제안이나 광범위 리팩터링을 완료 조건에 덧붙이지 않는다.

- 자산: 날짜와 HH:mm의 시간대 일치, 작가 미상/긴 이름, 페이지 경계/리사이즈의 날짜 그룹 연속성, 현재 선택/스크롤/영상 동작 보존.
